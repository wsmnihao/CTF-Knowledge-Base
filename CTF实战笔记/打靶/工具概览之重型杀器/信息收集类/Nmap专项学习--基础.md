## 初识Nmap
### 主机在线存活侦察

**使用sudo和不使用sudo的区别

==sudo是暂时使用超级管理员（root）的一个账户权限，来执行一次当前命令。==
	
	有一点需要注意一下，suod不是用管理员账户使用的，而是暂时调用root的权限来执行一次命令。建议执行命令的时候，使用sudo即可。不建议一直使用root，这种账户的权限超乎想象，可以对系统的安全以及稳定性重大影响。
	建议平时用普通用户执行命令，遇到权限报错再考虑加 `sudo`。不建议一直用 root 账户，因为 root 权限极大，一旦操作失误或被恶意利用，后果很严重。
	
```bash
sudo nmap -sn 目标地址/c段子网掩码

# 例如
sudo nmap -sn 192.168.128.0/24  # 也可以用192.168.128.1/24，但是建议还是前者比较好
```

**注解**：
	'-sn' 指no port scan 不进行端口扫描，只输出响应了请求的存活主机，也被称为ping扫描！！
		-sn它相比对广播地址基兴县ping请求更可靠，许多主机不会响应广播请求
		**默认情况下，`-sn` 在扫描远程网络时会发送四项探测：**
		1、ICMP回显请求
		2、对端口443的TCP SYN请求
		3、对端口80的TCP ACK请求
		4、默认情况下的ICMP时间戳请求
		**但如果目标在同一子网，Nmap 会优先使用 ARP 请求来发现主机。** ARP 工作在数据链路层，不涉及端口或 TCP/ICMP，比那四项更可靠。

	-sL 目的域-sn一样，但是-sn要比这个列表扫描多一步，允许对目标网络进行轻量级的侦擦，比列表扫描要更有价值

**非特权用户执行 `-sn`**：

- 如果目标在**同一子网**，Nmap 会尝试用 ARP 但可能受限，导致探测不完整
    
- 如果目标在**远程网络**，Nmap 只能用 TCP connect 到 80 和 443 端口来判断主机是否存活，这种方式比特权用户的原始包探测更容易被防火墙拦截

**特权用户（sudo）执行 `-sn`**：

- 如果目标在**同一子网**，Nmap 发 ARP 请求，最可靠
- 如果目标在**远程网络**，Nmap 发送那四项探测（ICMP echo、TCP SYN 到 443、TCP ACK 到 80、ICMP 时间戳请求），穿透防火墙的能力更强
- `arp-scan` 是一个专门用来**发送 ARP 请求**来发现本地网络中存活主机的工具。它工作在**数据链路层（第2层）**，比 Nmap 的 `-sn` 更直接、更快速，而且**不受防火墙规则影响**（因为防火墙通常只过滤 IP 层以上的流量）

### 端口扫描

**摘要
端口信息参数摘要

| 参数  | 说明                             |
| --- | ------------------------------ |
| -sT | 与TCP连接扫描——完整的三次握手              |
| -sS | 与TCP连接扫描——只发送SYN包，一次握手，隐蔽性要高一点 |
| -sU | 进行UDP扫描                        |
| -F  | 快速模式——扫描常见的100个常见的端口           |
| -p  | 指定端口扫描，例如 -p 80,443,3306       |
| -p- | 进行全端口扫描                        |
