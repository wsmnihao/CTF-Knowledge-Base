# 第一部分 · 磁盘与挂载

## lsblk — 看块设备结构

```bash
lsblk [选项]...
```

| 选项 | 作用 |
|---|---|
| `-f` | **显示文件系统类型和 UUID**（最常用） |
| `-a` | 含空设备 |
| `-p` | 显示完整设备路径 |
| `-t` | 只显示某类型（`-t part` 分区、`-t disk` 磁盘） |
| `-i` | 显示拓扑（父子关系） |
| `-s` | 反向依赖树 |
| `-n` | 只输出设备名 |
| `-b` / `-o` | 字节 / 自定义列 |
| `-J` | JSON 输出 |

```bash
$ lsblk                     # 树状：磁盘 → 分区 → 挂载点
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0   20G  0 disk
├─sda1   8:1    0    1G  0 part /boot/efi
└─sda2   8:2    0   19G  0 part /
sdb      8:16   0  100G  0 disk

$ lsblk -f                  # ⭐ 显示 FS 类型和 UUID
$ lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT
$ lsblk -no uuid /dev/sda2   # 只要 UUID（写 fstab 常用）
$ lsblk -J                   # JSON，脚本用
```

⚠️ **设备名（`sda`/`nvme0n1`）是不稳定的**。加盘、插拔、改 BIOS 顺序都可能变。**`/etc/fstab` 里必须用 `UUID=` 而不是 `/dev/sda2`。**

⚠️ **`lsblk` 只看得到块设备**。看不到 NFS、CIFS 等网络文件系统的全貌，完整的看 `/proc/mounts` 或 `findmnt`。

⚠️ **NVMe 和 SATA 命名规则不同**：NVMe 是 `nvme0n1` + `nvme0n1p1`（分区用 `p`），SATA 是 `sda` + `sda1`。**脚本里写死分区后缀会踩。**

## findmnt — 看挂载（比 mount 好）

```bash
findmnt [选项] [目标]
```

| 选项 | 作用 |
|---|---|
| （无） | 树状显示**所有**挂载 |
| `-T 路径` | **查某路径在哪个挂载点上**（最实用） |
| `-t 类型` | 按类型过滤（`-t ext4` `-t nfs`） |
| `-D` / `--fstab` | **显示 `/etc/fstab` 里的条目**（含未挂载的） |
| `-n` | 去掉表头 |
| `-o` | 自定义列 |
| `-J` | JSON |

```bash
$ findmnt                     # 树状，最全
$ sudo findmnt /               # 根分区
$ findmnt -T /var/log          # ⭐ /var/log 在哪个挂载点上
$ findmnt -T /home/liu/project # 判断在不在独立分区上
$ findmnt -t ext4
$ findmnt --fstab              # fstab 里配了什么（和 mount 看到的不一样）
```

⚠️ **`findmnt -T 路径` 是判断「这个目录是不是单独分区」的正解**。要判断日志/数据库是否会撑满根分区，全靠它。

⚠️ **`mount` 和 `findmnt` 看到的内容不同**：`mount` 只列**已挂载**的，`findmnt -D` 列**fstab 里配置的**（可能还没挂、可能失败了）。排查开机挂载失败用 `-D`。

## mount / umount — 挂载与卸载

```bash
mount [选项]... 设备 挂载点
umount [选项]... 设备或挂载点
```

| mount 选项 | 作用 |
|---|---|
| `-t 类型` | 文件系统类型（`ext4` `xfs` `btrfs` `vfat` `nfs4` `tmpfs`） |
| `-o 选项` | 挂载选项（逗号分隔） |
| `-a` | 按 fstab 挂载所有 |
| `-n` | 试挂不真挂（检查配置） |
| `-r` | 只读挂载 |
| `--bind` | 绑定挂载 |
| `-U UUID` | **用 UUID 挂**（推荐） |
| `-L 标签` | 用标签挂 |

| umount 选项 | 作用 |
|---|---|
| `-l` / `--lazy` | **懒卸载**：等不用了再真正卸载 |
| `-f` | 强制 |
| `-R` | 递归（含子挂载） |

**常用挂载选项**

| 选项 | 作用 |
|---|---|
| `ro` / `rw` | 只读 / 读写 |
| `noatime` | **不更新访问时间**（省 IO） |
| `nodiratime` | 不更新目录访问时间 |
| `relatime` | 访问时间按天更新（**默认**） |
| `noexec` | 禁止执行文件 |
| `nosuid` | 忽略 setuid/setgid |
| `nodev` | 忽略设备文件 |
| `defaults` | 默认选项 |
| `errors=remount-ro` | 出错就重挂只读 |

```bash
# 挂载（用 UUID）
$ sudo mount -U "$(lsblk -no uuid /dev/sda2)" /mnt/data

# 指定类型和选项
$ sudo mount -t ext4 -o rw,noatime /dev/sdb1 /mnt/data
$ sudo mount -t tmpfs -o size=1G tmpfs /dev/shm

# 只读挂载（查文件系统问题时的安全做法）
$ sudo mount -o ro,loop image.iso /mnt/iso

# 按 fstab 全部挂载 / 检查
$ sudo mount -a
$ sudo mount -a -n                    # 只测试不真挂

# 卸载
$ sudo umount /mnt/data
$ sudo umount /dev/sdb1
$ sudo umount -l /mnt/nfs             # 懒卸载（NFS 服务端已挂掉时用）
$ sudo umount -R /mnt/data            # 连子挂载一起
```

⚠️ **`umount` 报 `target is busy`** 说明有进程在里面（当前目录、打开的文件、进程的工作目录）。三种解法：退出所有 cd 进该目录的 shell、用 `fuser`/`lsof` 找出占用者后关掉、或**用 `umount -l` 懒卸载**。

⚠️ **`umount -l` 只是从挂载表摘掉，文件还在后台写**。进程继续跑没问题，但**别马上重新挂到同一位置**，否则同一份数据会有两个挂载点，非常危险。

⚠️ **数据已经在写的时候卸载 = 数据损坏**。**先停服务，再卸载。**

⚠️ **NFS 挂不上时不要用 `-f` 硬卸**，用 `-l`。`-f` 可能在服务端留下不一致的锁。

⚠️ **命令行 `mount` 的配置重启就丢**。要持久化写进 `/etc/fstab`。

## /etc/fstab — 开机自动挂载

**六个字段，顺序固定**：

```
设备/UUID    挂载点    类型    选项    dump  fsck
```

| # | 字段 | 说明 | 常见值 |
|---|---|---|---|
| 1 | 设备 | **用 `UUID=`**，不要用 `/dev/sda` | `UUID=xxxx` |
| 2 | 挂载点 | 目录路径 | `/`, `/home` |
| 3 | 类型 | 文件系统 | `ext4` `swap` `nfs4` |
| 4 | 选项 | 逗号分隔 | `defaults,noatime` |
| 5 | dump | 备份标志，**现代系统填 0** | `0` |
| 6 | fsck | 开机检查顺序，根分区填 1，其余 2 或 0 | `0` |

```bash
# 取 UUID
$ lsblk -no uuid /dev/sda2

# 追加一条
UUID=1234-5678   /data      ext4   defaults,noatime   0   2

# swap 用 swapoff/swapon
/swapfile       none        swap   sw                0   0
```

⚠️ **第六字段填 1 和 2 不只是「检查顺序」**。根分区用 `1` 会被优先检查，其余 `2`，网络文件系统（nfs/cifs）**必须填 0**（不检查）。

⚠️ **网络文件系统写在 fstab 里且开机时网络还没通，会让开机卡住甚至进 emergency shell**。用 `_netdev` 选项或 `nofail`：

```bash
UUID=abcd   /mnt/nfs   nfs4   defaults,_netdev,nofail   0   0
```

⚠️ **`noatime` 减少写盘**，但会让依赖访问时间的软件行为异常（少数监控/反取证工具）。一般机器上建议开。

⚠️ **改完 fstab 一定要先测试**：

```bash
$ sudo mount -a -n        # 只检查语法和设备可达性，不真挂
```

⚠️ **`mount -a` 会真的挂所有**，fstab 写错可能导致**系统开不了机**。改之前保持一个已登录的 root 会话。

⚠️ **设备名不用 UUID 会因为盘序变化而挂错**，把数据挂到错误的位置——**这是最危险的一类 fstab 事故**。

## fdisk / parted — 分区（⚠️ 高危）

```bash
fdisk [选项] 设备
parted [选项]...
```

| fdisk 操作 | 说明 |
|---|---|
| `n` | 新建分区 |
| `d` | **删除分区** |
| `p` | 打印分区表 |
| `t` | 改分区类型 |
| `l` | 列出已知分区类型 |
| `w` | **写入并退出** |
| `q` | 不写退出 |

```bash
$ sudo fdisk -l                    # 列出所有磁盘分区表
$ sudo fdisk -l /dev/sda           # 只看某盘
$ sudo fdisk /dev/sdb              # ⚠️ 交互式分区，w 会立刻写盘
$ sudo fdisk -s /dev/sda           # 只看块数大小，不进交互

$ sudo parted /dev/sda print
$ sudo parted mklabel gpt /dev/sdb
$ sudo parted mkpart primary ext4 0% 100%
```

⚠️ **`fdisk` 默认用 MBR 分区表**。UEFI 系统上应该用 GPT，`parted` 支持 GPT。**新机器一律 GPT。**

⚠️ **`fdisk` 里的 `w` 会立刻写盘**。不确定就用 `q` 退出不写。

⚠️ **分区操作会清空分区上的数据**。执行前 `lsblk` 确认设备名 —— **`fdisk /dev/sda` 打错成 `/dev/sdb` 就是灾难性的**。

⚠️ **删了分区本身不删数据**，但重新建分区后原有数据通常找不回来。

⚠️ **超过 2TB 的磁盘必须用 GPT**，MBR 只能到 2TB 且最多 4 个主分区。

⚠️ **分区后要 `partprobe` 或重启**才能让内核重新读分区表（`parted` 会自动做）。

## dd — 按块复制/清零（⚠️⚠️ 极高危）

```bash
dd [选项] if=输入 of=输出 [bs=块大小] [count=块数] [status=进度]
```

| 选项 | 作用 |
|---|---|
| `if=` | 输入文件（**input file**） |
| `of=` | 输出文件（**output file**） |
| `bs=` | **块大小**（block size） |
| `count=` | 复制多少块 |
| `status=` | 进度显示，`progress` 或 `none` |
| `conv=` | 转换：`sync` `notrunc` `fsync` `sparse` |
| `iflag=` / `oflag=` | `direct`（不经过页缓存） `dsync` |

```bash
# 从 U 盘启动（最常见的正当用途）
$ sudo dd if=ubuntu.iso of=/dev/sdX bs=4M status=progress conv=fsync

# 创建 1G 空文件
$ dd if=/dev/zero of=disk.img bs=1M count=1024 status=progress

# 磁盘清零（销毁数据）
$ sudo dd if=/dev/zero of=/dev/sdX bs=4M status=progress
$ sudo dd if=/dev/urandom of=/dev/sdX bs=4M status=progress conv=fsync

# 测试读性能（绕过缓存）
$ dd if=/dev/sda of=/dev/null bs=1M count=1000 iflag=direct
```

⚠️ **`of=/dev/sdX` 打错一个字符就是整盘报废**。`sdX` 和 `sdb` 长得像，**粘贴前逐字核对**。养成习惯：先 `lsblk` 确认，再执行。

⚠️ **`if=` 和 `of=` 写反了就是把源盘擦掉**。粘贴别人的 dd 命令前先想清楚哪个是源哪个是目标。

⚠️ **写完不加 `conv=fsync` 可能数据还没落盘**就拔盘。

⚠️ **`bs=4M` 比默认 512 字节快几十倍**。默认值是为了兼容老设备，现代磁盘上纯属浪费。

⚠️ **`shred` 在 SSD 上不可靠，`dd if=/dev/urandom` 也不可靠**（SSD 磨损均衡会绕开覆盖）。真正安全的销毁是**全盘加密 + 销毁密钥**。

## swapon / swapoff — 交换分区

```bash
swapon [选项]... [设备]
swapoff [选项]... [设备]
```

| 选项 | 作用 |
|---|---|
| `-s` | 显示摘要 |
| `-a` | 按 fstab 全部启用/关闭 |
| `-p` | 优先级（`-1` 禁用） |

```bash
$ swapon --show
$ sudo swapon /swapfile
$ sudo swapoff /swapfile
$ free -h                    # 看 Swap 行
```

⚠️ **创建 swapfile 建议用 `dd` 而不是 `fallocate`**（`fallocate` 建的文件在部分文件系统上有洞，导致 `swapon` 报 `Invalid argument`）：

```bash
$ sudo dd if=/dev/zero of=/swapfile bs=1M count=2048 status=progress
$ sudo chmod 600 /swapfile              # 权限必须 600
$ sudo mkswap /swapfile
$ sudo swapon /swapfile
$ echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

⚠️ **Btrfs 上的 swapfile 必须 COW（不能用 `chattr +C`）**，且**必须用 NOCOW**；ext4/XFS 上没这个限制。

⚠️ **swap 不是内存的替代品**。用了 swap 就是性能已经在掉。`vmstat` 的 `si`/`so` 非零说明已经在换页，该加内存了。

⚠️ **`swapoff` 需要先把页面换回内存**，内存不够时会失败。

## pvs / vgs / lvs — LVM 逻辑卷

LVM 三层：**物理卷 PV** → **卷组 VG** → **逻辑卷 LV**。

```bash
pvs [选项]... [卷组...]
vgs [选项]... [卷组...]
lvs [选项]... [逻辑卷...]
```

| 通用选项 | 作用 |
|---|---|
| `-a --all` | 显示所有（含内部对象） |
| `-o` | 自定义列 |
| `-S --select` | 条件筛选 |
| `-f` | 过滤格式 |
| `--units` | 单位（`-o +devices` 配合看盘） |

| 命令 | 看什么 | 常用 `-o` |
|---|---|---|
| `pvs` | 物理卷 | `pv_name,vg_name,pv_size,pv_free,uuid` |
| `vgs` | 卷组 | `vg_name,vg_size,vg_free,pv_count,lv_count` |
| `lvs` | 逻辑卷 | `lv_name,vg_name,lv_size,lv_path,devices` |

```bash
$ sudo pvs
$ sudo vgs
$ sudo lvs
$ sudo lvs -o +devices          # ⭐ 逻辑卷在哪些物理盘上

# 扩容的完整流程（经典三步）
$ sudo pvs                        # 确认有新盘
$ sudo vgextend vg0 /dev/sdb1     # 把新盘加进卷组
$ sudo lvextend -l +100%FREE /dev/vg0/lv0
$ sudo resize2fs /dev/vg0/lv0     # 扩展文件系统（⚠️ 不能忘）

# 缩容（顺序相反：先缩文件系统）
$ sudo e2fsck -f /dev/vg0/lv0
$ sudo resize2fs /dev/vg0/lv0 40G
$ sudo lvreduce -L 40G /dev/vg0/lv0
```

⚠️ **LVM 的「五层链」是 `pvcreate → vgcreate → lvcreate → mkfs → mount`**，缺一步就报错。**新建的时候按这个顺序。**

⚠️ **`lvextend` 不会自动扩展文件系统**。XFS 之后**不能缩小**（ext4 可以），所以 XFS 卷只能扩不能缩。**容量规划要考虑这一点。**

⚠️ **`resize2fs` 和 XFS 的 `xfs_growfs` 是两个不同命令**，别搞混。

⚠️ **数据在 VG 里的话，重启可能「找不到」**。逻辑卷没写进 `/etc/fstab` / `/etc/lvm/backup` 的话，某些情况下会「消失」（`dmesg` 里能看到找不到 VG 的信息）。**创建完立刻写 fstab。**

⚠️ **`lvextend -l +100%FREE` 会吃掉卷组所有剩余空间**，没有余量给后续快照。**批量操作前确认 `vgs` 的 `vg_free`。**

⚠️ **LVM 的快照（snapshot）是写时复制**，快照点占的不是快照那一刻的大小，而是「变化量」。**快照不是备份**，误删主卷快照救不回来。

⚠️ **`pvcreate` 会清空目标设备上的分区表**。执行前 `lsblk` 确认目标盘没数据。

# 第二部分 · 网络

## ip — 网络配置（ifconfig/netstat 的替代）

```bash
ip [选项] 对象 命令
```

| 子命令 | 作用 |
|---|---|
| `ip addr` / `ip a` | **看 IP 地址** |
| `ip link` | 看网卡和状态 |
| `ip route` | **看路由表** |
| `ip -br addr` | **brief，一行一个（最好用）** |
| `ip link set 网卡 up/down` | 启停网卡 |
| `ip addr add 192.168.1.10/24 dev eth0` | 加 IP |
| `ip addr del ...` | 删 IP |
| `ip route add default via 192.168.1.1` | 加默认路由 |

| 选项 | 作用 |
|---|---|
| `-4` / `-6` | IPv4 / IPv6 |
| `-br` | brief 单行格式 |
| `-c` | 彩色 |
| `-s` | 统计 |

```bash
$ ip -br addr                      # ⭐ 最常用
lo      UNKNOWN  127.0.0.1/8 ::1/128
eth0    UP       192.168.1.100/24 fe80::.../64

$ ip addr show eth0
$ ip link
$ ip route                         # ⭐ 排查网络问题的第一步
default via 192.168.1.1 dev eth0 proto dhcp metric 100
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.100

$ ip -4 addr show scope global       # 只看全局 IPv4

# 临时改（重启失效）
$ sudo ip link set eth0 down
$ sudo ip link set eth0 up
$ sudo ip addr add 10.0.0.5/24 dev eth0
$ sudo ip route add 10.1.0.0/16 via 10.0.0.1
```

⚠️ **`ip addr add` 和 `ip route add` 的配置重启就丢**。持久化要么写 `/etc/netplan/*.yaml` 后 `sudo netplan apply`，要么写 NetworkManager 配置。

⚠️ **netplan 和 NetworkManager 不该同时管同一个接口**，两者会互相覆盖。新装机器上先用 `ls /etc/netplan/` 和 `systemctl status NetworkManager` 看清是谁在管。

⚠️ **改网络前保持一个本地终端或串口会话**。网络配错了远程就断了，只能从控制台救。

⚠️ **`ip route` 里 `proto dhcp` 表示路由是 DHCP 下发的**，手动改可能被 DHCP 服务端覆盖回去。

⚠️ **`ifconfig` 和 `netstat` 在 Ubuntu 里需要装 `net-tools`**，最小安装里没有。**新脚本一律用 `ip` 和 `ss`。**

## ping / traceroute / mtr — 连通性

```bash
ping [选项]... 目标
traceroute [选项]... 目标
mtr [选项]... 目标
```

| ping 选项 | 作用 |
|---|---|
| `-c N` | **发 N 个包就停**（不加会一直 ping，脚本里必加） |
| `-W 秒` | 单包超时等待时间 |
| `-w 秒` | 总超时 |
| `-s 字节` | 包大小（测 MTU 用） |
| `-i 秒` | 发送间隔（小于 0.2 需要 root） |
| `-n` | 不反查主机名（**脚本里加，快**） |
| `-4` / `-6` | 指定协议版本 |
| `-f` | flood（root） |

| traceroute 选项 | 作用 |
|---|---|
| `-n` | 不反查 |
| `-I` | 用 ICMP（否则用 UDP） |
| `-T` / `-p 端口` | 用 TCP 指定端口（穿透防火墙） |
| `-m` | 最大跳数 |
| `-q N` | 每跳发 N 个包（减少输出） |

| mtr 选项 | 作用 |
|---|---|
| `-c N` | 发 N 个包就退出 |
| `-r` | 显示每秒报告（类 ping） |
| `-n` | 不反查 |

```bash
$ ping -c 4 -n 1.1.1.1
$ sudo ping -c 3 -s 1472 -M do example.com    # 测 MTU（设 DF 位）
$ ping -c 2 example.com | grep -o 'time=[^ ]*'

$ traceroute -n example.com
$ sudo traceroute -T -p 443 example.com        # 走 TCP，穿透防火墙
$ mtr -c 10 example.com                        # ⭐ ping + traceroute 合一
```

⚠️ **`ping` 不加 `-c` 会永远跑**，脚本和终端里都要记得停。

⚠️ **ping 通不代表服务可用**（可能通 ICMP 但端口不通），**ping 不通也不代表服务不可用**（可能禁了 ICMP）。**判断服务必须测端口**。

⚠️ **DNS 解析失败时 ping 不了域名**，先 `getent hosts example.com` 单独验证 DNS。用 `ping -n` 跳过 DNS 正好能区分「DNS 问题」和「网络问题」。

⚠️ **`ping` 需要 `CAP_NET_RAW`**。容器里常被禁用，看到 `Operation not permitted` 不是网络问题。

⚠️ **`traceroute` 默认用 UDP，高端口常被中间设备丢弃**，显示 `*` 不一定是真断。用 `mtr` 或 TCP 模式（`-T -p 443`）更准。

## curl — 一切 HTTP

```bash
curl [选项]... URL
```

| 选项 | 作用 |
|---|---|
| **`-I`** | **只取响应头**（`HEAD` 请求） |
| **`-f` / `--fail`** | **HTTP 4xx/5xx 时返回非 0（脚本必用）** |
| `-o 文件` | 输出到指定文件 |
| `-O` | 输出到 URL 里的同名文件 |
| `-L` | **跟随重定向** |
| `-k` | **跳过证书验证**（⚠️ 只在明确知道风险时用） |
| `-s` / `-S` | 静默 / 但显示错误 |
| `-v` / `-vv` | 显示过程 / 更详细（含 TLS 握手） |
| `-u 用户:密码` | Basic 认证（⚠️ 密码进历史） |
| `-H "头: 值"` | 加请求头 |
| `-X 方法` | 指定 HTTP 方法 |
| `-d 数据` / `--data` | POST body |
| `-F 字段=值` | multipart 表单上传 |
| **`-w 格式`** | 输出状态码/耗时等 |
| `-m 秒` | 总超时 |
| `-x 代理` | 走代理 |
| `-C -` | **断点续传** |
| `--retry N` | 重试 |
| `-4` / `-6` | 指定协议版本 |

```bash
# 测站点
$ curl -I https://example.com
$ curl -sS -o /dev/null -w '%{http_code}\n' https://example.com
$ curl -sS -o /dev/null -w 'code=%{http_code} time=%{time_total}s size=%{size_download}\n' https://example.com

# 下载
$ curl -O https://example.com/file.tar.gz        # 保留原名
$ curl -o /tmp/f.tar.gz https://example.com/f    # 指定文件名
$ curl -C - -O https://example.com/big.iso       # 断点续传

# 重定向后的最终地址（排查跳转）
$ curl -sS -o /dev/null -w '%{url_effective}\n' -L http://example.com

# POST
$ curl -X POST -H 'Content-Type: application/json' -d '{"a":1}' https://api.example.com
$ curl -F "file=@report.pdf" https://example.com/upload

# 下载并校验（可靠做法）
$ curl -fSL -o f.tar.gz https://example.com/f.tar.gz
$ echo "expected_sha256  f.tar.gz" | sha256sum -c -

# 调试：看完整过程
$ curl -v https://example.com 2>&1 | less
```

⚠️ **`curl` 不加 `-f` 时 HTTP 错误也返回 0**。`404`、`500` 在管道里会被当成功处理。**脚本里加 `-f`**——**这是最常见的监控/部署脚本 bug。**

⚠️ **`-k` 跳过证书验证等于放弃 TLS 的意义**。只在自签名内网调试时用，**生产代码里永远不要出现**。

⚠️ **`-u 用户:密码` 把密码写进命令行**，会进 shell 历史和 `ps`。用 `--netrc-file`、`~/.netrc` 或环境变量。

⚠️ **`-L` 跟随重定向时凭据可能被带到重定向目标**。从不可信的源下载时不要同时用 `-u`。

⚠️ **`-O` 用 URL 里的文件名**，从不可信服务器下载时文件名可能带路径或奇怪字符。要安全就用 `-o` 指定名字。

⚠️ **`-C -` 断点续传要求服务端支持 Range 请求**。不支持时会从头下并可能损坏文件。

⚠️ **`-w` 的占位符很多**：`%{http_code}` `%{time_total}` `%{time_dns}` `%{time_connect}` `%{size_download}` `%{speed_download}` `%{num_redirects}` `%{ssl_verify_result}`。写监控脚本时很有用。

⚠️ **`wget` 更适合「单纯下文件」**（递归、断点、限速内置），`curl` 更适合「构造 HTTP 请求」。

## wget — 下载文件

```bash
wget [选项]... URL
```

| 选项 | 作用 |
|---|---|
| `-c` | **断点续传** |
| `-b` | 后台下载 |
| `-O 文件` | 输出到指定文件 |
| `-P 目录` | 指定目录 |

## nft — nftables 防火墙

```bash
nft [选项]... 命令
```

| 命令 | 作用 |
|---|---|
| `nft list ruleset` | **看所有规则** |
| `nft list tables` | 看表 |
| `nft list chain inet filter input` | 看某链 |
| `-f 文件` | 从文件加载规则 |
| `-c` / `--check` | **只检查语法，不应用** |
| `-a` | 显示句柄（handle） |
| `flush ruleset` | **清空所有规则** |
| `add` / `delete` / `insert` | 增删插规则 |
| `-e` | 用 JSON 风格输出（可读性好） |

```bash
$ sudo nft list ruleset
$ sudo nft -a list ruleset
$ sudo nft list tables
$ sudo nft list chain inet filter input

# 从文件加载（先检查）
$ sudo nft -c -f /etc/nftables.conf
$ sudo nft -f /etc/nftables.conf

# 加规则
$ sudo nft add rule inet filter input tcp dport 22 ct state new,established counter accept
$ sudo nft insert rule inet filter input iif lo accept

# 删规则（按 handle）
$ sudo nft -a list chain inet filter input     # 先看 handle 号
$ sudo nft delete rule inet filter input handle 5

# 看哪些规则在起作用
$ sudo nft list chain inet filter input -a
```

⚠️ **`nft -f` 加载前一定先 `-c` 检查语法**。规则表加载到一半失败，**可能把你自己的 SSH 连接也锁在外面**。

⚠️ **`nft -c` 只检查语法，不检查逻辑合理性**。「语法对但把 SSH 挡了」是常发生的事。

⚠️ **改防火墙时保持一个已登录的 root 会话，并预设兜底**：

```bash
# 兜底：5 分钟后自动清空规则，救你出来
$ ( sleep 300 && sudo nft flush ruleset ) &
$ sudo nft -f /etc/nftables.conf
```

⚠️ **`flush ruleset` 会清空全部规则**（包括别人加的）。批量操作前要小心。

⚠️ **规则里加 `counter`** 才能看出哪些规则真正在拦流量。

⚠️ **持久化要写 `/etc/nftables.conf` 并启用服务**：

```bash
$ sudo systemctl enable nftables
$ sudo systemctl restart nftables
```

⚠️ **Ubuntu 24.04 的 `iptables` 是 nftables 兼容层（`iptables-nft`）**。老教程里的 iptables 命令能跑，但**新配置直接写 nftables**，别维护两套规则。

## sysctl — 内核参数

```bash
sysctl [选项]... 参数名[=值]
```

```bash
$ sysctl -a                        # 所有参数（很长）
$ sysctl net.ipv4.ip_forward
```

⚠️ **`sysctl -a` 的输出格式可以直接当配置文件用**。

## date / timedatectl

```bash
date [选项]
timedatectl [选项] [命令]
```

| date 选项 | 作用 |
|---|---|
| `-d "表达式"` | 按表达式算时间（`"2 days ago"` `"next monday"`） |
| `-r 文件` | 用文件的修改时间 |
| `-u` | 显示/设置 UTC |
| `-R` | RFC 2822 格式 |
| `-I` / `--iso-8601` | ISO 8601 格式 |
| `+%格式` | 自定义输出（`+%F %T`） |
| `-s` | 设置时间（需 root，现代系统应该用 NTP） |

| timedatectl 命令 | 作用 |
|---|---|
| （无） | 显示全部时间设置 |
| `set-time` | 设时间 |
| `set-timezone 时区` | **设时区** |
| `set-ntp` | 开关 NTP |
| `list-timezones` | 列出所有时区 |
| `show` | 所有属性 |

```bash
$ date
$ date -Iseconds
$ date '+%Y-%m-%d %H:%M:%S'
$ date -d "2024-01-15 10:00" -d "+30 days"      # 套两个 -d
$ date -d '19875 days ago' +%Y-%m-%d             # ⭐ 算 shadow 里的天数对应哪天的日期
$ date -r /etc/passwd                            # 文件的修改时间

$ timedatectl
$ sudo timedatectl set-timezone UTC
$ timedatectl list-timezones | grep Shanghai
$ sudo timedatectl set-ntp true
```

⚠️ **系统时钟（`CLOCK_REALTIME`）会被 NTP 调整，硬件时钟（`CLOCK_MONOTONIC`）不会**。日志时间乱跳要先看 NTP 状态。

⚠️ **`date -s` 改时间会让正在跑的程序混乱**（定时器、日志顺序、证书校验）。**现代系统应该用 NTP 同步，不要手动 `date -s`。**

⚠️ **时区必须用 IANA 名**（`Asia/Shanghai`），不是 `CST` 也不是 `+0800`。用错名字 `timedatectl` 会报错。

⚠️ **服务器上统一用 UTC**（`sudo timedatectl set-timezone UTC`）能省掉很多时区转换的麻烦。

## chronyc / chronyd / chrony — 时间同步（NTP 守护进程）

```bash
chronyc [选项] 命令
```

| chronyc 命令 | 作用 |
|---|---|
| `tracking` | **同步状态总览** |
| `sources -v` | **数据源列表和状态** |
| `sourcestats -v` | 数据源统计 |
| `activity` | 当前活动任务 |
| `makestep` | 立即大步校正时钟 |
| `minpoll` / `maxpoll` | 调整轮询间隔 |
| `server` | 临时加一个源（不持久） |

**`sources` 里的状态字母**

| 状态 | 含义 |
|---|---|
| `*` | **当前选中的源** |
| `+` | 可用的候选 |
| `-` | 不可用 |
| `x` | **falseticker，时钟有问题应排除** |
| `~` | 时间戳不准 |
| `?` | 源不可达或数据不足 |

```bash
$ chronyc tracking
Reference ID    : C0A8010B (192.168.1.11)
Stratum         : 3
Ref time (UTC)  : Mon Aug 12 02:33:00 2024
System time     : 0.000000123 seconds fast of NTP time
Leap status     : Normal
Root delay      : 0.0004 seconds
Root dispersion : 0.0009 seconds

$ chronyc sources -v
  MS Name/IP address         Stratum Poll Reach LastRx Last sample
^* 192.168.1.11                  2   6   377   17   +12us   [+12us]
^+ ntp.ubuntu.com               2   6   377   15  -234us  [-234us]
^? pool.ntp.org                 0   6     0     -     +0ns    [+0ns]

$ sudo chronyc makestep        # 立即校正（启动脚本里常用）
```

⚠️ **`Reach` 列是 0 说明这个源完全没收到过包**。持续为 0 表示网络不通或源地址错。**这是判断 chrony 是否正常的关键列。**

⚠️ **chrony 和 `systemd-timesyncd` 会抢时钟，只能留一个**。Ubuntu 默认是 timesyncd，想更精确就装 chrony 并停掉 timesyncd。

⚠️ **`chronyc makestep` 在时钟偏差很大时用**（比如虚拟机从快照恢复后时钟跑偏）。平时让它慢慢收敛（slew）更好，突然跳变可能影响运行中的程序。

⚠️ **容器里没有 `CAP_SYS_TIME` 就设不了时间**，chrony 会报权限错误。容器默认共享宿主机时钟。

## locale / locale-gen — 字符集与语言环境

```bash
locale [选项]
locale -a [选项]
locale-gen [选项] [locale...]
```

| locale 变量 | 作用 |
|---|---|
| `LANG` | **全局语言和字符集**（兜底） |
| `LC_ALL` | **覆盖所有 LC_* 变量**（最高优先级） |
| `LC_CTYPE` | 字符分类、字符集 |
| `LC_COLLATE` | 排序规则 |
| `LC_MESSAGES` | 界面语言 |
| `LC_NUMERIC` | 数字格式 |
| `LC_TIME` / `LC_DATE` | 时间/日期格式 |
| `LC_MONETARY` | 货币格式 |
| `LC_PAPER` / `LC_NAME` / `LC_ADDRESS` | 纸张/姓名/地址格式 |
| `LANGUAGE` | gettext 语言优先级 |

```bash
$ locale                    # 当前所有设置
$ locale -a                 # 系统可用 locale
$ locale -a | grep -i zh

$ LC_ALL=C date            # ⭐ 固定的 C/POSIX 格式，脚本里必用
$ LC_ALL=en_US.UTF-8 date
$ LC_ALL=C sort file        # ⭐ 排序结果可预测
$ LC_COLLATE=C ls           # 目录列表按字节序

# 生成中文 locale
$ sudo locale-gen zh_CN.UTF-8
$ sudo locale-gen --keep-existing zh_CN.UTF-8

# 临时切换
$ LANG=zh_CN.UTF-8 ls

# 持久改系统 locale
$ sudo update-locale LANG=zh_CN.UTF-8
```

⚠️ **`LC_ALL=C` 是脚本里保证结果可预测的标配**。**`sort` 的顺序会随 locale 变**（`LC_ALL=C.UTF-8` 和 `LC_ALL=C` 的排序结果不同），不固定 locale 的话同一份数据在不同机器上排序可能不同。

⚠️ **系统上某个 locale 不存在时，bash 会警告 `setlocale: LC_ALL: cannot change locale` 但继续执行**，默默退回 C。**看到这行警告要处理**，否则你以为设了中文，其实没有。

⚠️ **`LANG=C.UTF-8` 和 `LANG=C` 不一样**：前者是 UTF-8 但排序仍按字节，后者连 UTF-8 都不是。

⚠️ **`LC_ALL` 一设就覆盖全部**，包括你想保留的某些设置。**只改一个的话改具体变量**（如只改 `LC_TIME`），别用 `LC_ALL`。

⚠️ **`export LANG=...` 只对当前会话有效**，要持久化用 `sudo update-locale` 写 `/etc/default/locale`。

## 小结

| 场景 | 命令 |
|---|---|
| 看磁盘分区挂载 | `lsblk -f` |
| 判断某目录在哪个分区 | `findmnt -T /var/log` |
| fstab 配置了什么 | `findmnt -D` |
| 临时挂载 | `sudo mount -t ext4 -o noatime /dev/sdb1 /mnt` |
| 卸载报 busy | `sudo umount -l /mnt` |
| 写启动盘 | `sudo dd if=x.iso of=/dev/sdX bs=4M status=progress conv=fsync` |
| 看 IP | `ip -br addr` |
| 看路由 | `ip route` |
| 看端口监听 | `sudo ss -tlnp` |
| 测端口通不通 | `curl -sS -o /dev/null -w '%{http_code}\n' https://host` |
| 只看响应头 | `curl -I https://example.com` |
| 下载并校验 | `curl -fSL -o f https://...` + `sha256sum -c` |
| 看防火墙规则 | `sudo nft list ruleset` |
| 加载防火墙配置 | `sudo nft -c -f /etc/nftables.conf` 然后 `sudo nft -f ...` |
| 看时间同步状态 | `chronyc tracking` + `chronyc sources -v` |
| 设时区 | `sudo timedatectl set-timezone UTC` |
| 脚本里稳定排序 | `LC_ALL=C sort file` |

**十二条铁律**

1. **fstab 里用 `UUID=` 不用 `/dev/sda`**，盘序会变。
2. **改 fstab 后先 `mount -a -n` 测试**，写错会开不了机。
3. **卸载前先停服务**，数据在写时卸载 = 损坏。
4. **`dd of=/dev/sdX` 逐字核对设备名**，一个字符之差整盘报废。
5. **`ip addr add` / `ip route add` 重启就丢**，持久化走 netplan 或 NetworkManager。
6. **`curl` 脚本里加 `-f`**，否则 HTTP 404/500 也返回 0。
7. **`curl -k` 和 `-u` 别进生产代码**，前者废掉 TLS，后者泄露密码到历史和 `ps`。
8. **改防火墙先 `nft -c` 检查语法**，并保持 root 会话 + 兜底清规则。
9. **ping 通不代表服务可用**，测端口才算。
10. **`ping` 不加 `-c` 不会停**。
11. **脚本里 `sort` 加 `LC_ALL=C`**，否则排序随环境变。
12. **chrony 和 `systemd-timesyncd` 只能留一个**，两个都跑会抢时钟。
