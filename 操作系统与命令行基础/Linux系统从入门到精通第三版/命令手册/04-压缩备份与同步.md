# 04 · 压缩、备份与同步

三条不同路线，别搞混：

| 目标 | 用 |
|---|---|
| 打包 + 压缩，Linux 内部传递 | **`tar` + `gzip`**（首选） |
| 要 Windows 也能解开 | `zip` / `unzip` |
| 增量同步、只传差异、远端可用 | **`rsync`** |
| 校验完整性 | `sha256sum` |
| 不可恢复地销毁 | `shred` |

---

## tar — 归档（打包）

tar = **t**ape **ar**chive。它把多个文件打成一个文件流，可选地压缩。

**最需要背下来的四个选项**

| 选项 | 作用 | 记忆 |
|---|---|---|
| `-c` | create，创建归档 | **c**reate |
| `-x` | extract，解开归档 | e**x**tract |
| `-t` | list，列出内容 | **t**able of contents |
| `-f` | 指定归档文件名 | **f**ile |
| `-v` | verbose，显示处理的文件 | 常用 |

**压缩方式**

| 选项 | 格式 |
|---|---|
| `-z` | gzip，生成 `.tar.gz` / `.tgz`（**最通用**） |
| `-j` | bzip2，`.tar.bz2`，压缩率更好但更慢 |
| `-J` | xz，`.tar.xz`，压缩率最好、最慢 |
| `--zstd` | zstd，`.tar.zst`，**新系统的推荐**，速度快 |

**其他常用**

| 选项 | 作用 |
|---|---|
| `-C 目录` | **切换到该目录再操作**（打包时的关键） |
| `--exclude 模式` | 排除，支持 glob |
| `--strip-components N` | 解开时去掉前 N 层目录 |
| `-p` | 保留权限 |
| `--numeric-owner` | 存档里用数字记属主（跨机器更可靠） |
| `--sort=name` | 按名字排序 → **可复现的归档** |
| `--mtime` | 固定修改时间，配合 `--sort` 做确定性备份 |
| `--transform` | 重写路径 |

### 打包

```bash
# 打包 + gzip（最常用）
$ tar -czvf backup.tar.gz project/

# 只打包不压缩
$ tar -cvf backup.tar project/

# xz（压缩率最高）
$ tar -cJvf backup.tar.xz project/

# 解开（gzip/bzip2/xz 都用同一个命令，它自己认格式）
$ tar -xzvf backup.tar.gz

# 解到指定目录
$ tar -xzvf backup.tar.gz -C /tmp/restore/

# 选格式建议用长选项，不用记忆短选项
$ tar --create --gzip --verbose --file backup.tar.gz project/
```

⚠️ **`-C` 必须在文件名前面，且影响的是它后面的路径**。这是打包路径错乱的头号原因：

```bash
# 想让包里直接是内容而不是目录壳：
$ tar -czf b.tar.gz -C /home/liu project/     # ✅ 包内是 project/...
$ tar -czf b.tar.gz /home/liu/project/        # ❌ 存的是绝对路径，解开会重建整个树
```

⚠️ **绝对路径是 tar 的著名坑**。用 `/home/liu/project/` 打包，解开后可能往当前目录里重建 `home/liu/project`。**永远用 `-C` + 相对路径。**

⚠️ **`-z` 只对「最后一个 -f 文件」生效**。`tar -czvf` 这种连写没问题，但 `tar -c -f a.tar -z -f b.tar` 里第一个 `-f` 不压缩。**每个归档对应一组选项。**

⚠️ **`tar` 不保留 ACL、SELinux 标签、硬链接关系**（除非加 `--acls --xattrs --hardlinks`）。系统级备份不该用 tar，应写 `rsync -aAXH` 或用专门的备份工具。

⚠️ **解压时注意路径穿越**。解压别人给的归档前先 `tar -tf` 看一眼有没有 `../` 或绝对路径，否则可能覆盖系统文件。这是真实的攻击面（路径遍历漏洞）。GNU tar 会在部分情况下警告但**不总是阻止**。

⚠️ **`tar` 不跳过 0 字节变化的文件**。反复 tar 同一个未改动的目录，归档文件本身会变（mtime 记录在归档里）。用 `--sort=name --mtime=...` 才能做可复现归档。

### 常用组合

```bash
# 排除大目录和缓存
$ tar -czf backup.tar.gz \
    --exclude='*.log' \
    --exclude='node_modules' \
    --exclude='.git' \
    project/

# 从 stdin 管道进来（不落地 tar 文件）
$ tar -czf - project/ | ssh user@host 'cat > backup.tar.gz'

# 通过网络直接传（省磁盘）
$ tar -cz -C /var/log . | ssh user@host 'cd /tmp && tar -xzf -'

# 远程备份一条命令
$ rsync -az --delete /home/liu/ user@host:/backup/liu/

# 可复现归档（每次生成的文件完全一致，便于比对哈希）
$ tar --sort=name --mtime='2024-01-01' --owner=0 --group=0 \
        --numeric-owner -czf deterministic.tar.gz project/

# 解开时只取其中一个目录（去掉顶层壳）
$ tar -xzf backup.tar.gz --strip-components=1

# 列出内容不解开
$ tar -tvf backup.tar.gz

# 追加文件到已有归档
$ tar -rvf existing.tar newfile.txt
```

⚠️ **`tar` 不会自动跳过已归档过的文件**（那是 rsync 的活）。重复用 tar 打包大目录很慢。

⚠️ **`-v` 列出几百个文件会刷屏**，可以 `| less` 或去掉。

## gzip / gunzip — 压缩单个文件

```bash
gzip [选项]... [文件]...
gunzip [选项]... [文件]...
zcat 文件.gz
```

| 选项 | 作用 |
|---|---|
| `-d` | 解压（`gunzip` 等价 `gzip -d`） |
| `-k` | **保留原文件**（默认会删掉原文件） |
| `-c` | 输出到 stdout，不动原文件 |
| `-1` … `-9` | 压缩级别，越大越慢越小（默认 6） |
| `-l` | 查看压缩前后大小 |
| `-r` | 递归压缩目录（**不推荐，效率低**） |
| `-t` | 测试压缩文件是否完好 |

```bash
# 压缩（会删掉原文件）
$ gzip big.log

# 压缩但保留原文件
$ gzip -k big.log

# 解压（会删掉 .gz）
$ gunzip big.log.gz

# 保留原压缩文件解压
$ gunzip -k big.log.gz

# 解压到 stdout，不产生文件
$ zcat big.log.gz | head
$ gzip -cd big.log.gz

# 看压缩率
$ gzip -l big.log.gz

# 测试完整性（不解压只校验）
$ gzip -t big.log.gz && echo OK
```

⚠️ **gzip 默认删除原文件**。压日志前先确认你不需要原文件，或用 `-k`。

⚠️ **gzip 不能压缩目录**。要压目录用 `tar -czf`。

⚠️ **不会记文件名后缀**。`gzip foo` 生成 `foo.gz`，解压后仍是 `foo`。所以压缩多个同名的不同文件会互相覆盖。

⚠️ **`gzip` 不做无损归档备份**。它不是备份方案，压缩损坏就全丢。

## bzip2 / xz / zstd — 另外三种压缩算法

**为什么会有四种**：gzip 快但压得小，xz 压得最小但慢，zstd 兼顾两者。

| 算法 | 压缩率 | 速度 | 后缀 | 典型用途 |
|---|---|---|---|---|
| `gzip` | 中 | **快** | `.gz` | 默认选它，通用 |
| `bzip2` | 较高 | 中 | `.bz2` | 略优于 gzip，已不推荐新用 |
| `xz` / `lzma` | **最高** | **慢** | `.xz` | 发行版 ISO、内核源码、长期归档 |
| `zstd` | 高 | **很快** | `.zst` | 现代首选，压缩率和速度都赢 |

```bash
# 用法完全对称
$ bzip2 file                # → file.bz2（原文件消失）
$ bzip2 -k file             # -k 保留原文件
$ bunzip2 file.bz2
$ bzip2 -d file.bz2

$ xz -k file                # → file.xz
$ unxz file.xz              # 或 xz -d
$ xz -T0 file               # ⭐ -T0 用所有核心（解压并行，很快）

$ zstd -k file              # → file.zst
$ unzstd file.zst           # 或 zstd -d
$ zstd -T0 -19 file         # -19 最高压缩，-T0 并行

# tar 里直接用（⭐ 实际最常用的形式）
$ tar -czf a.tar.gz dir/          # gzip
$ tar -cjf a.tar.bz2 dir/         # bzip2
$ tar -cJf a.tar.xz dir/          # xz（-J）
$ tar --zstd -cf a.tar.zst dir/   # zstd

# 只测试不真正压（估算能压到多大）
$ tar -czf /dev/null dir/         # 输出 0 字节，看 time 和管道
$ xz -9 --robot file              # 机器人模式，报压缩前后大小

# 查看压缩包内容
$ xz -l file.xz                  # ⭐ 看压缩率
$ zstd -l file.zst
```

⚠️ **xz 的单线程解压极慢**，一个几 GB 的 `.xz` 能解压半小时。**用 `xz -T0` 开并行**（需要多线程 xz，`sudo apt install xz-utils`），或者干脆**别用 xz 装软件**（很多 `.deb`/`.rpm` 打包时用了 xz，所以删了它很多包都装不了）。

⚠️ **xz 高压缩级别（`-9`）会占用大量内存**。`xz -9` 峰值内存可能到解压时的 700MB，1GB 内存的机器上会 OOM。

⚠️ **zstd 需要单独装**：`sudo apt install zstd`（不是所有最小安装都有）。**它需要 Ubuntu 22.04+ 的 apt 支持**，老系统上只能用 `unzstd` 装依赖。

⚠️ **`tar` 的选项字母记不住就查表**：`z`=gzip `j`=bzip2 `J`=xz，`--zstd` 没有单字母（早期 GNU tar 不认 `-zstd`）。**用 `tar --zstd -cf` 别用 `-zstd`**。

⚠️ **压之前先看内容**。`tar -tf a.tar.gz | head` 和 `unzip -l a.zip`。**解压不可信归档有路径穿越风险**（见 tar 节）。

⚠️ **对已经压缩过的数据（jpg/mp4/已压缩的日志）再压基本白费**，只浪费时间。看不出大小的文件先 `file` 确认。

⚠️ **压缩率差异的量级**：日志/文本压缩 xz 能压到原大小的 3–5%，gzip 大约 10–15%，zstd 介于两者之间但速度快得多。**归档长期保存选 xz，日常传输选 zstd 或 gzip。**

## cpio / pax / 7z — 冷门但有用

```bash
cpio [选项]... < 文件列表
7z [选项]...
```

```bash
# cpio：从 find 的列表打包（管道友好，早期 initramfs 就是这么做的）
$ find . -type f | cpio -o > backup.cpio
$ cpio -id < backup.cpio            # 解开
$ cpio -itv < backup.cpio           # 先列（⭐ 安全习惯）

# pax：tar 的替代，POSIX 标准
$ pax -w -f out.tar dir/
$ find . | pax -w -f out.tar

# 7z：跨平台全能格式（Windows 上解压方便）
$ sudo apt install p7zip-full
$ 7z a archive.7z dir/             # a = add
$ 7z x archive.7z                  # x = extract
$ 7z l archive.7z                  # l = list
$ 7z t archive.7z                  # t = test
$ 7z a -tzip -p a.zip dir/         # 指定格式和密码
$ 7z u archive.7z newfile          # 增量更新归档
```

⚠️ **解不可信归档前一律先 `-itv` / `l` 列一遍**。tar/cpio/zip 都可能有路径穿越（`../../etc/passwd`）和符号链接攻击。

⚠️ **7z 的加密是真加密**（AES-256），比 zip 的 ZipCrypto 强得多。**但密码写在命令行同样进历史**，用 `-p` 不带参数让它交互式问。

⚠️ **7z 在 Linux 上是兼容方案**（p7zip 是 7-Zip 的分支），更新落后。**`.7z` 主要给别人看，Linux 内部协作别用。**

⚠️ **`cpio` 不会自动记目录结构权限的坑比 tar 多**，能用 tar 就用 tar。

## 备份工具 — restic / duplicity / rsnapshot

**压缩归档是「导出」，不是「备份」。** 真备份要满足：异机、自动、可恢复。

| 工具 | 特点 | 适合 |
|---|---|---|
| `rsnapshot` | **基于 rsync 的快照**，硬链接省空间 | 同一台机器的多个时间点 |
| `restic` | **去重 + 加密 + 增量**，支持 S3/SFTP | **现代通用备份首选** |
| `duplicity` | rsync + GnuPG 加密 | 老牌加密增量备份 |
| `borg` | 去重 + 压缩，仓库制 | 有 Borg 仓库的场合 |

```bash
# restic（推荐）
$ sudo apt install restic
$ export RESTIC_REPOSITORY="sftp:backup@host:/srv/backups"
$ export RESTIC_PASSWORD_FILE=/root/.restic-pw      # 密码别放命令行
$ restic init                                     # 建仓库（只需一次）
$ restic backup /etc /home /var/www               # 备份
$ restic snapshots                                # 看有哪些快照
$ restic check                                    # ⭐ 校验完整性
$ restic forget --keep-daily 7 --keep-monthly 12 --prune   # 清理旧快照
$ restic restore latest --target /tmp/restore     # 恢复

# rsnapshot
$ sudo apt install rsnapshot
$ sudo rsnapshot hourly      # 触发一次
$ sudo cat /etc/rsnapshot.conf | less

# duplicity
$ sudo duplicity /etc 'sftp://user@host//backup/etc' --encrypt-secret-key=(GPGKEYID)
$ sudo duplicity restore 'sftp://user@host//backup/etc' /tmp/etc-restore
```

⚠️ **`restic` 的密码一定用 `RESTIC_PASSWORD_FILE`，不要用 `RESTIC_PASSWORD` 环境变量**——环境变量在 `ps` 里可见（除非加 `=` 前缀的私有形式），命令行更糟。

⚠️ **备份不验证等于没备份**。**定期 `restic check`**，并且**真的恢复一次到临时目录看看能不能用**。恢复演练是唯一能证明备份有效的办法。

⚠️ **备份和被备份的东西在同一台机器上 = 没有备份**。rsnapshot 尤其危险：机器坏了，备份一起没了。**必须有一份异机的。**

⚠️ **`restic forget --prune` 会真正删掉旧快照的数据块，不可恢复**。先 `--dry-run` 看。

⚠️ **`duplicity` 的 `--encrypt-secret-key` 是 GPG 的 key ID，不是密码**，弄混会以为加密了其实没有。

⚠️ **备份脚本要 `set -e`**，否则某天 rsync 失败（磁盘满）脚本继续跑并返回 0，你以为备份成功了。**日志要留存并检查。**

## zip / unzip — 跨平台压缩

```bash
zip [选项]... 归档  文件...
unzip [选项]... 归档 [文件...] [-d 目录]
```

| zip 选项 | 作用 |
|---|---|
| `-r` | **递归目录（不加只存空目录）** |
| `-9` | 最大压缩 |
| `-e` | 加密（用 ZipCrypto，**不安全**） |
| `-P 密码` | 密码在命令行，**会留在历史和进程列表里** |
| `-v` | 详细 |
| `-d 名字` | 从归档里删除条目 |
| `-m` | 移动（删原文件） |
| `-x 模式` | 排除 |

| unzip 选项 | 作用 |
|---|---|
| `-l` | 只列出不解开 |
| `-t` | 测试 |
| `-d 目录` | 解到指定目录 |
| `-o` | 覆盖已有 |
| `-n` | 不覆盖已有 |
| `-q` | 安静 |
| `-P 密码` | 同上，不安全 |

```bash
# 压缩目录（-r 必须有）
$ zip -r archive.zip project/

# 指定压缩级别
$ zip -9 -r archive.zip project/

# 排除
$ zip -r archive.zip project/ -x '*.log' 'project/node_modules/*'

# 只列出
$ unzip -l archive.zip

# 解开
$ unzip archive.zip
$ unzip archive.zip -d /tmp/out/
$ unzip -q archive.zip

# 解开部分文件（通配）
$ unzip archive.zip 'project/*.md'

# 测试完整性
$ unzip -t archive.zip

# 加密（不推荐，见下）
$ zip -e -r secret.zip project/
```

⚠️ **`zip -r` 的 `-r` 不能省**。`zip archive.zip project/` 只会存一个叫 `project` 的空目录项，里面的文件全丢。这是 zip 最常见的误用。

⚠️ **不要用 `-P 密码`**，密码会进 shell 历史，也会出现在 `ps` 的进程列表里任何用户都能看到。用 `zip -e` 交互输入，或 `gpg` 加密后再打包。

⚠️ **zip 的加密（ZipCrypto）很弱**，几百年前就能暴力破解。当成混淆，别当加密。

⚠️ **`zip` 不保存 Unix 权限**（用扩展字段能存但跨平台不可靠）。解开后权限全变默认值。**Linux 上传东西给 Windows 用 zip；Linux 之间传一律用 tar。**

⚠️ **中文文件名在 Windows 上解压可能乱码**，因为 zip 头里没有统一的编码标记。Linux 上用 `unzip -O GBK` 之类的选项可以缓解。

⚠️ `zip` 不是系统必需的，可能要 `sudo apt install zip unzip`。

## rsync — 增量同步

rsync 的核心是**只传输差异**，本地和远程都能用。

```bash
rsync [选项]... 源 目标
```

| 选项 | 作用 | 记忆 |
|---|---|---|
| `-a` | **归档模式**，`= -rlptgoD` | **必用** |
| `-v` | 详细 | |
| `-z` | 传输时压缩 | 慢网络有用 |
| `-u` | 只更新较新的（**防旧覆盖新**） | update |
| `-n` | **演练，不真做** | dry-run |
| `--delete` | 删目标里源没有的文件 | ⚠️ |
| `-e ssh` | 指定远程 shell | |
| `-h` | 人类可读进度 | |
| `--exclude` | 排除模式 | |
| `--include` | 包含（放 `--exclude` 前） | |
| `-L` | 跟随符号链接 | |
| `--partial` | 断点续传 | |
| `-b` / `--backup-dir` | 备份被覆盖的 | |
| `--numeric-ids` | 用数字记属主 | |
| `-A` `-X` | 保留 ACL / 扩展属性 | |
| `-H` | 保留硬链接 | |
| `--stats` | 传输统计 | |
| `--max-size` | 超过就跳过 | |
| `--delete-delay` | 传输完再删（更安全） | |

```bash
# 本地 → 本地（-a 保留权限属主时间戳）
$ rsync -av src/ dst/

# 本地 → 远程（-e ssh）
$ rsync -avz src/ user@host:/dst/path/

# 远程 → 本地
$ rsync -avz user@host:/remote/ ./local/

# 排除某些东西
$ rsync -avz \
    --exclude='node_modules/' \
    --exclude='.git/' \
    --exclude='*.log' \
    src/ user@host:/dst/

# 同步系统配置（Linux 之间搬机器的标准做法）
$ rsync -aAXH --numeric-ids /etc/ target:/etc/

# 演练：先看会做什么
$ rsync -avzn --delete src/ dst/

# 断点续传 + 进度条
$ rsync -avP src/ user@host:/dst/

# 删除镜像（目标严格等于源）
$ rsync -av --delete-delay src/ user@host:/dst/
```

⚠️ **`src` 和 `dst` 的尾部斜杠含义完全不同**，这是 rsync 最反直觉的地方：

```bash
$ rsync -av src  dst/       # dst/src/...   （把 src 这个目录复制进去）
$ rsync -av src/ dst/       # dst/...       （把 src 的内容铺进 dst）  ← 通常要的是这个
```

⚠️ **`--delete` 会删目标里源没有的文件，没有后悔药**。第一次用**必须**先加 `-n` 演练：

```bash
$ rsync -avzn --delete src/ dst/     # 确认要删什么
$ rsync -avz --delete-delay src/ dst/   # 确认无误再实跑
```

⚠️ **`--delete` 加上路径写错 = 删错目录**。`dst` 写成 `user@host:/` 会试图让 `/` 和源完全一致。**在根目录上跑 `rsync --delete` 极其危险。**

⚠️ **`-a` 不含 `-H`（硬链接）、`-A`（ACL）、`-X`（扩展属性）**。做系统级同步要 `-aAXH`，否则权限和 ACL 会丢。

⚠️ **`-a` 里的 `-D` 保留设备文件和特殊文件**。远程目标机器的设备号可能不同，用 `--copy-devices` 或 `-D` 要当心。

⚠️ **`rsync` 靠「大小 + 修改时间」判断是否传输**。如果文件被改了但大小和时间戳没变（如用 `cp -p` 覆盖、`rsync` 恢复），会漏掉。极端情况用 `-c`（算校验和）或 `--checksum`。

⚠️ **`rsync` 的 `-z` 只在传输时压缩**，归档本身不是压缩文件。落地后可以再 `gzip`。

⚠️ **远程 rsync 默认不保留属主，除非你是 root**。普通用户同步会显示属主变化。目标机器上用 `--numeric-ids` 保持数字一致。

⚠️ **`rsync` 单向**。它**不会删除源文件**，也不会把目标的改动推回源。想要双向同步需要 `unison` 或 `rsync` 两次（会冲突）。

⚠️ **`rsync` 不是备份工具**。它不保留历史版本，源文件被误删后目标也会同步删掉（尤其开了 `--delete`）。备份要用带快照的工具（见下方）。

## sha256sum — 校验和

```bash
sha1sum | sha256sum | md5sum
```

| 选项 | 作用 |
|---|---|
| （无） | 输出 `<哈希>  <文件名>` |
| `-c` / `--check` | **对照文件列表校验** |
| `-b` | 二进制模式（**Linux 上不用加**） |
| `--tag` | BSD 格式输出（`SHA256 (file) = hash`） |
| `--text` | 把二进制当文本 |

```bash
# 算哈希
$ sha256sum bigfile.iso
d1f2e3...  bigfile.iso

# 校验单个文件
$ echo "d1f2e3...  bigfile.iso" | sha256sum -c -
bigfile.iso: OK

# 批量：先存清单，再校验
$ sha256sum *.iso > checksums.sha256
$ sha256sum -c checksums.sha256
bigfile.iso: OK
other.iso: OK

# 和官方公布的比对（下载后第一件事）
$ sha256sum ubuntu.iso
$ grep 'SHA256' /官方页面上的校验值
```

⚠️ **`sha256sum -c` 依赖文件名**。目录整体移动后校验会因为路径不同而失败。

⚠️ **`md5sum` 和 `sha1sum` 已被证明可碰撞，不要用于安全目的**。校验完整性/传输用 `sha256sum`。md5 只在和历史文件比对时用。

⚠️ **哈希验证的是「文件没变」，不是「文件来源可信」**。攻击者能同时替换文件和哈希。要确认来源得验签名（GPG），见 [06-软件包管理.md](06-软件包管理.md)。

⚠️ **下载大 ISO 后校验是必须的**。损坏的 ISO 装出来的系统会有莫名其妙的问题。

## shred — 不可恢复地覆写文件

```bash
shred [选项]... 文件...
```

| 选项 | 作用 |
|---|---|
| `-n N` | 覆写 N 次（默认 3） |
| `-z` | 最后一次覆写为 0 |
| `-u` | 覆写后**删除文件** |
| `-v` | 显示进度 |
| `-f` | 允许写只读文件（需权限） |
| `--remove` | 覆写并删除（等于 `-u`） |

```bash
# 覆写 5 次并删除
$ shred -n 5 -u -z secrets.txt

# SSD 场景：单次覆写即可（见下）
$ shred -n 1 -u secrets.txt
```

⚠️ **`shred` 在 SSD / 闪存 / 日志式文件系统（LVM、btrfs zoned、CoW）上不可靠**。SSD 有磨损均衡，逻辑块会被重映射到不同物理位置，你的覆写根本没落在原数据上；CoW 文件系统每次写都新分配块。**在这类存储上唯一可靠的办法是加密（数据本身就没明文落盘）。**

⚠️ **日志式文件系统（ext3/ext4 的 journal、btrfs、ZFS）**上，覆写前后的块可能已经在日志/快照里留了旧内容。

⚠️ **`rm` 之后再 `shred` 没用**，先 `rm` 只是把目录项删了，数据块还在等复用，`shred` 也拿不到路径。要 shred 就直接 shred 别 rm。

⚠️ **最稳的做法是全盘加密**（LUKS）。那时"销毁密钥"就是销毁全部数据。

## 备份的三个 2-1-1 原则

真正的备份要满足：

| | |
|---|---|
| **3** 份副本 | 原始 + 至少 2 份备份 |
| **2** 种介质 | 别全在同一块盘 |
| **1** 份异地 | 不在同一栋楼 |
| **（1）份校验过** | 恢复过才知道能不能用 |

⚠️ **`rsync` 不是备份**。它做镜像，源删了目标跟着删。真正的备份需要**历史版本**——`rsync` 加 `--backup-dir` 保留被覆盖的旧版本：

```bash
$ rsync -a --backup --backup-dir=/backup/historical/$(date +%F) src/ user@host:/dst/
```

⚠️ **tar 也不等于备份**。tar 是打包工具，不负责定期执行、不负责异地、不负责保留历史。

⚠️ **一定要定期演练恢复**。没恢复过的备份等于没有备份。

## 小结

| 场景 | 命令 |
|---|---|
| Linux 间打包传输 | `tar -czf a.tar.gz -C /src dir/` |
| 解开 | `tar -xzf a.tar.gz -C /dst/` |
| 打包时排除 | `tar --exclude='*.log' --exclude=.git -czf a.tar.gz dir/` |
| 给 Windows 传 | `zip -r a.zip dir/` / `unzip a.zip -d out/` |
| 增量同步（先演练） | `rsync -avzn src/ user@host:dst/` |
| 真同步 | `rsync -avz --delete-delay src/ user@host:dst/` |
| 搬系统配置 | `rsync -aAXH --numeric-ids /etc/ target:/etc/` |
| 校验下载的文件 | `sha256sum -c checksums.sha256` |
| 不可恢复地销毁 | `shred -n 3 -u -z file` |
| **压得小最重要**（归档） | `tar -cJf a.tar.xz -C /src dir/` + 解压 `xz -T0 -d` |
| **又快又压得小**（传输） | `zstd -T0 -19 file` 或 `tar --zstd -cf a.tar.zst dir/` |
| 看压缩率 | `xz -l file.xz` |
| 解不可信归档前先看内容 | `tar -tf` / `unzip -l` / `cpio -itv` / `7z l` |
| **真备份（去重+加密）** | **`restic backup /etc /home`** |
| 备份完整性校验 | `restic check` |
| 同机多时间点快照 | `rsnapshot hourly` |
| 加密异地备份 | `duplicity /etc sftp://host//backup --encrypt-secret-key=KEYID` |

**十二条铁律**

1. **`tar` 打包路径用 `-C` + 相对路径**，绝对路径会在解开时重建目录树。
2. **解压外部归档前先 `tar -tf` 看一眼**，防路径穿越。
3. **`rsync` 的尾部斜杠决定语义**：`src/` 是内容，`src` 是目录本身。
4. **`--delete` 第一次必须加 `-n` 演练**，它没有后悔药。
5. **`gzip` 会删原文件**，要留就加 `-k`。
6. **`shred` 在 SSD / CoW / 快照上无效**，那种环境靠加密。
7. **`xz` 单线程解压极慢**，`xz -T0` 开并行；`xz -9` 内存占用高，1GB 内存的机器慎用。
8. **`tar --zstd -cf` 而不是 `tar -zstd -cf`**，GNU tar 没有 `-zstd` 单字母选项。
9. **`tar` 的压缩字母**：`z`=gzip `j`=bzip2 `J`=xz，`zstd` 只能写全名。
10. **解压不可信归档一律先列内容**（`tar -tf` / `unzip -l` / `7z l` / `cpio -itv`）。
11. **备份密码用 `RESTIC_PASSWORD_FILE`**，不要用命令行或普通环境变量。
12. **备份不验证等于没备份**：定期 `restic check`，并真的恢复一次到临时目录。
13. **备份必须有一份异机的**。rsnapshot 在同机上，机器坏了一起没。
