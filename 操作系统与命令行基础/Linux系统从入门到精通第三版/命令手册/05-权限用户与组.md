# 05 · 权限、用户与组

Linux 的权限模型只有**三个身份**（属主 / 属组 / 其他人）和**三个权限位**（读 / 写 / 执行）。
这一章的命令分三层：改文件权限 → 管账号 → 管提权。

---

## chmod — 改权限

```bash
chmod [选项]... 模式 文件...
```

**两种写法**

| 写法 | 例子 | 适用 |
|---|---|---|
| 八进制 | `chmod 644 file` | 一次性设定三个身份的权限 |
| 符号 | `chmod u+x file` | 只动某一位，或批量给某类文件加权限 |

**八进制每一位**：属主 / 属组 / 其他人，每位是 4(读) + 2(写) + 1(执行) 的和。

```
7 = rwx   读+写+执行（目录：能进、能列、能建删）
6 = rw-   读+写，不给执行
5 = r-x   读+执行，不给写
4 = r--   只读
0 = ----- 什么都没有
```

| 常见 | 含义 | 谁用 |
|---|---|---|
| `644` | `-rw-r--r--` | **普通文件，最常用** |
| `600` | `-rw-------` | 私密文件（`.ssh/id_rsa`） |
| `755` | `-rwxr-xr-x` | **脚本和目录，最常用** |
| `700` | `rwx------` | 私密目录（`~/.ssh`） |
| `775` | `rwxrwxr-x` | 团队共享目录 |
| `777` | `rwxrwxrwx` | ⚠️ **几乎总是错的** |

| 选项 | 作用 |
|---|---|
| `-R` | 递归 |
| `--reference=文件` | 抄另一个文件的权限 |
| `--preserve-root` | 拒绝操作 `/`（**默认已开启**） |
| `--verbose` | 显示改了什么 |

**符号写法**

```
[身份][操作][权限]  文件
身份：u 属主 / g 属组 / o 其他人 / a 全部（= ugo）
操作：+ 加 / - 减 / = 设为（**先清零再加**）
权限：r 读 / w 写 / x 执行 / X = 只对目录或已有执行位的文件生效
```

```bash
$ chmod 644 notes.txt
$ chmod 755 script.sh
$ chmod u+x script.sh                 # 只给属主加执行
$ chmod go-w notes.txt                # 去掉属组和其他人的写
$ chmod a=r notes.txt                 # 全部设为只读（先清零再加 r）
$ chmod -R u+rwX,go+rX project/       # 用户目录的常见权限
$ chmod --reference=a.txt b.txt       # 抄权限
$ chmod 600 ~/.ssh/id_rsa             # 私钥必须是 600
```

⚠️ **`=` 和 `+` 的区别**。`chmod u=r file` 是**先清空属主所有权限再给读**，执行位会被抹掉。`chmod u+r file` 是在原有基础上加。

⚠️ **大写 `X` 和小写 `x` 不同**。`X` 只在**目录**或**已经有执行位的文件**上加执行位。这个设计是为了让 `chmod -R a+X dir/` 安全 —— 否则所有普通文件都会变成可执行。**递归改权限永远用 `X` 不是 `x`。**

⚠️ **`chmod -R` 到系统目录会毁掉一切**。`chmod -R 777 /`、`chmod -R 000 /` 都能让系统立刻不可用。误操作后只能从 live 环境救。

⚠️ **`chmod 777` 不是"解决问题"，是取消权限系统**。程序需要特权的正确做法是用 `sudo` 执行程序本身，或用 `setuid`，不是给文件 777。

⚠️ **`chmod` 改不了属主**。提示 `Operation not permitted` 说明你是属组不是属主，需要 `chown` 或 `sudo`。

⚠️ **权限位不够用时要靠 ACL**（`setfacl`），`chmod` 表达不了「让某个特定用户可写」。见文件末尾。

## chown / chgrp — 改属主 / 属组

```bash
chown [选项]... 属主[:属组] 文件
chgrp [选项]... 属组 文件
```

| 选项 | 作用 |
|---|---|
| `-R` | 递归 |
| `-h` | 改符号链接**本身**的属主，不跟随 |
| `--reference=文件` | 抄另一个文件 |
| `--from=原属主` | 只改指定原属主的（安全） |
| `--no-preserve-root` | 允许操作 `/` |

```bash
$ sudo chown liu:liu notes.txt          # 同时改属主和属组
$ sudo chown liu notes.txt              # 只改属主
$ sudo chown :liu notes.txt             # 只改属组（前面留空）
$ sudo chgrp liu notes.txt
$ sudo chown -R liu:liu project/        # 递归
$ sudo chown -R liu:liu project/        # 末尾斜杠影响递归行为！
```

⚠️ **`chown -R` 的末尾斜杠影响结果**。`chown -R user dir` 和 `chown -R user dir/` 在旧版 GNU 里可能不同。**统一带斜杠并用完整路径。**

⚠️ **`chown -R` 跟错符号链接会改到别处**。默认**跟随命令行上的符号链接**，但不跟随递归遇到的。加 `-h` 才是改链接本身。

⚠️ **`chown` 会清掉 setuid/setgid 位**。改属主等于换人跑，需要 `sudo` 显式保留。`chmod u+s` 要在 chown **之后**执行。

⚠️ **批量改之前先 `ls -ld` 确认路径**。`chown -R user /` 之后想恢复要重启。

⚠️ **不要用 `chown` 代替 `chmod`**。文件该属谁和该谁能执行是两个正交的问题。

## umask — 默认权限掩码

新建文件/目录时，权限 = 请求的权限 `AND NOT` umask。

```bash
umask [-S] [-p]
```

| 文件类型 | 请求权限 | 常见 umask 022 后 | 常见 umask 077 后 |
|---|---|---|---|
| 普通文件 | `666` | `644` | `600` |
| 目录 | `777` | `755` | `700` |

```bash
$ umask                  # 输出数字形式
0022
$ umask -S               # 输出符号形式
u=rwx,g=rx,o=rx

$ umask 077               # 当前 shell 生效
$ umask 0022

# 写进 ~/.bashrc 固化
$ echo 'umask 027' >> ~/.bashrc
```

⚠️ **umask 是「减掉的权限」，不是「保留的权限」**。`umask 022` 意思是不给 group 和 other 的写权限。**写越大越严格。**

⚠️ **umask 只影响新建的文件**，改不了已有的。用 `chmod`。

⚠️ **`umask` 只在当前 shell 及其子进程生效**，换个终端就没了。要持久化写进 shell 配置文件。

⚠️ **`sudo` 的 umask 与你的不同**（默认更严，通常 `0022` 或更严）。这解释了为什么"我明明建了文件别人却读不了"。

## getent — 查数据库里的账号信息

```bash
getent [选项] 数据库 [键]...
```

| 数据库 | 内容 |
|---|---|
| `passwd` | 用户 |
| `group` | 组 |
| `shadow` | 密码哈希（需 root） |
| `services` | 服务名/端口 |

```bash
$ getent passwd liu                 # 像 grep passwd，但走 NSS
$ getent passwd | wc -l              # 用户总数
$ getent group docker
$ getent group docker
$ sudo getent shadow myapp          # 密码哈希
$ getent services ssh               # ssh → 22/tcp

# 查名字→数字，查不到说明账号不存在
$ getent passwd nosuchuser; echo $?
2
```

⚠️ **查账号用 `getent passwd`，不要 grep `/etc/passwd`**。`getent` 会依次查 NSS（本地文件、LDAP、SSSD……），**只 grep 文件在接入 LDAP/SSSD 的机器上会漏掉一大半账号**。这是很实际的一个坑。

⚠️ **「用户不存在」和「NSS 查不到」都返回非 0**。`getent` 不区分，得自己看。

## id / whoami — 我是谁

```bash
id [选项] [用户]
whoami
groups
```

| 选项 | 作用 |
|---|---|
| （无） | 打印 UID、GID、所有组 |
| `-u` | 只 UID |
| `-g` | 只 GID |
| `-G` | 所有组 ID |
| `-n` | 显示名字而非数字 |
| `-r` | 显示真实 ID（去掉有效 ID 影响） |

```bash
$ id
uid=1001(liu) gid=1001(liu) groups=1001(liu),27(sudo),4(adm),988(docker)

$ id -u          # 1001
$ id -un         # liu
$ id -G          # 1001 27 4 988
$ id -Gn         # liu sudo adm docker

$ whoami         # liu
$ groups         # 当前用户的所有组
```

⚠️ **`id` 的输出顺序不保证稳定**，脚本里别假设组一定按某种顺序。

⚠️ **判断"我能做什么"要看所有组，不只看主组**。`sudo` 权限来自 `sudo` 这个**补充组**，不是主组。

⚠️ **有效 UID vs 真实 UID**（`sudo` 会改变有效 UID）。看真实身份用 `id -r`。排查「文件读不了」的权限问题时会用到。

⚠️ **`id -un` 和 `$USER` 不总一致**。`USER` 是环境变量（可以伪造），`id` 直接查系统。**脚本里判断身份用 `id -un`。**

## useradd / adduser — 建用户

⚠️ **Debian/Ubuntu 上有两个不同的命令，行为不一样**：

| | `useradd` | `adduser` |
|---|---|---|
| 来源 | shadow-utils（原 SuSE） | Debian 包装脚本（perl） |
| 建用户组 | **不自动建** | **默认自动建同名的** |
| 建 home | **默认不建**（`/home/liu` 不存在） | **默认建** |
| 登录 shell | `/bin/sh`（按 `/etc/default/useradd`） | `/bin/bash` |
| 密码 | 锁定 | 交互设置 |
| 风格 | 底层、灵活、**适合脚本** | 上手友好、**适合手动** |

```bash
# adduser（交互，手动建用户）
$ sudo adduser liu
# 会问：全名、房间号、电话、是否设密码等，最后打印「信息是否正确」

# adduser 的常用非交互形式
$ sudo adduser --system --group --no-create-home svc-backup
$ sudo adduser --disabled-password --gecos "" deploy

# useradd（脚本，精细控制）
$ sudo useradd -m -s /bin/bash -c "Liu Ops" liu
$ sudo useradd -r -s /usr/sbin/nologin -c "My App" myapp
```

**useradd 常用选项**

| 选项 | 作用 |
|---|---|
| `-m` | **创建 home 并从 `/etc/skel` 拷模板** |
| `-M` | 不建 home（**默认就是不建**） |
| `-d 路径` | 指定 home 路径（**不给它加 `-m` 就不会创建**） |
| `-s` | 登录 shell |
| `-G 组1,组2` | 加入**附加组**（可多个） |
| `-g 组` | 主组 |
| `-u UID` | 指定 UID |
| `-r` | **系统账号**，UID 从系统号段分配，**不建 home，shell 默认 nologin** |
| `-f` | 即使 `-r` 也建 home |
| `-k 目录` | 改模板目录（默认 `/etc/skel`） |
| `-c 备注` | GECOS 字段，`finger` 能看到 |
| `-e 日期` | 账号过期日期 |
| `-N` / `-U` | 强制同名的用户组 / 独立的用户组 |

```bash
# 交互建普通用户：给 home、给 bash shell、加两个附加组
$ sudo useradd -m -s /bin/bash -G sudo,docker liu
$ sudo passwd liu

# 建服务账号（不能登录）
$ sudo useradd -r -s /usr/sbin/nologin -c "My Application" myapp
```

⚠️ **`useradd -m` 和 `-d` 是两件事**。`useradd -d /var/lib/myapp myapp` **只记录路径，不会创建目录**，而且因为没 `-m` 所以 home 不会被拷贝模板。结果是目录不存在 → 服务起不来。要么加 `-m`，要么自己建目录：

```bash
$ sudo install -d -o myapp -g myapp -m 0750 /var/lib/myapp
```

⚠️ **`useradd` 默认不建 home**。用 `useradd` 建了用户然后 `su - liu` 报 `No such file or directory`，就是因为 home 不存在。

⚠️ **`useradd -r` 的 UID 是动态分配的**。不同机器上服务账号可能是 991、995、998。**脚本里不要写死系统账号 UID**，用 `id -u myapp` 拿。

⚠️ **`useradd` 不设密码 → 账号密码登录锁定，但 `su -` 仍能切进去**（root 可以）。想彻底禁用在 shell 设 `/usr/sbin/nologin`。

⚠️ **`useradd` 建的用户默认不在 `sudo` 组**，新建用户 sudo 不了。要显式 `-G sudo`。

⚠️ **`/usr/sbin/nologin` 在 Debian/Ubuntu 上，不在 `/sbin/`。**很多老文档写错。`command -v nologin` 可以查。

⚠️ **删用户用 `userdel`，删组用 `groupdel`，别手工去删 `/etc/passwd` 里的行。**

## usermod — 改用户

```bash
usermod [选项]... 用户
```

| 选项 | 作用 |
|---|---|
| `-a` | **追加**（配合 `-G`，**几乎必写**） |
| `-G 组1,组2` | 设置附加组 |
| `-g 组` | 改主组 |
| `-d 路径` | 改 home 路径 |
| `-m` | **配合 `-d`，把家目录搬过去** |
| `-s` | 改登录 shell |
| `-l 新名` | 改用户名 |
| `-L` | 锁定账号（前置 `!`） |
| `-U` | 解锁 |
| `-u` | 改 UID |
| `-c` | 改备注 |
| `-e 日期` | 账号过期 |
| `-f` | 立即执行过期（`-f -1` 取消） |
| `-aG 组` | 追加到附加组（简写，最常用） |

```bash
$ sudo usermod -aG docker liu         # 加入 docker 组
$ sudo usermod -aG sudo,docker liu    # 同时加多个
$ sudo usermod -s /bin/zsh liu        # 换 shell
$ sudo usermod -L liu                 # 锁定
$ sudo usermod -U liu                 # 解锁
$ sudo usermod -d /data/liu -m liu    # 改并搬 home
$ sudo usermod -l liwei liu           # 改名
```

⚠️ **`-a` 不写会踢掉用户原有的所有附加组**。这是 usermod 最著名的事故：

```bash
$ sudo usermod -G docker liu          # ❌ liu 的 sudo 组没了，变成不能 sudo
$ sudo usermod -aG docker liu         # ✅ 在原有基础上加
```

**`-a` = append。记不住就永远写 `-aG`。**

⚠️ **加入组之后当前会话不生效**，要重新登录（或 `newgrp docker` 在当前 shell 临时切）。`su - liu` 会重新读组信息。

⚠️ **`usermod -d` 不加 `-m` 只改路径记录**，旧文件留在原地。改完登录会进空目录（因为目标不存在）。**搬家必须带 `-m`。**

⚠️ **`usermod -l` 改名不改 UID**，所以文件属主显示的还是旧名字（`ls` 显示数字）。改 UID 要 `usermod -u`，但那会让所有文件属主对不上，**必须同时 `chown -R`**。

⚠️ **不能用 `usermod` 改正在运行的进程的属主**，进程仍跑在旧 UID 下。

## userdel / groupdel / groupmod — 删改组

```bash
userdel [选项]... 用户
groupdel [选项]... 组
groupmod [选项]... 组
groupadd [选项]... 组
newgrp 组
```

| 命令 | 选项 | 作用 |
|---|---|---|
| `userdel` | 无 `-r` | 只删账号，**home 目录留下** |
| `userdel` | **`-r`** | **连 home 和邮件目录一起删** |
| `userdel` | `-f` | 强制（**会删掉已存在的 home**） |
| `groupadd` | `-g GID` | 指定 GID |
| `groupadd` | `-r` | **系统组**（GID 从 1000 段起分配） |
| `groupdel` | `-f` / `--force` | 强制删（即使 GID 还被文件引用） |
| `groupmod` | `-n 新名` | 改组名 |
| `groupmod` | `-aG 用户` | 加**附属**成员 |
| `groupmod` | `-g GID` | 改 GID |

```bash
$ sudo userdel liu                    # 只删账号
$ sudo userdel -r liu                 # 删账号 + home（⚠️ 不可恢复）
$ sudo groupadd docker
$ sudo groupadd -r docker             # 系统组
$ sudo groupdel docker                # 删组（组里还有成员会失败）
$ sudo gpasswd -d liu docker          # ⭐ 先摘成员再删组
$ sudo groupmod -a liu docker         # 加附属成员（不用切组）
$ sudo groupmod -n docker-prod docker # 改组名
$ newgrp docker                       # 当前 shell 切到该组
```

⚠️ **`userdel` 不带 `-r` 会留下孤儿 home 目录**。看到 `userdel` 没加 `-r` 要意识到目录还在占空间。

⚠️ **`userdel -r` 会删掉用户所有文件，不可恢复**。执行前 `ls -la /home/用户名` 看一眼，**先 `tar` 打包或备份**。

⚠️ **`groupdel` 没有 `-a` 选项**。把成员从组里摘出来用 **`gpasswd -d 用户 组名`**。删组之前必须先做这一步，否则 `groupdel` 报 `group 'docker' has some members`。

⚠️ **用户 UID 被删除后会变成孤儿 UID**，之后新建用户可能复用这个 UID，然后**旧文件突然归新用户所有**。删账号前先把 home 归档，或把 UID 改到一个保留段。

⚠️ **改 GID 和改 UID 一样有同样的孤儿文件问题**。

## passwd / chage — 密码与有效期

```bash
passwd [选项]... [用户]
chage [选项]... 用户
```

**passwd**

| 选项 | 作用 |
|---|---|
| （无，自己） | 改自己的密码 |
| `-l` | **锁定**密码（前置 `!`），账号保留 |
| `-u` | 解锁 |
| `-e` | 强制下次登录改密码 |
| `-S` | 查看密码状态 |
| `-n N` | 最短使用天数 |
| `-x N` | 最长使用天数 |
| `-i N` | 过期后宽限天数 |
| `-d` | **删除密码**（⚠️ 等于无密码） |
| `-k` | 强制改密码（仅 root） |

```bash
$ passwd                          # 改自己的
$ sudo passwd liu                 # 改别人的
$ sudo passwd -l liu              # 锁定（离职）
$ sudo passwd -u liu              # 解锁
$ sudo passwd -e liu              # 下次登录必须改
$ sudo passwd -S liu              # 看状态
```

**chage**

| 选项 | 作用 |
|---|---|
| `-l` | 看密码有效期策略 |
| `-M N` | 最长使用天数 |
| `-m N` | 最短使用天数（两次改密最小间隔） |
| `-W N` | 到期前提前几天警告 |
| `-I N` | 密码过期后账号锁定多少天 |
| `-E 日期` | 账号绝对过期日（`2024-12-31` 或 `-1` 取消） |
| `-d 日期` | 最后改密码的日期 |

```bash
$ chage -l liu
$ sudo chage -M 90 -m 7 -W 14 liu      # 90 天必改、7 天内不能改、提前 14 天警告
$ sudo chage -E 2024-12-31 liu         # 离职：到期账号作废
$ sudo chage -E -1 liu                 # 取消过期
$ sudo chage -I -1 liu                 # 密码过期也不锁账号
```

⚠️ **`passwd -l` 锁不住「空密码」账号**。密码本来就是空的话，「加锁」没有意义（空密码本来就是畅通的）。**空密码是重大漏洞，要立刻设密码或 `passwd -l` + 确认账号不是空密码。**

⚠️ **`passwd -l` 不阻止 root 登录**，也不阻止 SSH 公钥登录（如果 `PermitRootLogin` 允许）。**禁用账号要同时做三件事**：`passwd -l`、`usermod -s /usr/sbin/nologin`（或设过期 `chage -E`）、移除 SSH 公钥。

⚠️ **`passwd -d` 是删密码不是设密码**。写错成 `-d` 等于给账号开无密码后门。

⚠️ **`chage -I -1`** 把「密码过期后锁账号」关掉，安全性下降，只在特殊场景用。

## chpasswd / gpasswd — 批量设密码 / 管组成员

```bash
chpasswd            # 从标准输入读 用户:密码
gpasswd [选项]... 组
```

| gpasswd 选项 | 作用 |
|---|---|
| `-a 用户` | 加成员 |
| `-d 用户` | 移成员 |
| `-m 用户` | 设组成员为只有该用户（**危险，等于踢掉所有其他人**） |
| `-A` | 管理员列表 |
| `-S` | 看组信息 |
| `-e` | 密码过期时间 |
| `-k` | 只改组密码 |

```bash
# 批量设密码（密码从文件读，不要写在命令行）
$ sudo chpasswd < passwords.txt
# 文件格式：liu:$6$abc...$def...
# 或直接传明文（会留在历史里，慎用）
$ echo 'liu:MyPass123' | sudo chpasswd

# 管理组成员
$ sudo gpasswd -a liu docker
$ sudo gpasswd -d liu docker
$ sudo gpasswd -A liu,wang docker       # 设管理员
```

⚠️ **`gpasswd -m` 会把组里所有人踢掉**，只留你指定的那个。名字像"manage"很容易误用。

⚠️ **别在命令行里写密码**（`chpasswd` 的明文形式、`useradd -p`、`sshpass -p`）。**密码会进 shell 历史，也会出现在 `ps` 输出里**。用文件重定向、交互输入或 `-e` 传哈希。

⚠️ **组密码是历史遗留功能**，现在基本不用（成员制才是正路）。看到组设密码要警惕是不是配错了概念。

## su — 切换用户

```bash
su [选项]... [-] [用户]
```

| 选项 | 作用 |
|---|---|
| 无 | 切到 root，**保留原环境**（危险） |
| **`-` / `-l`** | **登录式切换：换环境、换 HOME、加载目标用户的登录脚本** |
| `-c 命令` | 执行单条命令后退出 |
| `-s` | 指定 shell |
| `-p` | 保留原环境（含 `$PATH`） |

```bash
$ sudo su - liu              # 完整登录 liu（推荐）
$ su -c 'id' - liu          # 切到 liu 执行 id 再回来
$ su liu -c 'whoami'
$ su - liu                   # 目标用户写在后面（老写法）
```

⚠️ **`su` 不带 `-` 是真正的坑**。`su liu` 会保留 root 的 `$PATH`、`$HOME`、已设的 `LD_PRELOAD` 等。**排查"为什么 su 过去还是 root 的环境"就用不带 `-` 的 `su`。**统一用 `su -`。

⚠️ **`su - liu` 不读 `.bashrc`，读 `.profile` / `.bash_profile`**。这是 shell 配置里的经典差异（见 [09](09-Shell与脚本基础.md)）。想统一到 `.bashrc` 就在 `.profile` 里 source 它。

⚠️ **`su` 不记审计日志**，用 `sudo` 有日志。**生产服务器上用 `sudo -i su - user` 的组合，或直接 `sudo -u user -i`。**

## sudo — 提权执行

```bash
sudo [选项]... 命令
```

| 选项 | 作用 |
|---|---|
| `-l` / `-ll` | **列出当前用户的 sudo 权限** |
| `-u 用户` | 以别的用户身份跑（默认 root） |
| `-g 组` | 以别的组身份 |
| `-i` | **模拟完整登录**（换 HOME、加载登录脚本） |
| `-s` | 只换 shell |
| `-E` | 保留环境变量 |
| `-H` | 换 `$HOME`（`-i` 已包含） |
| `-n` | **非交互**，没权限直接失败不提示 |
| `-k` | **立即作废缓存的凭据** |
| `-v` | 延长/刷新凭据有效期 |
| `-A` | 用辅助程序问密码（配合 askpass） |

**sudoers 里 `/etc/sudoers.d/` 的写法**

```
# 允许 liu 执行 systemctl 重启 cron，不要密码
liu ALL=(root) NOPASSWD: /usr/bin/systemctl restart cron

# 允许 opsdemo 执行指定命令，要密码
opsdemo ALL=(root) /usr/bin/systemctl restart cron

# 允许用户切换到特定用户，不要密码
liu ALL=(liu,liu-wang) NOPASSWD: ALL

# 只允许在特定主机
liu SERVER1 = (root) NOPASSWD: /usr/bin/apt update

# 授权目录下的命令（⚠️ 有提权风险，见下）
liu ALL=(root) NOPASSWD: /opt/scripts/
```

```bash
$ sudo -l                                  # 我能 sudo 什么
$ sudo systemctl restart cron
$ sudo -u www-data ls /var/www
$ sudo -u myapp -i                        # 模拟以 myapp 完整登录
$ sudo -i                                 # 切到 root 登录环境
$ sudo -n true                            # 脚本里：没权限直接失败
$ sudo -k                                 # 走之前作废凭据缓存
```

⚠️ **一定要用 `visudo` 改 sudoers，绝不直接编辑**。语法错误会让 sudo 完全锁死（连 root 都进不去），`visudo` 会在保存前做语法检查并自动保留一份能用的备份。**这是 sudo 最重要的安全习惯。**

⚠️ **用 sudoers 授权目录极危险**。`liu ALL=(root) NOPASSWD: /opt/scripts/` 等于把 root 给了 liu —— 他可以在那个目录里放一个自己写的脚本然后 sudo 执行。**必须指定具体命令，不能授权目录。**

⚠️ **`sudo` 的默认配置 `!authenticate` 等标记会变**，以 `sudo -l` 输出和你机器上的 `/etc/sudoers` 为准，不要照抄网上教程。

⚠️ **sudoers 里必须用绝对路径**，且**命令路径后面跟参数才是精确匹配**。写 `/usr/bin/systemctl` 就允许任何参数；写 `/usr/bin/systemctl restart cron` 只允许这一条。

⚠️ **`sudo -u` 不等于切换身份环境**。`sudo -u myapp cmd` 用的是 root 的环境变量，只是 UID 变了。要完整切换用 `sudo -u myapp -i` 或 `su - myapp`。**这个区别在验证权限时经常搞错。**

⚠️ **sudo 默认不继承 `PATH`**，也不透传某些变量。用 `secure_path` 控制。要透传用 `sudo -E`（需 `SETENV` 权限）。

⚠️ **`sudo` 的凭据缓存有时间**。输一次密码后能连续用几分钟（看 `timestamp_timeout`）。**共用账号场景下别人能用你的 sudo 额度**，用完 `sudo -k` 立刻失效。

## visudo — 安全地改 sudoers

```bash
visudo [选项]...
```

| 选项 | 作用 |
|---|---|
| （无） | 改 `/etc/sudoers` |
| `-f 文件` | **检查指定文件**（`visudo -cf /etc/sudoers.d/liu`） |
| `-c` | **只检查语法，不编辑** |
| `-x` | 导出为 JSON |
| `-s` | 严格检查（连拼写可疑的写法也报） |
| `-q` | 静默模式 |

```bash
$ sudo visudo                       # 改主配置
$ sudo visudo -f /etc/sudoers.d/liu # 改片段
$ sudo visudo -cf /etc/sudoers      # ⭐ 只检查语法（改完验证用）
$ sudo visudo -c                    # 检查主文件
```

⚠️ **`visudo` 做的三件事**是用别的编辑器做不到的：编辑前备份、保存前语法检查（语法错直接拒绝保存）、**语法错时自动调用编辑器让你修**。

⚠️ **sudoers 语法错误的后果是 sudo 完全不可用**，连 root 都执行不了 sudo，只能用 root shell 或进 rescue 模式。**改 sudoers 之前保持一个已登录的 root 会话（`sudo -i`）。**

⚠️ **别用 `sudo sed -i` 直接改 sudoers**，绕过检查的后果就是上面那条。**唯一例外**是用 `visudo -f` 改片段文件，这是官方推荐做法。

⚠️ **`/etc/sudoers.d/` 里的片段文件名不能有 `.`**，且**不能以 `~` 结尾**（`sudoedit` 的备份），否则 sudo 会静默忽略它们。用 `visudo -c` 可以看出哪些没被读。

⚠️ **改完验证**：

```bash
$ sudo visudo -cf /etc/sudoers.d/liu   # 必须输出 parsed OK
$ sudo -l -U liu                        # 确认实际生效的权限
```

## faillock / pam_faillock — 登录失败锁定

```bash
faillock [选项]...
```

| 选项 | 作用 |
|---|---|
| `--user 用户` | 看某用户状态（**默认看当前用户**） |
| `--unlock 用户` | 解锁 |
| `--reset` | 重置失败计数 |
| `--time now` | 立即锁定 |
| `--ttl N` | 锁定时长（秒） |
| `--reset` | 清零计数 |
| `--dir 路径` | 记录目录 |

⚠️ **`faillock` 命令来自 `faillock` 包，默认不装**。`sudo apt install faillock`。

⚠️ **更重要的是 PAM 配置本身**：`/etc/pam.d/common-auth` 里要有 `pam_faillock.so` 相关行，Ubuntu 默认**没有启用**。命令能用不代表锁定生效。检查：

```bash
$ grep -rn faillock /etc/pam.d/     # 没输出 = 没启用
```

⚠️ **启用 `faillock` 会影响 SSH 和本地登录**，配错了可能把自己锁在外面。**改 PAM 前保持一个已登录的 root 会话，并确认另一个终端能登录再退出。**

## getcap / setcap / getfacl — setuid 之外提权方式

```bash
getcap [选项]... 文件...
setcap 能力[=值]... 文件
setcap -r 文件              # 移除能力
getfacl [选项]... 文件
setfacl [选项]... 文件
```

**常见文件能力**

| 能力 | 作用 |
|---|---|
| `cap_net_bind_service` | 绑定 1024 以下端口 |
| `cap_net_raw` | 原始套接字（`ping` 需要） |
| `cap_dac_override` | 绕过读权限检查 |
| `cap_sys_admin` | **几乎等于 root，慎给** |

| getcap 选项 | 作用 |
|---|---|
| `-r` | 递归 |
| `-n 数字` | 用数字 UID/GID 显示 |
| `-v` | 详细 |
| `-n`（getfacl） | 不解析名字 |

```bash
# 看某个二进制有没有能力
$ getcap /usr/bin/ping
$ getcap -r /usr/bin/          # 递归看整个目录

# 常见做法：给服务绑定 80 端口的能力（不用 root 跑）
$ sudo setcap cap_net_bind_service=+ep /usr/local/bin/myserver

# 移除能力（⭐ 别忘）
$ sudo setcap -r /usr/local/bin/myserver

# ACL：给某用户单独授权
$ setfacl -m u:liu:rwx /srv/data
$ setfacl -d -m u:liu:rwx /srv/data     # 默认 ACL，新文件也继承
$ getfacl /srv/data
```

⚠️ **文件能力是 setuid 的现代替代品**，粒度更细、可审计性更好，`/proc/sys/fs/suid_dumpable` 相关的攻击面也小。**新东西优先用 `setcap`。**

⚠️ **能力会跟着文件走**。`cp` 一个带 `cap_net_raw` 的文件，能力可能被清掉（要看 `security.capability` xattr 和 `no_new_privs`）。**部署带能力的文件用 `install` + `setcap` 两步走更稳。**

⚠️ **`cap_sys_admin` 几乎等价于 root**，而且**在某些场景下（容器、用户命名空间）反而更容易提权**。只给真正需要的那一个能力。

⚠️ **`setcap` 之后一定要验证服务还起不来**。有些程序检测到非 root 身份 + 能力后会主动放弃功能。测完记得 `setcap -r` 清掉。

⚠️ **ACL 和传统权限会互相干扰**。`ls -l` 显示的 `+` 表示有 ACL，此时 `chmod` 的行为可能和你想的不一样（`chmod` 的某些位会改 ACL 掩码）。**排查权限问题时 `getfacl` 优先于 `ls -l`。**

## pwconv — passwd 哈希迁移

```bash
pwconv [选项]
```

| 选项 | 作用 |
|---|---|
| （无） | 把 `/etc/passwd` 里的哈希搬到 `/etc/shadow` |
| `-r` | **只处理 passwd，已在 shadow 里则跳过** |
| `-s` | 只处理 shadow |

⚠️ **`pwconv` 是 Debian 3.x（2002 年）的遗留工具**。Ubuntu 上 `/etc/passwd` 的密码字段是 `x`，真正的哈希在 `/etc/shadow`。**`pwconv` 在现代 Ubuntu 上通常是空操作**。搞混方向会以为它「把 shadow 的密码写回 passwd」，那是错的——它**从不写回 passwd**。

⚠️ **不要为了"安全"把 `/etc/shadow` 的哈希复制回 `/etc/passwd`**。那会把哈希暴露给所有本地用户。`/etc/shadow` 必须 root-only。

⚠️ **想看哈希用 `sudo getent shadow 用户`，别用 `pwconv`**。

## openssl — 生成随机与哈希

```bash
openssl rand [选项]
openssl passwd -6 [密码]
openssl dgst -sha256 [文件]
```

```bash
# 随机字符串
$ openssl rand -base64 32           # 43 字符，用于 API key
$ openssl rand -hex 16              # 32 字符十六进制
$ openssl rand -hex 24              # 48 字符

# 生成密码哈希（yescrypt，Ubuntu 默认算法）
$ openssl passwd -6 'MyPassword'
$ python3 -c "import crypt; print(crypt.crypt('pw', crypt.mksalt(crypt.METHOD_SHA512)))"

# 算哈希
$ openssl dgst -sha256 file.iso
```

⚠️ **`openssl passwd -1` 是 MD5，`-5` 是 SHA-256，都不如 yescrypt（`$y$`）或 SHA-512（`$6$`）。**Ubuntu 默认口令哈希是 `$y$`（yescrypt）。存密码用系统的 `chpasswd`，别自己拼 `openssl passwd`。

⚠️ **命令行上写密码会进历史**。用交互输入或管道。

## ACL — 权限表达不了的时候

`chmod` 只能表达「属主 / 属组 / 其他人」三个身份。需要「让某个具体用户可写，但其他人不行」时要用 ACL。

```bash
# getfacl / setfacl 来自 acl 包
$ sudo apt install acl

$ sudo setfacl -m u:liu:rw notes.txt      # 给 liu 读写权限
$ sudo setfacl -m g:devs:rwx project/     # 给 devs 组全部权限
$ sudo setfacl -m d:u:liu:rwx project/    # 默认 ACL，新建的子文件继承
$ sudo setfacl -x u:liu notes.txt         # 删掉某条 ACL
$ sudo setfacl -b notes.txt               # 删掉所有扩展 ACL

$ getfacl notes.txt
# owner: liu
# group: liu
# user::rw-
# user:liu:rw-          ← 额外授权
# group::r--
# other::---
```

⚠️ **`ls -l` 看不到 ACL**。有 ACL 的文件权限位后面会多一个 `+` 号，但要看具体规则必须用 `getfacl`。

⚠️ **`chmod` 会部分改写 ACL 的 mask**，改完 ACL 用 `getfacl` 复查。ACL 和权限位是两套机制，混着改容易互相覆盖。

⚠️ **`cp` 默认不保留 ACL**，要 `cp -a` 或 `getfacl` / `setfacl` 手动迁移。

## 小结

| 场景 | 命令 |
|---|---|
| 脚本/文件默认权限 | `chmod 755 script.sh` / `chmod 644 file` |
| 只给某身份加执行 | `chmod u+x script.sh` |
| 递归改目录权限 | `chmod -R u+rwX,go+rX dir/` |
| 改属主属组 | `sudo chown user:group file` |
| 建普通用户 | `sudo useradd -m -s /bin/bash -G sudo liu` |
| 建服务账号 | `sudo useradd -r -s /usr/sbin/nologin myapp` |
| 加附加组 | `sudo usermod -aG docker liu` |
| 删用户（留 home） | `sudo userdel liu` |
| 删用户（删 home） | ⚠️ `sudo userdel -r liu` |
| 锁账号 | `sudo passwd -l liu` + `sudo usermod -s /usr/sbin/nologin liu` |
| 设密码有效期 | `sudo chage -M 90 -m 7 -W 14 liu` |
| 查账号（走 NSS） | `getent passwd liu` |
| 完整切换身份 | `sudo -i` 或 `su - liu` |
| 查我的 sudo 权限 | `sudo -ll` |
| 精确授权一条命令 | `visudo` 加 `liu ALL=(root) NOPASSWD: /usr/bin/systemctl restart cron` |
| 验证服务账号权限 | `sudo -u myapp -i cmd`（**必须 `-i`，见坑**） |

**十条铁律**

1. **`chmod -R` 到系统目录 = 毁机器**。误操作只能从 live 环境救。
2. **`chmod 777` 是取消权限，不是修问题**。
3. **`usermod -G` 不写 `-a` 会踢掉原有的附加组**，永远写 `-aG`。
4. **`useradd` 默认不建 home**，`-d` 不带 `-m` 也不建。
5. **改 sudoers 只能用 `visudo`**，直接编辑可能把自己锁在外面。
6. **sudoers 里精确写命令+参数，绝不授权目录**。
7. **`userdel -r` 不可恢复**，执行前先 `ls` 看一眼。
8. **`userdel` 不带 `-r` 会留下孤儿目录**占着配额。
9. **密码永不写命令行**（`-p`、`-P`、`echo`），会进历史和 `ps`。
10. **查账号用 `getent` 不用 `grep /etc/passwd`**，否则接了 LDAP/SSSD 会漏。
