## ps — 看进程快照

`ps` 有**两套不兼容的语法**，这是它最大的坑。

| 风格 | 用法 | 特点 |
|---|---|---|
| **BSD** | `ps aux` | 选项可以不带 `-`，**带 `%CPU` `%MEM`** |
| **System V** | `ps -ef` | 选项必须带 `-`，字段更多 |

```bash
$ ps aux                       # BSD 风格：谁在跑、CPU/内存
USER  PID %CPU %MEM   VSZ   RSS TTY  STAT START   TIME COMMAND
liu   1234  0.5  1.2 123456 7890 ?   Sl   10:33   0:03 nginx: worker

$ ps -ef                       # System V 风格：完整命令行 + 父子关系
UID   PID  PPID  C STIME TTY  TIME CMD
liu   1234  1200  0 10:33 ?    00:00:03 nginx: worker

$ ps -ef --forest               # ⭐ 树状显示父子关系，排查进程问题的关键
$ ps -u liu                     # 某用户的进程
$ ps aux --sort=-%cpu | head    # 按 CPU 排序
$ ps aux --sort=-%mem | head    # 按内存排序
$ ps -eo pid,ppid,user,%cpu,%mem,cmd --sort=-%cpu | head
$ ps -p 1234                    # 指定 PID
$ ps -C nginx                   # 按命令名
$ ps aux | grep nginx           # 经典写法（见下方坑）
```

⚠️ **`ps aux | grep xxx` 会把 `grep` 自己列出来**。因为 `grep xxx` 这条命令行里含 "xxx"。三种正确写法：

```bash
$ pgrep -a nginx                              # ⭐ 最好
$ ps aux | grep '[n]ginx'                     # 方括号让 grep 匹配不到自己
$ ps -C nginx                                 # 最干净
```

⚠️ **`ps aux` 和 `ps -ef` 的列完全不同**。`%CPU`/`%MEM` 只有 BSD 风格有；`PPID`（父进程）System V 风格更清楚。

⚠️ **`VSZ` 和 `RSS` 不是一个东西**。`VSZ` 是虚拟内存（含未映射的、交换出去的），看着几个 GB；`RSS` 是**实际占用的物理内存**。**判断内存占用看 RSS。**

⚠️ **`STAT` 列要会读**：

| 值 | 含义 |
|---|---|
| `R` | 运行中或就绪 |
| `S` | 可中断睡眠（**大部分进程常态**） |
| `D` | **不可中断睡眠**（卡在 I/O，通常是磁盘或 NFS 问题） |
| `T` | 已停止（`Ctrl+Z` 之后） |
| `Z` | **僵尸**（已退出但父进程没回收） |
| `I` | 空闲的内核线程 |

`D` 状态堆积和 `Z` 状态堆积都要查。

⚠️ **`ps` 不带参数只列当前终端的进程**（加 `-a` 才看全部）。

⚠️ **`%CPU` 是开机以来的平均值**，不是瞬时值。要看瞬时用 `top` 或 `pidstat`。

## top / htop — 实时监控

```bash
top [选项]
htop        # 更友好的交互界面，需安装
```

| top 选项 | 作用 |
|---|---|
| `-p PID` | 只监控指定进程 |
| `-u 用户` | 只看某用户 |
| `-d 秒` | 刷新间隔 |
| `-b` | 批处理模式（输出一次就退出，配合管道） |
| `-n N` | 刷新 N 次后退出（配合 `-b`） |

**top 里最常用的键**

| 键 | 作用 |
|---|---|
| `P` / `M` | 按 CPU / 内存排序 |
| `1` | 展开所有 CPU 核心 |
| `c` | 显示完整命令行 |
| `k` | **杀进程**（输入 PID） |
| `q` | 退出 |
| `H` | 显示每个线程 |

```bash
$ top                          # 实时
$ top -u www-data
$ top -p 1234
$ sudo top -b -n 1 | head -20   # 采一次样就退出（脚本里用）
$ sudo apt install htop        # htop 更好用
```

⚠️ **内存要看的不是 `free` 里的 free，是 `available` 和 `%Mem`**。Linux 会拿空闲内存做缓存，`free` 一直很低是**正常且健康**的。看「真正还能用多少」看 `available`。

⚠️ **`RES`（RSS）高不等于内存泄漏**，要看是否持续增长。快照没意义，趋势才有意义。

⚠️ **CPU 使用率 100% 不一定是问题**。有进程在跑满就是正常的（`COMMAND` 里能看到谁）。`top` 里 `100.0%id` 才说明真空闲。

⚠️ **`top` 的第一行 `load average` 不是 CPU 使用率**。它表示**运行队列长度**（含不可中断睡眠）。1 分钟负载 > CPU 核数才需要关注。单核机器上 load 2 就该看了。

⚠️ **`htop` 的界面差异**：`F5` 树状，`F9` 杀进程，`F2` 设置。`htop` 的 CPU 图形里绿色是正常、红色是 steal time（虚拟化被宿主机抢走的时间）。

## kill / pkill / pgrep — 发信号给进程

```bash
kill [选项]... PID...
killall [选项]... 进程名
pkill [选项]... 模式
pgrep [选项]... 模式
```

| 信号 | 编号 | 含义 | 能否被捕获 |
|---|---|---|---|
| `TERM` | 15 | **优雅退出，默认用这个** | ✅ |
| `KILL` / `9` | 9 | **立即杀死，不给清理机会** | ❌ |
| `INT` | 2 | 中断（同 `Ctrl+C`） | ✅ |
| `HUP` | 1 | 挂断，很多守护进程用它重载配置 | ✅ |
| `QUIT` | 3 | 退出并转储核心 | ✅ |
| `USR1` / `USR2` | 10 / 12 | 用户自定义信号 | ✅ |
| `STOP` / `CONT` | 19 / 18 | 暂停 / 继续 | ❌ / — |

| 选项 | 作用 |
|---|---|
| `-TERM` / `-15` | 优雅退出 |
| `-KILL` / `-9` | 强杀 |
| `-l` | 列出所有信号名 |
| `-0` | **只检查权限和进程存在，不真发信号** |

| pgrep/pkill 选项 | 作用 |
|---|---|
| `-f` | **匹配完整命令行**（不 `-f` 只匹配进程名） |
| `-u 用户` | 匹配用户 |
| `-a` | 列出 PID 和完整命令行（pgrep） |
| `-l` | 列出 PID 和进程名（pkill） |
| `-1` | 匹配 PID 1（**systemd，误杀系统**） |
| `--older N` / `--newer N` | 按启动时间过滤 |

```bash
# 优雅停止，给它时间保存数据
$ kill 1234
$ kill -TERM 1234
$ kill 1234

# 等一会儿还没死再强杀
$ sleep 5 && kill -0 1234 2>/dev/null && kill -KILL 1234

# 查 PID
$ pgrep -a nginx
$ pgrep -u www-data
$ pgrep -f 'python.*worker'

# 按名字杀
$ pkill nginx
$ pkill -f 'python.*worker.py'
$ pkill -u liu

# 只检查存在性和权限（脚本里最常用）
$ if kill -0 1234 2>/dev/null; then echo "在跑"; fi

# 列出所有信号
$ kill -l
```

⚠️ **`kill -9` 是最后手段**。被强杀的进程**没有机会**：关闭文件、flush 缓冲、释放锁、发通知。数据库、Redis 这类会**留下损坏的数据或锁**。正确顺序是 `kill`（TERM）→ 等 → 确认还在 → `kill -9`。

⚠️ **`kill -9 <PID>` 杀不掉僵尸进程**。僵尸已经死了，只是父进程没回收它。**要解决的是父进程**（让它退出，或者给它发 SIGCHLD 处理）。

⚠️ **`kill -9` 杀不掉 D 状态进程**。它卡在不可中断的内核等待里，信号排队等内核返回。**唯一办法是重启或者解决底层 I/O 问题**（比如 NFS 挂载）。

⚠️ **误杀 PID 1 = 系统结束**。`pkill -f ...` 的模式写太宽（比如匹配到 `sshd` 也匹配到 `sshd-keygen`，甚至匹配到执行 kill 的那条命令行本身）就会出事。**养成 `pkill` 之前先 `pgrep -a` 看一遍的习惯。**

⚠️ **系统服务的重启别用 `kill`**，用 `systemctl restart`。手动 kill 掉 systemd 管的进程，systemd 会认为它异常退出并按策略重启或记错误。

⚠️ **`pkill -f` 可能匹配到自己**。`pkill -f 'sh'` 会把运行这条命令的 shell 一起杀掉。

## systemctl — systemd 服务管理

```bash
systemctl [全局选项] 命令 [单元]...
```

**最常用命令**

| 命令 | 作用 |
|---|---|
| `status 单元` | 详细状态（**含最近日志**） |
| `start` / `stop` | 启动 / 停止 |
| `restart` / `reload` / `reload-or-restart` | 重启 / 重载配置 / 优先重载 |
| `enable` / `disable` | 开机自启 / 不自启 |
| **`enable --now 单元`** | **自启 + 立刻启动（最常用组合）** |
| `mask` / `unmask` | **彻底禁止 / 解除禁止** |
| `is-active` / `is-enabled` / `is-failed` | 状态查询（**脚本友好，有退出码**） |
| `list-units` / `list-unit-files` | 列正在跑的 / 列已安装的 |
| `cat 单元` | 看 unit 文件内容（含 drop-in） |
| `show 单元` | 所有属性 |
| `daemon-reload` | **改完 unit 文件后必跑** |
| `reset-failed` | 清除失败标记 |
| `list-jobs` | 进行中的任务 |
| `list-timers` | 定时器 |
| `edit` | 编辑 unit（带 drop-in，自动校验） |
| `set-property` | 运行时改资源限制 |

```bash
# 日常
$ sudo systemctl status nginx
$ sudo systemctl start nginx
$ sudo systemctl restart nginx
$ sudo systemctl reload nginx              # 只重载配置，不断连接
$ sudo systemctl enable --now nginx        # 自启 + 启动

# 查
$ systemctl is-active nginx      # active / inactive / failed（退出码 0/3/4）
$ systemctl is-enabled nginx
$ systemctl list-units --type=service --state=running
$ systemctl list-unit-files | grep enabled

# 排查
$ systemctl status nginx         # ⭐ 出错先看这个，日志直接显示在下面
$ systemctl cat nginx            # 完整 unit 配置，含 drop-in
$ systemctl show nginx -p MemoryMax
$ journalctl -u nginx -n 50      # 只看这个服务的日志

# 改了 unit 文件之后
$ sudo systemctl daemon-reload
$ sudo systemctl restart nginx

# 彻底禁用（连手动启动都不行）
$ sudo systemctl mask nginx
$ systemctl is-enabled nginx     # masked
$ sudo systemctl unmask nginx

# 定时器
$ systemctl list-timers --all
$ systemctl status cron.service
```

⚠️ **`enable` ≠ `active`**，这是 systemctl 最重要的一个区分：

| 命令 | 含义 |
|---|---|
| `enable` | **开机时自动启动**（写一个符号链接） |
| `start` | **现在启动** |
| `disable` | 取消开机自启（**不停止**） |
| `stop` | 现在停止（**不取消自启**） |

`disable` 之后服务仍在跑，下次开机才不启动。**`disable --now` 才是「停掉且不自启」。**

⚠️ **`disable` 和 `mask` 完全不同**：

| | disable | mask |
|---|---|---|
| 开机自启 | ❌ | ❌ |
| **手动 `systemctl start`** | ✅ 仍能启动 | ❌ **完全禁止** |
| 实现 | 删符号链接 | 链接到 `/dev/null` |

⚠️ **`mask` 之后连 `systemctl start` 都会失败**，必须先 `unmask`。**在不需要禁用时不要用 `mask`，用 `disable`。**

⚠️ **改完 `/etc/systemd/system/xxx.service` 必须 `daemon-reload`**，否则 systemd 还用旧的。「我改了配置但没生效」十有八九是漏了这步。

⚠️ **`daemon-reload` 不会重启正在跑的服务**。它只是让 systemd 重新读配置。要生效还得 `restart`。

⚠️ **`reload` 不一定被服务支持**。得看 unit 里有没有 `ExecReload=`。没有的话 `reload` 会报 `Job type reload is not applicable`。**不确定就用 `reload-or-restart`。**

⚠️ **`systemctl status` 显示 `failed` 时，日志就在输出里**，不用再去 `journalctl` 找（除非日志量大）。

⚠️ **socket 激活的服务（24.04 的 OpenSSH 就是）**，直接 `restart` 服务不够，要重启对应的 `.socket` 才能让改了监听参数生效。详见 [08-磁盘网络与时间.md](08-磁盘网络与时间.md)。

⚠️ **服务名不一定等于配置文件名**。`systemctl status sshd` 会报 `Unit sshd.service not found`，因为服务叫 `ssh`。**找不到时用 `systemctl list-unit-files | grep <关键词>` 找真名。**

⚠️ **`systemctl` 的脚本友好性靠 `is-*` 系列和退出码**，不要解析 `status` 的文本输出。

## service / update-rc.d — SysV 兼容层

```bash
service 服务名 命令
update-rc.d 服务名 动作
```

```bash
$ sudo service nginx restart          # 老写法，内部转 systemctl
$ sudo service nginx status
$ sudo update-rc.d nginx defaults     # 设置开机自启
```

⚠️ **`service` 是 SysV 时代的兼容脚本，Ubuntu 上保留只为过渡**。**新写的东西一律用 `systemctl`。** 它会静默把命令翻译成 systemctl 调用，参数和返回值不完全等价。

⚠️ **`service nginx start` 和 `systemctl start nginx` 有个区别**：前者会读 `/etc/init.d/` 下的旧脚本（如果有），可能行为不同。

## journalctl — 查系统日志（systemd 日志）

```bash
journalctl [选项]...
```

| 选项 | 作用 |
|---|---|
| `-f` | **实时跟踪**（等效 `tail -f`） |
| `-u 单元` | **只看某个服务/单元**（最常用） |
| `-b` / `-b -1` | 本次开机 / 上一次开机 |
| `-k` | **内核日志**（等效 `dmesg`） |
| `-p 级别` | 按优先级过滤：`emerg`…`err` `warning` `notice` `info` `debug` |
| `-n N` | 最近的 N 条（默认 10） |
| `--since` / `--until` | 时间范围：`"1 hour ago"` `"2024-08-12 10:00"` `"-30min"` |
| `-e` | 跳到末尾 |
| `-o short-precise` | 时间戳精确到毫秒 |
| `-x` | 展开成完整的 `systemd-cat` 说明（**强烈推荐**） |
| `--disk-usage` | 看占用多少 |
| `--vacuum-size` / `--vacuum-time` | **清理日志** |
| `-q` / `--no-pager` | 安静 / 不分页 |
| `--no-hostname` | 不显示主机名 |

**日志优先级**

```
emerg  <  alert  <  crit  <  err  <  warning  <  notice  <  info  <  debug
严重                                              普通                     最啰嗦
```

```bash
# 实时看某个服务
$ sudo journalctl -u nginx -f
$ sudo journalctl -u cron -f

# 开机以来某个服务的所有日志，带解释
$ sudo journalctl -u nginx -b -x

# 内核日志
$ sudo journalctl -k -f
$ sudo journalctl -k -b -1 -p warning      # 上次开机的内核警告

# 只看错误
$ sudo journalctl -p err -b
$ sudo journalctl -p err --since "1 hour ago"

# 时间范围
$ sudo journalctl --since "2024-08-12 09:00" --until "2024-08-12 18:00"
$ sudo journalctl --since "-2h"

# 磁盘占用和清理（⚠️ 要小心）
$ journalctl --disk-usage
$ sudo journalctl --vacuum-size=500M
$ sudo journalctl --vacuum-time=7d
```

⚠️ **很多服务的日志不在 journal 里**。**老程序（尤其是自己编译的）可能只往文件写**。`journalctl -u xxx` 空不代表服务没日志，先看服务的 unit 里 `StandardOutput=` 指向哪。

⚠️ **日志可能占满磁盘**。默认 `/var/log/journal` 有上限，但没开持久化存储时日志在内存里，重启就没了。生产上要：

```bash
# 确认有持久化存储
$ ls /var/log/journal/       # 有 machine-ID 子目录才对；空说明没持久化
# 建目录启用持久化
$ sudo mkdir -p /var/log/journal
$ sudo systemd-tmpfiles --create --prefix /var/log/journal
$ sudo systemctl restart systemd-journald
```

⚠️ **`--vacuum-*` 会真删日志**，不可恢复。先 `--disk-usage` 看占用，再决定删多少。**别为了腾空间删掉还没排查完的故障现场。**

⚠️ **`-x`（`--catalog`）能把 systemd 的解释一起打出来**，排查时非常有用：`systemd[1]: Started nginx.` 这行会附带「这是启动服务」的解释。

⚠️ **`journalctl -f` 按 `Ctrl+C` 退出**。想保留最近 N 行加 `-n 100 -f`。

⚠️ **默认输出会分页**（用 less）。管道或脚本里加 `--no-pager`。

⚠️ **时区影响时间过滤**。`journalctl` 用系统本地时区，`--utc` 可切。

## dmesg — 内核环形缓冲区

```bash
dmesg [选项]
```

| 选项 | 作用 |
|---|---|
| （无） | 全部打印 |
| **`-T`** | **时间戳转成可读**（否则是开机后秒数，**几乎必加**） |
| `-t` | 只显示时间戳 |
| `-w` | **实时等待新消息** |
| `-H` | 同 `-w` 且人类可读 |
| `-l` / `--level` | 按级别过滤 |
| `-c` | **打印后清空缓冲区**（⚠️ 会丢证据） |
| `-s` / `--since` | 时间过滤 |
| `--since-boot` | 相对开机时间 |

```bash
$ sudo dmesg -T | tail -30
$ sudo dmesg -T -l err,crit,alert,emerg        # 只看严重级别
$ sudo dmesg -w                              # 实时等
$ sudo dmesg -H --level=warning
```

⚠️ **`dmesg` 不加 `-T` 的时间戳是「开机后多少秒」**（如 `[  123.456789]`），没有日期跨天就完全没法读。**永远加 `-T`。**

⚠️ **`dmesg -c` 会清空缓冲区，无法恢复**。**排查故障时绝对不要先跑它**，等于销毁现场。要看「启动以来所有消息」用 `journalctl -k -b`。

⚠️ **部分机器上 `dmesg` 需要 root**（`kernel.dmesg_restrict`）。

⚠️ **环形缓冲区会满**，满了丢最老的。所以启动早期（BIOS、内存检测）的消息可能已经没了。

⚠️ **`dmesg` 里 `[]` 里的数字是时间戳不是错误码**。`(1234)` 括号里才是 PID。

## uname / hostnamectl — 系统标识

```bash
uname [选项]
hostnamectl [选项]
```

| uname 选项 | 作用 |
|---|---|
| `-a` | 全部信息 |
| `-r` | **内核版本**（release） |
| `-m` | 架构（machine） |
| `-n` | 主机名 |
| `-o` | 操作系统名 |
| `-p` | 处理器型号 |
| `-i` | 硬件平台 |
| `-v` | 内核构建版本 |

| hostnamectl 选项 | 作用 |
|---|---|
| （无） | 全部 |
| `set-hostname 名` | 改主机名 |
| `set-chassis 类型` | 改机器类型（`container` `vm` `laptop`…） |
| `--static` / `--transient` | 显示静态/临时主机名 |

```bash
$ uname -a
Linux ubuntu-server 6.8.0-x-generic # SMP ... x86_64 GNU/Linux
$ uname -r                       # 6.8.0-x-generic
$ uname -m                       # x86_64
$ uname -n                       # ubuntu-server

$ hostnamectl
 Static hostname: ubuntu-server
       Icon name: computer-vm
  Operating System: Ubuntu 24.04 LTS
            Kernel: Linux 6.8.0-x-generic
      Architecture: x86-64

$ sudo hostnamectl set-hostname web-01
$ sudo hostnamectl set-chassis vm
```

⚠️ **改完主机名三处要同步**：`/etc/hostname`、`/etc/hosts`（旧名还在的话 sudo 会有警告）、当前 shell 的 `$HOSTNAME`。`hostnamectl` 只管前两个。

⚠️ **云主机（AWS/GCP/Azure）改主机名会被平台重置或不同步**。云上要用平台的 metadata 或者 cloud-init。

⚠️ **Linux 的 `uname` 里的版本串要会读**：`6.8.0-<N>-generic` 里，`6.8.0` 是内核版本，`<N>` 是 Ubuntu 的第 N 次打包，`generic` 是内核 flavor。**`lowlatency` 这种 flavor 是给低延迟场景的，`aws` 是给云优化的。** 具体版本串以你的机器 `uname -r` 的输出为准。

## free / uptime / vmstat — 资源与负载

```bash
free [选项]
uptime
vmstat [选项] [间隔] [次数]
```

### free — 内存

| 选项 | 作用 |
|---|---|
| `-h` | 人类可读 |
| `-m` / `-g` | MB / GB |
| `-s N` | 每 N 秒刷新 |
| `-w` | **只显示 total 和 available**（最清爽） |
| `-c` | 刷新 N 次 |

```bash
$ free -h
               total        used        free      shared  buff/cache   available
Mem:            15Gi       4.2Gi       2.1Gi       120Mi       8.7Gi       10.1Gi
Swap:           2.0Gi          0B       2.0Gi

$ free -w
$ watch -n 2 free -h
```

⚠️ **看 `available` 不看 `free`**。Linux 把空闲内存拿去做页缓存，`free` 低是**特性不是 bug**。`available` 才是「新应用还能拿到多少」。

⚠️ **`Swap: 0B 不代表内存够**。有 swap 说明一旦用满会开始抖动（thrash），性能暴跌。要看 `si`/`so`（`vmstat`）是否有实际换页。

⚠️ **`used` 在不同版本定义不同**。较新版本把 `buff/cache` 算进 `total - available`。以 `available` 为准。

### uptime — 开机多久

```bash
$ uptime
 10:33:12 up 3 days,  4:17,  2 users,  load average: 0.12, 0.34, 0.56
```

⚠️ **load average 的三个数是 1 / 5 / 15 分钟平均**。**要跟 CPU 核数比**：核数 4，load 4 以上才需要关心。

⚠️ **load 高不一定 CPU 忙**。它包含**不可中断睡眠（D 状态）**。load 20 但 CPU 空闲，说明有进程卡在 I/O（磁盘/NFS）。

### vmstat — 采样统计

```bash
$ vmstat              # 开机以来的均值，只输出一行
$ vmstat 2            # 每 2 秒一次
$ vmstat 2 5          # 每 2 秒一次，共 5 次
$ vmstat -S M 1       # 按 MB 显示
$ vmstat -d 1         # 磁盘统计
```

⚠️ **`vmstat` 第一行是开机以来的平均值，没有参考价值**。看第二行开始。

⚠️ **关键三列**：`r`（可运行进程数，等于 load）、`b`（阻塞在 I/O 的进程数）、`si`/`so`（swap in/out）。**`b` 持续大于 0 = 磁盘瓶颈；`si`/`so` 非零 = 在换页，性能问题。**

## lsof / fuser — 谁在用这个文件或端口

```bash
lsof [选项]...
fuser [选项]... 文件/端口
```

| lsof 选项 | 作用 |
|---|---|
| `-i :端口` | **谁占用这个端口** |
| `-i -P -n` | 不解析服务名/主机名（快） |
| `-p PID` | 某进程打开的所有文件 |
| `-u 用户` | 某用户打开的文件 |
| `+D 目录` | 目录下所有被打开的文件 |
| `-t` | 只输出 PID |
| `-n -P` | 不反查 DNS 和服务名（**脚本里必加**） |

| fuser 选项 | 作用 |
|---|---|
| `-v` | 详细 |
| `-k` | **杀掉占用者**（⚠️ 危险） |
| `-n tcp` | 按协议 |

```bash
# 端口被谁占了
$ sudo lsof -i :8080
$ sudo lsof -nP -iTCP:8080 -sTCP:LISTEN

# 谁在用这个文件
$ sudo lsof /var/log/syslog
$ sudo lsof +D /var/www            # 目录下所有被打开的（慢）

# 某进程的打开文件 / 网络连接
$ sudo lsof -p 1234
$ sudo lsof -a -p 1234 -i          # 既看进程又只看网络

# 删了文件空间没释放
$ sudo lsof +L1                    # ⭐ 列出已删除但仍被占用的文件

# 快速看（fuser）
$ sudo fuser -v 8080/tcp
$ sudo fuser -v /var/log/syslog
```

⚠️ **`lsof` 不加 `sudo` 只能看到自己的进程**，输出少得可怜。**几乎总要 `sudo`。**

⚠️ **「删了文件但磁盘没释放」的标准排查就是 `sudo lsof +L1`**。有输出说明文件被进程持有，空间要等进程关闭才回收。

⚠️ **`fuser -k` 会杀掉占用进程，没有确认**。**只在明确知道自己在做什么时用**，最好先用 `fuser -v` 看清楚要杀谁。

⚠️ **`lsof` 在文件描述符多的机器上非常慢**（要读 `/proc`）。进程几万个时用 `ss` 替代看网络部分。

## ss — 网络连接（比 netstat 好）

```bash
ss [选项]... [过滤条件]
```

| 选项 | 作用 |
|---|---|
| `-t` / `-u` | TCP / UDP |
| `-l` | **listen** 状态 |
| `-a` | 全部 |
| `-n` / `-p` | 不解析名字 / 显示进程 |
| `-o` | 显示定时器（`keepalive` `timewait`） |
| `-s` | 摘要 |

```bash
$ ss -tlnp                     # ⭐ 所有 TCP 监听端口 + 进程
$ ss -ulnp                     # UDP
$ ss -tnp state established    # 已建立的连接
$ ss -ant | wc -l              # 连接总数
$ ss -tnp dst 10.0.0.1:443    # 过滤
```

⚠️ **`netstat` 已过时**，很多选项在现代 net-tools 里废弃或默认关闭。**用 `ss`（iproute2 包，自带）。**

⚠️ **`ss` 不加 `-n` 会反查服务名和主机名**，在 DNS 配置有问题时会卡很久。**脚本里永远加 `-n`。**

⚠️ **`ss -p` 需要 root** 才显示别人的进程。


|---|---|

| `-d` | 高亮变化的部分 |

## aa-status — AppArmor 状态

```bash
aa-status
```

| 选项 | 作用 |
|---|---|
| `--enabled` | 只看是否启用（**脚本友好，有退出码**） |
| `--absent` | 列出所有未加载的 profile |
| `--json` | JSON 输出（便于脚本处理） |

## hostname — 老式的改主机名

```bash
hostname [选项]... [名字]
```

| 选项 | 作用 |
|---|---|
| （无） | 显示主机名 |
| `-f` / `-F` | 显示 / 设置完全限定域名（FQDN） |
| `-A` | 列出解析到本机的名字 |
| `-I` | **列出本机所有 IP** |
| `-i` | 列出解析到的主机名 |
| （给名字） | **临时改**（重启失效） |

```bash
$ hostname                    # ubuntu-server
$ hostname -s                 # 短名
$ hostname -f                 # FQDN
$ hostname -A                 # ⭐ 本机对应的所有域名
$ hostname -I                 # ⭐ 本机所有 IP
$ hostname -i                 # 反查本机名

$ sudo hostname newname       # 临时改，重启失效
```

⚠️ **`hostname newname` 改完重启就没了。永久修改用 `sudo hostnamectl set-hostname newname`**（它会同时改 `/etc/hostname` 和运行时 hostname）。

⚠️ **改完主机名 `/etc/hosts` 不会自动更新**。`/etc/hosts` 里旧的 `127.0.1.1 oldname` 还在的话，`sudo` 会报 `unable to resolve host` 警告。**改主机名后手动同步 `/etc/hosts`。**

⚠️ **`hostname -I` 是排查「本机到底有几个 IP」最快的命令**，比 `ip -br addr` 输出更干净。

⚠️ **容器里 `hostname` 是容器 ID 派生的短 ID**，不代表真实主机名。

## reboot / shutdown — 开关机（systemd 方式）

```bash
sudo systemctl reboot
sudo systemctl poweroff
```

| `systemctl` 命令 | 作用 |
|---|---|
| `reboot` | 重启 |
| `poweroff` | 关机 |
| `suspend` / `hibernate` | 挂起 / 休眠 |
| `halt` | **直接断电（不关机，等于拔电源）** |
| `kexec` | 用 kexec 换内核（不重新走固件初始化） |

```bash
$ sudo systemctl reboot
$ sudo systemctl reboot --dry-run   # 看会拉哪些 unit，不真重启
$ sudo systemctl poweroff
$ sudo systemctl kexec              # 热替换内核（更新内核后不用重启）
```

⚠️ **`systemctl poweroff` 比 `shutdown -h now` 干净**：它会走 systemd 的关机流程，让所有服务按依赖顺序正常停止。**直接断电（`halt` 或拔电源）会让文件系统有机会损坏。**

⚠️ **别用 `halt`**，它等于直接停机不关机。**要关机用 `poweroff`。**

⚠️ **`reboot` 前确认没有用户在使用**。`who` 看一下，需要的话先通知。

⚠️ **远程机器重启后 SSH 要等服务完全起来才能连**，直接重连会失败。用 `sleep 30` 或等 ping 通。

⚠️ **`shutdown` 的老语法仍能用**（`shutdown -h now`、`shutdown -r +5 "5分钟后重启"`），但在 systemd 系统上 `systemctl` 更规范。

## ssh / sshd — 远程登录

```bash
ssh [选项]... [用户@]主机 [命令]
```

| ssh 选项 | 作用 |
|---|---|
| `-p 端口` | 端口（**注意是小写 p**） |
| `-i 文件` | **指定私钥** |
| `-l 用户` | 用户名（等价 `用户@`） |
| `-J 跳板` | **通过跳板机（ProxyJump）** |
| `-L` / `-R` / `-D` | 本地 / 远端端口转发 / SOCKS 代理 |
| `-N` | **只转发不开 shell** |
| `-f` | 后台运行（配合 `-N`） |
| `-v` | 详细输出（**连不上时的第一诊断手段**） |
| `-o 选项` | 传配置项（`-o StrictHostKeyChecking=no`） |
| `-A` | 转发 agent |
| `-t` | 分配伪终端（跑需要 tty 的命令） |

| sshd_config 关键项 | 作用 |
|---|---|
| `Port 22` | 端口（**改完要重启 `ssh.socket`**） |
| `PermitRootLogin` | `no`（默认）/ `prohibit-password` / `yes` |
| `PasswordAuthentication` | **生产上建议 `no`**（只用密钥） |
| `PubkeyAuthentication` | 公钥登录（`yes` 才有） |
| `AllowUsers` / `AllowGroups` | **白名单，比黑名单安全** |
| `MaxAuthTries` | 最大认证尝试次数 |

```bash
# 基本
$ ssh liu@192.168.1.10
$ ssh -p 2222 liu@host
$ ssh liu@host 'uptime'                # ⭐ 跑一条命令就退出

# 密钥
$ ssh-keygen -t ed25519 -C "liu@laptop"  # 生成
$ ssh -i ~/.ssh/work_ed25519 liu@host   # 指定私钥
$ ssh-copy-id -i ~/.ssh/id_ed25519.pub liu@host   # 把公钥推上去

# 排错（⭐ 必用）
$ ssh -v liu@host
$ ssh -vvv liu@host           # 连握手细节都打出来

# 跳板机
$ ssh -J user@gw liu@10.0.0.5

# 端口转发
$ ssh -L 8080:localhost:80 user@host    # 本地转发：本地 8080 → 目标机 80
$ ssh -R 9000:localhost:3000 user@host  # 远端转发
$ ssh -N -D 1080 user@host              # SOCKS5 代理（配合浏览器）
```

⚠️ **Ubuntu 上 sshd 的服务名是 `ssh` 不是 `sshd`**。用 `sudo systemctl reload ssh`、`sudo systemctl restart ssh`。**写 `sshd.service` 会报 `Unit sshd.service not found`。**

⚠️ **Ubuntu 22.10 起 sshd 用 socket 激活**（`ssh.socket` + `ssh.service`）。**改完 `sshd_config` 里 `Port` 或 `ListenAddress` 之后，必须**：

```bash
$ sudo systemctl daemon-reload
$ sudo systemctl restart ssh.socket
```

⚠️ **`sshd_config` 改完先验证语法再重载**，语法错误会导致 SSH 完全起不来：

```bash
$ sudo sshd -t             # ⭐ 测试配置
$ sudo sshd -T | grep port # 看最终生效的配置
$ sudo systemctl reload ssh
```

⚠️ **改 SSH 端口前先开新端口再关旧端口**。直接改端口 + 重启 + SSH 连接被拒 = 需要用控制台救。

⚠️ **`PasswordAuthentication no` 之前一定要先确认密钥登录能用**。否则锁死自己的唯一入口。

⚠️ **`ssh -v` 的 `Permission denied (publickey)` 说明网络和端口是通的**，问题在认证阶段（密钥没推、agent 没加载、用户名错）。`Connection refused` 是服务没起，`Connection timed out` 是防火墙。

⚠️ **`~/.ssh` 权限必须是 700，`~/.ssh/id_*` 必须是 600**，否则 ssh 拒绝使用这个私钥（`UNPROTECTED PRIVATE KEY FILE`）。**这是最常见的密钥登录失败原因。**

⚠️ **`~/.ssh/config` 能让连接变简单**：

```
Host prod
    HostName 10.0.0.5
    User liu
    Port 2222
    IdentityFile ~/.ssh/work_ed25519
    ServerAliveInterval 60
```

之后 `ssh prod` 就行。**`ServerAliveInterval` 能避免长连接被 NAT 超时掐断。**

⚠️ **首次连接问 `Are you sure you want to continue connecting` 时看不到主机密钥指纹就别盲敲 yes**，那可能是中间人攻击。**确认指纹后再连。**

## nginx — 服务配置检查与 reload

```bash
nginx [选项]
```

| 选项 | 作用 |
|---|---|
| `-t` / `-T` | **测试配置** / 测试并 dump 全部配置 |
| `-c 文件` | 指定配置文件 |
| `-s 信号` | 发送信号（`stop` `reload` `quit` `reopen`） |
| `-g 指令` | 全局指令 |

```bash
$ sudo nginx -t                       # ⭐ 改完配置必做
nginx: configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful

$ sudo nginx -T 2>/dev/null | less     # ⭐ 看合并后的全部配置（含 include）
$ sudo nginx -s reload                 # 平滑重载（不中断连接）

$ sudo systemctl reload nginx          # 官方推荐，等价且更规范
```

⚠️ **改完配置必须先 `nginx -t`**，语法错误直接 reload 会让 nginx 起不来。**这是 nginx 最重要的习惯。**

⚠️ **`nginx -T`（大写）才能看到被 `include` 的所有片段**，排查「为什么我的配置没生效」就靠它。**`-t` 只测试不输出。**

⚠️ **`systemctl reload nginx` 是平滑重载**（发 HUP 信号，新连接走新配置，老连接继续处理完）。**`restart` 会断掉所有长连接**，生产上优先 reload。

⚠️ **`nginx` 主进程读的是启动时解析的配置**。改完不 reload 不生效。

## docker / podman — 容器速查

```bash
docker [选项] 命令
```

| 命令 | 作用 |
|---|---|
| `ps` / `ps -a` | 运行中 / 全部容器 |
| `images` | 本地镜像 |
| `run -d --name n 镜像 命令` | **后台起容器** |
| `exec -it 容器 sh` | **进容器交互**（容器没起时用） |
| `logs -f 容器` | 跟日志 |
| `stop` / `start` / `restart` | 生命周期 |
| `rm` / `rmi` | 删容器 / 删镜像 |
| `build -t 标签 .` | 构建镜像 |
| `cp 容器:路径 .` | 文件进出容器 |
| `system prune` | **清理无用数据（⚠️ 慎用）** |

```bash
$ sudo systemctl enable --now docker
$ docker ps
$ docker run -d --name web -p 8080:80 nginx
$ docker exec -it web bash
$ docker logs -f web
$ docker cp web:/etc/nginx/nginx.conf ./
$ docker stats                    # 实时资源
$ docker inspect web              # 完整元数据
```

⚠️ **Docker 的存储驱动（overlay2 等）不遵守 fstab 规则**，数据在 `/var/lib/docker`。**磁盘监控要把这个目录算进去**（`docker system df`）。

⚠️ **`docker system prune -a` 会删掉所有停止的容器和未被使用的镜像，不可恢复**。**先 `docker system df` 看清楚。**

⚠️ **容器里的 `systemctl` 基本不能用**（没有 systemd 作为 PID 1）。`docker exec ... systemctl restart nginx` 会失败，**改用 `docker restart` 或 `docker exec ... nginx -s reload`。**

⚠️ **`docker exec` 需要容器在运行**。容器已停止时用 `docker cp` 取文件，`docker start` 后再 exec。

⚠️ **容器内的服务重启不会因 `--restart` 策略而重建**，`--restart` 只在容器退出时生效。

⚠️ **Docker 的 iptables 规则和 nftables 交互复杂**（DOCKER 链），手写 nftables 规则时别把 Docker 的链删了，否则容器网络全断。

## 小结

| 场景 | 命令 |
|---|---|
| 谁在跑、占多少资源 | `ps aux --sort=-%cpu \| head` 或 `htop` |
| 进程树（查父子关系） | `ps -ef --forest` |
| 找 PID | `pgrep -a nginx` |
| 优雅停进程 | `kill PID` → 等 → 确认还在才 `kill -9` |
| 服务状态 + 日志 | `sudo systemctl status nginx` |
| 自启并启动 | `sudo systemctl enable --now nginx` |
| 取消自启并停掉 | `sudo systemctl disable --now nginx` |
| 改完 unit 文件 | `sudo systemctl daemon-reload && sudo systemctl restart xxx` |
| 跟日志 | `sudo journalctl -u nginx -f` |
| 内核日志 | `sudo journalctl -k -b -p warning` |
| 开机以来的错误 | `sudo journalctl -p err -b` |
| 端口被谁占 | `sudo ss -tlnp \| grep :8080` |
| 删了文件没释放空间 | `sudo lsof +L1` |
| 内存真实可用量 | `free -h` 看 `available` |
| 磁盘 I/O 是否是瓶颈 | `vmstat 1 5` 看 `b` 和 `si`/`so` |
| 重启 | `sudo systemctl reboot` |

**十二条铁律**

1. **`kill -9` 是最后手段**，TERM → 等 → 再 KILL。强杀会留下损坏数据和锁。
2. **`kill -9` 杀不掉 D 状态和僵尸进程**，前者要解决 I/O，后者要处理父进程。
3. **`enable` 是开机自启，`active` 是现在在跑**，两码事。`disable` 不停止服务。
4. **`disable` ≠ `mask`**，mask 连手动启动都禁止。
5. **改完 unit 文件必须 `daemon-reload`**，且它不会自动重启服务。
6. **`systemctl status` 出错时日志就在输出里**，先看它再 `journalctl`。
7. **`dmesg` 不加 `-T` 时间戳没法读；`dmesg -c` 会销毁现场**，排查时绝不用。
8. **内存看 `available` 不看 `free`**，free 低是正常的。
9. **load average 要跟核数比**，且高 load 不一定是 CPU 忙（可能是 D 状态）。
10. **`lsof` 几乎总要 `sudo`**，`ss` 脚本里永远加 `-n`。
11. **`ps aux | grep xxx` 会匹配到 grep 自己**，用 `pgrep -a` 或 `grep '[x]xx'`。
12. **`journalctl --vacuum-*` 会真删日志**，删之前确认现场不需要了。
