# 01 · 文件与目录

> 基线 Ubuntu 24.04 / GNU coreutils / GNU findutils。
> `ls` `cp` `rm` 这类命令在 Linux、BSD、macOS 上选项含义**不完全一致**，本手册以 GNU 版为准，差异处会标出。

---

## ls — 列目录内容

最常用的命令。没有它你什么都看不见。

```
ls [选项]... [文件]...
```

| 选项 | 作用 | 记忆点 |
|---|---|---|
| `-l` | 长格式 | 第一列是权限位，见下 |
| `-h` | 人类可读大小 | **永远和 `-l` 一起用** |
| `-a` | 含隐藏文件（`.` 开头） | 不加只显示非隐藏 |
| `-A` | 含隐藏但不含 `.` 和 `..` | 比 `-a` 干净 |
| `-t` | 按修改时间排序 | 最新在最后 |
| `-S` | 按文件大小排序 | 最大的在最后 |
| `-r` | 逆序（配合 `t`/`S`） | 最大的在最前 |
| `-R` | 递归子目录 | `-r` 是逆序，**大小写含义完全不同** |
| `-1` | 每行一个（给管道用） | 脚本里解析文件列表用这个 |
| `-d` | 只显示目录本身 | `ls -d dir/*` 不展开内容 |
| `-i` | 显示 inode 号 | 排查硬链接 |

```bash
# 最常用组合
$ ls -lh /etc

# 按时间倒序，看最近动了什么
$ ls -lht

# 连隐藏文件一起，包含 . 和 ..
$ ls -a

# 只列出目录名本身，不进内容
$ ls -d /var/log/*

# 递归整棵树
$ ls -R ~/project
```

**`-l` 第一列怎么读**

```
-rw-r--r--   1 root root  4.2K Aug 12 10:33 notes.txt
│└┬┘└┬┘└┬┘   │  │     │     │        │        └── 文件名
│ │  │  │     │  │     │     │        └─── 修改时间
│ │  │  │     │  │     │     └──────────── 字节大小
│ │  │  │     │  │     └────────────────── 属组
│ │  │  │     │  └──────────────────────── 属主
│ │  │  │     └─────────────────────────── 硬链接数
│ │  │  └───────────────────────────────── 其他人权限
│ │  └──────────────────────────────────── 属组权限
│ └─────────────────────────────────────── 属主权限
└───────────────────────────────────────── 文件类型
```

第一个字符是类型：`-` 普通文件、`d` 目录、`l` 符号链接、`c` 字符设备、`b` 块设备、`s` socket、`p` 命名管道。

⚠️ **`ls -r` 和 `ls -R` 完全无关**。`-r` 是 reverse（排序反过来），`-R` 是 recursive（递归）。新手最常混的一对。

⚠️ **脚本里不要用 `ls` 拿文件名**。`ls` 的输出是给人看的，列文件名带空格、换行或特殊字符时会崩，而且会触发别名。要处理文件用 glob 或 `find`：

```bash
# 别这样
for f in $(ls *.txt); do ... done      # 文件名带空格就废了

# 这样
for f in *.txt; do ... done            # glob 由 shell 处理
shopt -s nullglob                     # 没匹配时为空而不是字面量 *.txt
```

⚠️ 输出重定向到文件时不要用 `ls -l`，格式会散。

## cd — 切换目录

```bash
cd [目录]
```

| 写法 | 作用 |
|---|---|
| `cd /var/log` | 进绝对路径 |
| `cd ../..` | 上两级 |
| `cd -` | **回到上一个目录**，再次执行又跳回去 |
| `cd ~` | 回 home（默认就是，不带参数也行） |
| `cd` | 不带参数 = `cd ~` |

```bash
$ cd /etc/apt
$ cd -          # 回到刚才的目录
/root
$ cd -
/etc/apt
```

`cd -` 靠环境变量 `OLDPWD`，只有交互式 shell 才有。**脚本里 `cd -` 无意义**。

⚠️ `cd` 是 shell 内建命令，不是 `/bin/cd`，所以没有 `which cd`。用 `type cd` 能看到 `cd is a shell builtin`。

⚠️ **脚本里 `cd` 不会改变调用者的目录**。必须用子 shell 或 `cd "$(dirname "$0")"` 配合：

```bash
cd "$(dirname "$0")" || exit 1
```

## pwd — 显示当前目录

```bash
pwd [-LP]
```

| 选项 | 作用 |
|---|---|
| （无） | 打印**逻辑**路径，即你 `cd` 时给的路径，可能含符号链接 |
| `-P` | 打印**物理**路径，符号链接全部解析 |

```bash
$ cd /tmp && ln -sfn /var/log link
$ pwd
/tmp
$ pwd -P
/var/log
```

⚠️ 排查「为什么我删了文件还在」这类问题时用 `pwd -P`，逻辑路径会骗你。

## mkdir — 创建目录

```bash
mkdir [选项]... 目录...
```

| 选项 | 作用 |
|---|---|
| `-p` | **父目录不存在则一并创建**，已存在不报错 |
| `-m` | 指定权限模式，如 `mkdir -m 700 priv` |

```bash
# 递归建树，-p 最常用
$ mkdir -p project/src/{api,web}

# 指定权限
$ mkdir -m 750 /srv/private
```

⚠️ **`mkdir -p` 的一个副作用要记住**：如果中间某层已存在且不是目录，`-p` 会静默跳过，最终权限/属主不会按你预期设。建重要目录后用 `ls -ld` 确认一遍。

⚠️ 默认权限受 `umask` 影响。`mkdir` 不带 `-m` 时实际是 `777 & ~umask`。

## rmdir — 删除空目录

```bash
rmdir [选项]... 目录...
```

| 选项 | 作用 |
|---|---|
| `-p` | 连同空的父目录一起删 |
| `--ignore-fail-on-non-empty` | 目录非空时不报错 |

```bash
$ rmdir a/b/c          # 只能删空的
$ rmdir -p a/b/c       # 删完 c 再删 b、a（遇到非空就停）
```

⚠️ **只会删空目录**，这是它比 `rm -r` 安全的地方。非空时报 `Directory not empty` 而不是像 `rm` 那样直接连带内容。

⚠️ 但它**没有 `-r` 也照样是删东西**。养成在前面加 `--` 的习惯：`rmdir -- "$dir"`，防止目录名以 `-` 开头被当选项。

## touch — 创建空文件 / 更新时间戳

```bash
touch [选项]... 文件...
```

| 选项 | 作用 |
|---|---|
| `-a` | 只改访问时间（atime） |
| `-m` | 只改修改时间（mtime） |
| `-c` | 文件不存在时**不创建** |
| `-d` / `-t` | 指定时间，如 `-d "2 days ago"` |
| `-r` | 用参考文件的时间戳 |

```bash
$ touch notes.txt                    # 建空文件
$ touch -c /etc/passwd               # 只更新时间戳，不创建（用在检查权限时）
$ touch -d "2024-01-15 10:00" old.log
$ touch -r reference.txt target.txt  # 复制时间戳
```

⚠️ `touch` **不会清空文件**。很多人以为 `touch file` 是「创建新文件」，结果文件已存在时它只更新时间戳，**内容原封不动**。想清空用 `: > file` 或 `truncate -s 0 file`。

## cp — 复制

```bash
cp [选项]... 源 目标
```

| 选项 | 作用 | 关键区别 |
|---|---|---|
| `-r` | 递归复制目录 | 保留原权限，不保留时间戳 |
| `-a` | 归档模式 = `-pR` | **保留权限/属主/时间戳/符号链接** |
| `-p` | 保留模式属主时间戳 | |
| `-i` | 覆盖前询问 | **交互时用**，脚本里别用 |
| `-n` | 不覆盖已存在的 | |
| `-u` | 只更新较新的 | 增量同步的雏形 |
| `-v` | 显示过程 | |
| `-l` | 硬链接而非拷贝 | 同文件系统才行 |

```bash
$ cp file.txt backup.txt

# 递归并完整保留属性：备份首选
$ cp -a project/ project-backup/

# 只复制一层，不含目录
$ cp *.txt /tmp/

# 目标已存在时，src 是目录就会塞进 src/ 里面 —— 这是经典坑
$ cp -r a b          # 若 b 存在，结果是 b/a
$ cp -r a/. b/       # 明确把 a 的内容放进 b
```

⚠️ **末尾斜杠陷阱**：`cp -r src/ dst` 和 `cp -r src dst` 行为不同。`src/` 表示「src 的内容」，`src` 表示「src 这东西」。

⚠️ **GNU `cp` 覆盖已存在文件默认不提示**（BSD 和 macOS 的 `cp` 也一样，但 `cp -i` 习惯要写）。`cp -r` 覆盖目录时可能把新文件混进旧目录，不报错。重要数据用 `cp -a` 备份，或用 `rsync -a`（见 [04](04-压缩备份与同步.md)）。

⚠️ 跨文件系统复制大文件会报错或很慢（`Invalid cross-device link`）。用 `cp` 复制到别的挂载点没问题，但 `ln` 硬链接会失败。

## mv — 移动 / 改名

```bash
mv [选项]... 源 目标
```

| 选项 | 作用 |
|---|---|
| `-i` | 覆盖前询问 |
| `-n` | 不覆盖 |
| `-u` | 只在源较新时才动 |
| `-v` | 显示过程 |

```bash
$ mv old.txt new.txt              # 改名
$ mv file.txt /tmp/              # 移动
$ mv -t /dest/ a.txt b.txt c.txt # 多文件直接进目录，不用重复写目录名
```

⚠️ **同文件系统内 `mv` 只改目录项，秒完成；跨文件系统 = 复制 + 删除**。所以跨盘 `mv` 一个大文件可能很慢，且中途断电会留下半份数据。这种场景先用 `cp` 再手工确认，最后才 `rm`。

⚠️ 目标存在时，`mv a b` 中若 `b` 是目录，会变成 `b/a`。

## rm — 删除

⚠️⚠️⚠️ **本手册里唯一一个没有撤销的操作。** 下面是能减少损失的做法，不是在劝你少删。

```bash
rm [选项]... 文件...
```

| 选项 | 作用 |
|---|---|
| `-r` / `-R` | 递归 |
| `-f` | 强制，不询问不报错 ⚠️ |
| `-i` | 每个文件都问 |
| `-I` | 删超过 3 个文件才问一次（GNU） |
| `-d` | 删空目录 |
| `--one-file-system` | 递归时不跨越其他挂载点 |
| `-v` | 显示过程 |

```bash
$ rm notes.txt
$ rm -r old-project/
$ rm -rf /tmp/scratch/            # 最常见的组合

# 递归时限制在同一文件系统内
$ rm -rf --one-file-system /var/data/
```

⚠️ **`rm -rf` 没有 `-i`，也没有回收站**。删错就是删了。

⚠️ **必须加 `--`**。目录名以 `-` 开头时会被当选项：

```bash
$ rm -rf -weird-dir/        # 灾难
$ rm -rf -- -weird-dir/     # 正确
```

⚠️ **变量永远加引号**：

```bash
$ rm -rf "$DIR"/            # 对
$ rm -rf $DIR/              # DIR 为空时变成 rm -rf /
```

⚠️ **`rm -rf /`** 在 GNU coreutils 里其实有保护（`--preserve-root` 默认开启，会拒绝），但**变体很多**：`sudo rm -rf /var/lib/*`、`rm -rf ~/*`、递归删除挂载点，都不会有任何保护。

⚠️ **删除前先看**：

```bash
$ ls -ld -- "$DIR"          # 确认路径
$ du -sh -- "$DIR"          # 确认大小和范围
$ find "$DIR" -maxdepth 1    # 确认里面有什么
```

想有后悔药用 `trash-put`（见本文件末尾）。

⚠️ `rm -rf` 删掉的**符号链接只删链接不删目标**。这个行为是对的，别误以为删链接就删了数据。

## ln — 硬链接 / 符号链接

```bash
ln [选项]... 目标 链接名
ln -s [选项]... 目标 链接名
```

| 选项 | 作用 |
|---|---|
| 无 | **硬链接** |
| `-s` | 符号链接（软链接） |
| `-f` | 强制覆盖已存在的链接文件 |
| `-n` | 把指向目录的链接当普通文件，配合 `-f` |
| `-r` | 创建相对路径的符号链接 |
| `-v` | 显示过程 |

```bash
# 硬链接：同一个 inode
$ ln data.txt data.hardlink
$ ls -i data.txt data.hardlink
12345 data.txt      # inode 号相同
12345 data.hardlink

# 符号链接：存的是路径
$ ln -s /var/log/syslog ~/syslog.link
$ ls -l ~/syslog.link
lrwxrwxrwx ... /var/log/syslog -> /var/log/syslog
```

| | 硬链接 | 符号链接 |
|---|---|---|
| 本质 | inode 的另一个名字 | 一个存路径的独立文件 |
| 跨文件系统 | ❌ 不能 | ✅ 能 |
| 指向目录 | ❌ 不能 | ✅ 能 |
| 目标删除后 | 数据仍在（还有这个入口） | **变成断链** |
| 目标在别处 | 看起来是普通文件 | `ls -l` 显示 `->` |

⚠️ **`ln` 默认是硬链接**，不是符号链接。新手几乎每次都以为是软链接，结果踩坑。**默认写 `ln -s`**。

⚠️ **硬链接不增加占用**，`du` 看起来还是一份。排查「空间没释放」时要知道这点。

⚠️ `ln -s` 链接到目录时，`cd link` 会进去；但 `rm link` 只删链接。删链接删目录要用 `rm -r`。

## file — 判断文件类型

```bash
file [选项]... 文件...
```

| 选项 | 作用 |
|---|---|
| `-i` | 看 MIME 类型（`text/plain; charset=utf-8`） |
| `-b` | 不显示文件名 |
| `-L` | 跟随符号链接看真实内容 |
| `-s` | 看符号链接本身指向哪 |

```bash
$ file notes.txt
notes.txt: text/plain; charset=utf-8

$ file -i notes.txt
notes.txt: text/plain; charset=utf-8

$ file ./myprogram
./myprogram: ELF 64-bit LSB executable, x86-64, dynamically linked, ...

$ file link
link: symbolic link to notes.txt
```

⚠️ **扩展名不决定类型**。`x.txt` 可能是 ELF 二进制，`x.sh` 可能不是脚本。脚本要能执行靠**首行 shebang** + 执行权限，不是靠后缀：

```bash
$ file x.sh          # 实际是 ELF
$ head -1 x.sh       # 看真正的解释器
```

⚠️ `file` 靠 magic number 判断，**文本文件伪装不出差别**。要确认中文编码用 `file -i` 或 `iconv`。

## stat — 文件元数据详情

```bash
stat [选项]... 文件...
```

| 选项 | 作用 |
|---|---|
| `-c` | 自定义输出格式，如 `-c '%a %U %G %n'` |
| `-f` | 看文件系统状态 |
| `-L` | 跟随符号链接 |

```bash
$ stat notes.txt
  File: notes.txt
  Size: 4298          Blocks: 8     IO Block: 4096   regular file
Device: 259,3     Inode: 12345    Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/  liu)   Gid: ( 1000/  liu)
Access: 2024-08-12 10:33:00.000000000 +0800
Modify: 2024-08-12 10:33:00.000000000 +0800
Change: 2024-08-12 10:33:00.000000000 +0800
 Birth: 2024-08-12 10:33:00.000000000 +0800
```

脚本里取单个字段用 `-c`：

```bash
$ stat -c '%a' notes.txt        # 八进制权限 644
$ stat -c '%U' notes.txt        # 属主
$ stat -c '%s' notes.txt        # 字节数
$ stat -c '%Y' notes.txt        # mtime 的 Unix 时间戳
$ stat -c '%i' notes.txt        # inode
```

⚠️ `Access`（atime）、`Modify`（mtime）、`Change`（ctime）三者含义不同，`Change` 不是「创建时间」。创建时间是 `Birth`。

⚠️ `%` 本身要用 `%%`。写脚本时权限字符串里常带 `%`，容易漏。

## du / df — 谁占了空间

```bash
du [选项]... [文件]...
df [选项]... [文件]...
```

**du 查目录占用，df 查文件系统剩余。两回事。**

### du — 目录占了多少

| 选项 | 作用 |
|---|---|
| `-h` | 人类可读 |
| `-s` | 只出总数（**汇总必加**） |
| `-d N` | 深度限制，`-d 1` 只看一层 |
| `--max-depth=1` | `-d 1` 的长写法 |
| `-a` | 文件也算（默认只算目录） |
| `-x` | 不跨越其他文件系统 |
| `-c` | 最后加总计 |
| `--apparent-size` | 按文件逻辑大小算，不按占用块 |

```bash
# 找出空间黑洞：当前目录每一层各占多少，按大小排
$ du -hd 1 . | sort -h

# 最大的 10 个子目录
$ du -h --max-depth=1 . | sort -rh | head -11

# 系统整体哪里满了
$ du -xh / --max-depth=1 | sort -h
```

⚠️ **`du -sh *` 遇到权限不足会打印一堆 `Permission denied` 到 stderr**。加 `-x` 限制在同一文件系统能减少噪音，`2>/dev/null` 藏错误。

⚠️ **别对 `/` 直接跑 `du -h /`**。会顺着 `/proc`、`/sys` 爬几十分钟。用 `-x` 限制住。

⚠️ **`du` 报的数比 `ls` 大**是正常的：占用按**块**算（4K 一块），1 字节文件也占 4K。想按逻辑大小看用 `--apparent-size`。

⚠️ **删了文件空间没释放**：常见原因是文件被进程持有，`lsof +L1` 能查到。硬链接不重复计数，也会让数字看着偏小。

### df — 文件系统剩余

| 选项 | 作用 |
|---|---|
| `-h` | 人类可读 |
| `-T` | 显示文件系统类型（ext4/tmpfs/btrfs） |
| `-i` | **显示 inode 使用率** |
| `-x` | 不跨越其他文件系统 |

```bash
$ df -hT
Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/sda2      ext4   20G  8.1G   11G  43% /
tmpfs          tmpfs  1.6G     0  1.6G   0% /run

$ df -h /var/log          # 只看某个挂载点
```

⚠️ **`Use%` 到 90% 以上要处理**，ext4 保留 5% 给 root，普通用户会先遇到 `No space left on device`。

⚠️ **`df -h` 和 `du -sh` 对不上**，原因有两个：删了但进程仍持有（用 `lsof +L1` 查），或该文件系统上有已删除但仍被引用的文件。

⚠️ **`-i` 比 `-h` 更早爆**。小文件多的场景（缓存、日志、inode 密集）会出现 `df -h` 显示还有空间，但报 `No space left on device`——那是 inode 用光了。`df -i` 能看出来。

⚠️ 临时文件（`/tmp`、`/var/tmp`）常在 tmpfs 上，**占的是内存**。`df -h /tmp` 的 Size 就是你的可用内存的一部分。

## find — 按条件找文件

Linux 上最强大也最容易写错的命令。

```bash
find [路径...] [表达式]
```

**表达式按顺序求值，从左到右。** `-a`（and）、`-o`（or）、`!`（not）优先级要小心。

| 表达式 | 作用 |
|---|---|
| `-name 模式` | 名称匹配（区分大小写） |
| `-iname 模式` | 名称匹配（**忽略大小写**） |
| `-path 模式` | 匹配完整路径 |
| `-type f/d/l` | 类型：普通文件 / 目录 / 符号链接 |
| `-size [+|-]<n><单位>` | `+100M` 大于 100M，`-1k` 小于 1K |
| `-mtime <n>` | 修改时间，**`+n` 是 n 天前，`-n` 是 n 天内** |
| `-mmin <n>` | 同上但单位分钟 |
| `-newer 文件` | 比某文件新 |
| `-user` / `-group` | 属主 / 属组 |
| `-perm 模式` | 权限 |
| `-maxdepth N` / `-mindepth N` | **递归深度限制，必加** |
| `-exec ... {} +` | 对结果执行命令 |
| `-print` / `-print0` | 输出（`-print0` 配合 `xargs -0`） |

```bash
# 当前目录下所有 .log（不递归进子目录）
$ find . -maxdepth 1 -name '*.log'

# 7 天内改过的文件
$ find /var/log -type f -mtime -7

# 大于 100M 的文件
$ find / -xdev -type f -size +100M 2>/dev/null

# 找出属于 liu 的、且 30 天没动过的
$ find /home -user liu -type f -mtime +30

# 匹配时忽略大小写
$ find . -iname 'readme*'

# 处理文件名带空格：用 -print0 + xargs -0
$ find . -name '*.txt' -print0 | xargs -0 wc -l

# 批量删除，先 -print 看清楚
$ find . -name '*.tmp' -print
$ find . -name '*.tmp' -delete
```

⚠️ **`-mtime` 的正负号和直觉相反**。`-mtime +7` 是**7 天前**改的（更旧），`-mtime -7` 是**7 天内**改的（更新）。这里 GNU 和 BSD 语义一致，但和「+ 表示更多」的字面直觉冲突，是踩坑重灾区。记法：`+` = 超标（超过 7 天），`-` = 不足（不到 7 天）。

⚠️ **`find /` 一定要加 `-xdev`**，否则会爬进 `/proc`、`/sys`、其他挂载的网络盘，可能跑到没结果也停不下来。

⚠️ **必须写 `-maxdepth`**，否则递归深度不可控。

⚠️ **`-name '*.log'` 的引号不能省**。不加引号时 shell 先把 `*` 展开成当前目录的文件名，`find` 收到的是一堆文件名而不是模式。这是最常见的 `find` 失效原因。

⚠️ **`-exec ... {} \;` 里的 `;` 要转义或加引号**，因为 shell 会吃掉它。`{}` 也要用 `\;` 或空格隔开。批量处理**优先用 `{} +`**（快得多）或 `-delete`，别一个一个 `-exec`。

⚠️ `-delete` **不可恢复**，执行前一定先 `-print` 确认。

## xargs — 把输入变成命令行参数

```bash
xargs [选项]... [命令]
```

| 选项 | 作用 |
|---|---|
| `-0` | **输入以 NUL 分隔**（配合 `find -print0`） |
| `-n N` | 每次最多传 N 个参数 |
| `-L N` | 每次最多读 N 行 |
| `-I 串` | **用 `-I` 指定的串替换每个输入行**（占位符） |
| `-P N` | **并行跑 N 个进程** |
| `-r` / `--no-run-if-empty` | **输入为空时不执行命令** |
| `-t` | 执行前打印命令 |
| `-a 文件` | 从文件读而不是 stdin |
| `-d 分隔符` | 自定义分隔符 |
| `-E 串` | `-I` 的结束标记 |
| `--show-limits` | 看命令行长度限制 |

```bash
# 基本：把 find 的结果传给 rm
$ find . -name '*.tmp' -print0 | xargs -0 rm -f

# ⭐ 逐个处理（文件名带空格也安全）
$ find . -name '*.txt' -print0 | xargs -0 -I{} cp {} /backup/

# 并行加速
$ cat urls.txt | xargs -P 8 -n 1 curl -sS -O

# 空输入不执行（⭐ 脚本必备）
$ cat maybe_empty.txt | xargs -r rm -f

# 交互确认
$ find . -name '*.log' -print0 | xargs -0 -p rm -f

# 看会执行什么（先 -t 干跑）
$ find . -name '*.tmp' -print0 | xargs -0 -t rm -f
```

⚠️ **`find ... | xargs rm` 在文件名带空格时会拆错**，一个文件变成两个参数，可能删掉不相干的东西。**永远用 `-print0 | xargs -0`。**

⚠️ **`xargs -I{}` 一次只传一个参数**，`-n` 和 `-L` 在有 `-I` 时会被忽略。批量同名操作时 `-I` 反而更慢。

⚠️ **`xargs rm` 会删掉传入的所有东西**，管道源写错就是灾难。**先用 `-t` 看它到底要执行什么。**

⚠️ **`find` 里加 `-exec rm {} \;` 也能删，但一个文件 fork 一次，几十万个文件会非常慢**。`-delete` 或 `xargs -0` 快得多。

⚠️ **GNU `xargs` 默认在命令行超长时会自动分批**（BSD 上默认会直接报错），但 `xargs` 不理解引号和转义，**复杂文件名请用 `-0`**。

⚠️ **`xargs -I{}` 里的替换是纯文本替换**，`{}` 出现在命令的任意位置都会被替换，路径拼接时要小心。

⚠️ **能用 shell 内建重定向（`while read` + `< file`）就不要用 `xargs`**，少一个进程、语义更清楚。

## locate / updatedb — 数据库快速查找

```bash
locate [选项]... 模式
updatedb
```

| 选项 | 作用 |
|---|---|
| `-i` | 忽略大小写 |
| `-b` | 只匹配文件名部分 |
| `-e` | 只匹配存在的文件 |

## realpath / readlink — 解析路径

```bash
realpath [选项]... 文件...
readlink [选项]... 文件...
```

| 命令 | 选项 | 作用 |
|---|---|---|
| `readlink` | 无 | 只输出链接目标路径 |
| `readlink` | `-f` | 规范化整个路径并解析全部链接 |
| `readlink` | `-e` | 要求路径每一段都存在 |
| `realpath` | 无 | 输出解析后的绝对路径 |
| `realpath` | `-e` | 全部段必须存在 |
| `realpath` | `-m` | 允许不存在的部分 |

```bash
$ readlink /usr/bin/vi
/etc/alternatives/vi

$ readlink -f /usr/bin/vi
/usr/bin/vim.basic

$ realpath ~/notes.txt
/home/liu/notes.txt

$ realpath -e ./nonexistent/../file
# 不报错，静默退出 1
```

⚠️ **拿脚本所在目录**用这个组合：

```bash
DIR="$(cd "$(dirname "$(readlink -f "$0")")" && pwd)"
```

⚠️ `readlink` **只能解一层**，加 `-f` 才解到底。嵌套符号链接场景不加 `-f` 会拿到中间层。

## tree — 树状列出目录

```bash
tree [选项]... [目录]
```

| 选项 | 作用 |
|---|---|
| `-L N` | 限制深度 |
| `-d` | 只显示目录 |
| `-a` | 含隐藏文件 |
| `-h` | 人类可读大小 |
| `--dirsfirst` | 目录排在文件前面 |
| `-f` | 显示完整路径 |
| `-I 模式` | 排除匹配的目录 |
| `-C` | 彩色输出 |

```bash
$ tree -L 2 -h ~/project
$ tree -d /var/log
$ tree -a -I '.git|node_modules|__pycache__'
$ tree --dirsfirst -L 1 /usr/local
```

⚠️ **`tree` 不是系统自带的**，先装：`sudo apt install tree`。

⚠️ 目录很深时 `tree` 会比 `du` 慢，因为它要遍历全部。文件极多的目录加 `-L`。

⚠️ `tree -f`（完整路径）常被误认为 `-F`（类似 `ls` 的加 `/`）。注意大小写。

## trash-put — 移到回收站

```bash
trash-put 文件...
trash-list
trash-restore
trash-empty
```

```bash
$ trash-put old-report.pdf      # 可恢复
$ trash-list                     # 看回收站
$ trash-restore                   # 交互式挑回
$ trash-empty                    # 永久清空
```

⚠️ 这是给「想有后悔药」的场景准备的。它把文件存进 `~/.local/share/Trash`，遵循 freedesktop.org 规范，桌面环境也认这套。

⚠️ **`trash-put` 处理不了系统目录**，也不是所有脚本都认它。要批量清理还是用 `rm`。

## install — 一次完成建目录+复制+改权限

```bash
install [选项]... 源... 目标
```

| 选项 | 作用 |
|---|---|
| `-d` | **只创建目录**（等价 `mkdir -p` 加权限） |
| `-m` | 权限模式 |
| `-o` / `-g` | 属主 / 属组 |
| `-D` | 目标不存在时把源当普通文件复制过去 |

```bash
# 建目录并一次性设好权限和属主
$ sudo install -d -o myapp -g myapp -m 0750 /var/lib/myapp

# 装文件进系统目录，一步到位
$ sudo install -m 0755 script.sh /usr/local/bin/
```

⚠️ **`install` 在 `coreutils` 里，不是 `install(1)` 的 BSD 语义**。`install -d` 的权限处理和 `mkdir -m` 不同 —— `mkdir -m` 受 umask 影响，`install -d` **不受**。要精确权限就用 `install`。

⚠️ 装到 `/usr/local/bin/` 记得 `sudo`，否则 `Permission denied`。

## 小结

| 场景 | 命令 |
|---|---|
| 看目录 | `ls -lh` / `tree -L 2` |
| 看文件类型 | `file -i` |
| 看权限属主 | `ls -l` / `stat -c '%a %U %G'` |
| 找文件 | `find . -name '*.log' -print` |
| 找大文件 | `find / -xdev -type f -size +100M` |
| 找占空间 | `du -hd 1 . \| sort -h` |
| 看剩余空间 | `df -hT` / `df -i`（inode） |
| 安全删除 | `rm -r --` 或 `trash-put` |
| 完整备份 | `cp -a` / `rsync -a` |

**四条贯穿全本的规矩**

1. 路径和变量**永远加引号**：`"$DIR"`，不要 `$DIR`。
2. 删除类命令**永远加 `--`**：`rm -rf -- "$DIR"`。
3. 用 `find` 定位，用 `ls` 给人看。**脚本里别解析 `ls` 输出。**
4. 删之前先 `ls -ld -- "$DIR"` 看一眼。
