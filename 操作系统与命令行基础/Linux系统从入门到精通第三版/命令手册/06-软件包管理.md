# 06 · 软件包管理

Ubuntu 的软件来源是 **APT**（前端）+ **dpkg**（底层）。分清两者是本章的核心。

| 层 | 命令 | 特点 |
|---|---|---|
| 高层前端 | `apt` / `apt-get` / `apt-cache` / `apt-mark` | 能解依赖、联网 |
| 底层 | `dpkg` / `dpkg-query` / `dpkg-divert` | 只管本地 `.deb`，**不联网、不解依赖** |

⚠️ **新手最常见的错误：用 `dpkg -i` 装依赖多的软件，然后抱怨「装不上」。**
`dpkg -i` 不会去下载依赖，只会把包装上并标记为「未正确配置」。补救要靠 `apt -f install`。

## apt / apt-get — 装卸查、源状态、依赖关系

```bash
apt [选项] 命令
apt-get [选项] 命令
```

| 选项 | 作用 |
|---|---|
| `-y` | 所有确认都自动 yes（**脚本里用，人别用**） |
| `-s` / `--simulate` | **演练，不真做** |
| `-u` / `--dry-run` | 同上（`-s` 的别名） |
| `-f` / `--fix-broken` | **修复依赖问题** |
| `-q` / `--quiet` | 安静 |
| `-t` / `--target-release` | 指定发布版（如 `-t jammy-backports`） |
| `-V` / `--verbose-versions` | 显示完整版本号 |
| `--reinstall` | 重装 |
| `--allow-downgrades` | 允许降级 |
| `--no-install-recommends` | **不装推荐包**（精简系统的关键） |
| `--allow-unauthenticated` | 允许未认证包（⚠️ 危险） |
| `--install-suggests` | 强制连建议包一起装（极少用） |

**`apt` 和 `apt-get` 选哪个**

| | `apt` | `apt-get` |
|---|---|---|
| 输出稳定 | 不稳定（版本间会变） | **稳定**，脚本友好 |
| 有 `search` / `list` | ✅ | ❌（用 `apt-cache`） |
| 有 `show` / `policy` | ✅ | ❌ |
| 提示信息 | 彩色、带 `WARNING` | 朴素 |
| 适合 | **交互式手动操作** | **脚本** |

```bash
# ---- 装 ----
$ sudo apt update                       # 先更新索引，不 update 会装到旧版
$ sudo apt install nginx                # 装
$ sudo apt install nginx redis-server   # 一次装多个
$ sudo apt install -y nginx             # 自动确认
$ sudo apt install --reinstall nginx    # 重装
$ sudo apt install --no-install-recommends nginx   # 不带推荐包
$ sudo apt install ./local.deb          # 装本地 deb（仍会解依赖）

# ---- 卸 ----
$ sudo apt remove nginx                 # 删程序，留配置
$ sudo apt purge nginx                  # 删程序 + 配置（更干净）
$ sudo apt autoremove                   # 删不再需要的依赖
$ sudo apt autoremove --dry-run         # 先看会删什么
$ sudo apt clean                        # 清 apt 缓存的 .deb
$ sudo apt autoclean                    # 只清已过期版本的

# ---- 查 ----
$ apt policy                            # ⭐ 源优先级一览（排查装哪个版本）
$ apt policy nginx                      # 某个包在各个源的优先级和版本
$ apt list --installed | grep nginx    # 已装
$ apt list --upgradable                 # 有什么可升级
$ apt list --all-versions nginx
$ apt list 'nginx*'                     # 通配符
$ apt search nginx                      # 搜（只有 apt 有）
$ apt show nginx                        # 看详细信息（只有 apt 有）
$ apt --names-only search 'log rotate'
$ apt depends nginx                     # 依赖树（正向依赖）
$ apt rdepends nginx                    # 反向依赖（谁依赖它）

# ---- 升级 ----
$ sudo apt upgrade                      # 只升级已有包，不装新的
$ sudo apt full-upgrade                 # 会装新包/删不兼容的包（dist-upgrade 的新名字）
$ sudo apt dist-upgrade                 # 旧名，仍能用

# ---- 修复 ----
$ sudo apt -f install                   # 依赖坏了用这个

# ---- 演练（改之前先看）----
$ sudo apt -s purge nginx               # 只打印不执行
$ sudo apt -s autoremove
```

⚠️ **不 `apt update` 就 `install` 会装到旧版**。这是最常见的"明明源里有却装不上新版本"。

⚠️ **`apt remove` 留配置，`apt purge` 连配置一起删**。改完配置想干净重来用 `purge`。**配置在 `/etc` 下，改了之后 purge 又装，配置会恢复默认** —— 这有时正是你想要的。

⚠️ **`autoremove` 会删掉「看起来没包依赖」的包**。如果你手动装了某个包然后又有别的包装它，它可能变成孤儿。**`autoremove` 前一定先 `--dry-run`。**

⚠️ **`apt policy` 是排查「为什么没装到最新版」的第一招**。Pin-Priority 写错最常导致「源里有新版却一直装老版」。

⚠️ **`-y` 在生产上很危险**。它会跳过所有交互确认，包括「这个包要删掉 30 个包，你确定吗」。**先不带 `-y` 看一遍要做什么。**

⚠️ **`apt upgrade` 和 `full-upgrade` 不同**。`upgrade` 拒绝删包或装新包（安全）；`full-upgrade` 会为了升级而装新包、删不兼容的包（发行版大版本升级用它）。**在生产机上随手 `full-upgrade` 可能把服务依赖的库换掉。**

⚠️ **脚本里用 `apt-get` 不用 `apt`**。`apt` 会输出 `WARNING: apt does not have a stable CLI interface`，而且输出格式可能在小版本间变化，把你的脚本搞崩。

⚠️ **`apt install ./file.deb` 和 `dpkg -i` 完全不同**。前者解依赖，后者不解。**装本地 deb 优先用前者。**

⚠️ **`--allow-unauthenticated` 等于关闭完整性检查**，只在完全信任的本地镜像上用。

⚠️ **`apt` 会锁 dpkg 数据库**。别在两个终端同时跑 apt，会出现 `Could not get lock /var/lib/dpkg/lock`。

## apt-cache — 查包信息

```bash
apt-cache [选项] 命令
```

| 命令 | 作用 |
|---|---|
| `policy 包` | **版本和来源**：候选版、已装版、优先级、来自哪个源 |
| `show 包` | 详细信息（依赖、大小、描述） |
| `madison 包` | 源里所有可用版本（`apt policy` 的加强版） |
| `depends 包` | 依赖 |
| `rdepends 包` | 谁依赖它（**删包前必看**） |
| `showpkg 包` | 包名与文件列表的双向查询 |
| `stats` | 包数据库统计 |

```bash
# 最有用的一条：看这个包为什么是这个版本
$ apt-cache policy nginx
nginx:
  Installed: (none)
  Candidate: <版本号>            # 候选版本，以你机器的输出为准
  Version table:
     <版本号> 500
        500 http://archive.ubuntu.com/ubuntu noble/main amd64 Packages
        100 /var/lib/dpkg/status
     ...

$ apt-cache show nginx | head -20
$ apt-cache madison nginx

# 删包之前：谁在依赖它
$ apt-cache rdepends libc6 | head -20
```

⚠️ **`policy` 里靠前的数字是优先级**（正常源是 500，PPA 通常是 100）。同一个包有多个源时看谁的优先级高决定装哪个。**具体数字以你的源配置为准。**

⚠️ **`madison` 输出是给人看的，不是给脚本解析的**。脚本选版本用 `apt-cache policy` 或 `apt policy`。

⚠️ **`Version table` 里出现 `/var/lib/dpkg/status` 表示那个版本是「已安装的本地版本」**，不是任何源提供的。**它和源里的版本冲突时，源里的优先（因为 500 更高）**。

⚠️ **`rdepends` 的输出包含「只是恰好一起装」的关系**，全删掉通常不可行。`apt autoremove` 会算依赖图，`rdepends` 只是文本匹配。

## apt-mark — 标记包状态

```bash
apt-mark [选项] 命令
```

| 命令 | 作用 |
|---|---|
| `showmanual` | 手动安装的 |
| `showauto` | **作为依赖自动装的** |
| `showhold` | 被 hold 住的 |
| `hold 包` | **锁定，不自动升级** |
| `unhold 包` | 取消锁定 |
| `markauto` / `markmanual` | 改标记 |

```bash
$ apt-mark showhold                        # 谁被锁着
$ sudo apt-mark hold nginx                # 锁定：apt upgrade 不会动它
$ apt-mark showauto | grep nginx           # 哪些是依赖带进来的
$ sudo apt-mark unhold nginx

$ sudo apt-mark showmanual > /tmp/manual.txt
$ sudo apt-mark showauto > /tmp/auto.txt
```

⚠️ **`apt-mark hold` 是生产环境防升级的常用手段**。锁了某个关键包（比如内核、数据库客户端），`apt upgrade` 会跳过它并在末尾列出来提醒你。

⚠️ **hold 之后那个包也会在 `apt upgrade` 输出里显示为「kept back」**，不是错误。

⚠️ **`showauto` 是判断「我是不是手动装的」的唯一可靠方式**。想复制一套环境到新机器时，`showmanual` 就是你的安装清单。

## dpkg — 底层包操作

```bash
dpkg [选项] 操作
```

| 操作 | 作用 | 解依赖 |
|---|---|---|
| `-i` / `--install` | 安装 `.deb` | ❌ **不解** |
| `-r` / `--remove` | 删除，留配置 | — |
| `-P` / `--purge` | 删除 + 删配置 | — |
| `-l` | 列出已装包 | — |
| `-L` | 列某包安装的所有文件 | — |
| `-S` | **查某文件属于哪个包** | — |
| `-s` / `--status` | 查包状态 | — |
| `-c` | 列 `.deb` 里的文件 | — |
| `-I` | 看 `.deb` 的元信息 | — |
| `-x` | 解开 `.deb`（不用装） | — |
| `--unpack` | 只解包不配置 | — |
| `--configure -a` | 配置所有待配置的包 | — |
| `--audit` / `--verify` | 检查一致性 | — |
| `--print-architecture` | 打印架构（`amd64`） | — |
| `--get-selections` | 导出已装包选择 | — |
| `--set-selections` | 导入已装包选择 | — |

```bash
# 装
$ sudo dpkg -i package.deb              # ⚠️ 不解依赖
$ sudo apt -f install                  # 依赖没满足时用这个补救

# 只解包不配置（批量装前的常见第一步）
$ sudo dpkg --unpack *.deb
$ sudo dpkg --configure -a

# 查
$ dpkg -l | grep nginx
$ dpkg -l 'nginx*'                    # 模式匹配
$ dpkg -L nginx                        # 这包装了哪些文件
$ dpkg -s nginx                        # 状态、版本、依赖
$ dpkg -S /usr/sbin/nginx              # 这个文件属于哪个包  ← 最有用的
$ dpkg -S $(command -v nginx)

# dpkg-query：按字段查询（比 -l 更可控）
$ dpkg-query -W -f='${Package}\t${Version}\t${Status}\n' | head -10
$ dpkg-query -W -f='${binary:Package}\t${Version}\t${Architecture}\n' nginx

# 导出/还原已装包列表
$ dpkg --get-selections > /tmp/pkgs.list
$ sudo dpkg --set-selections < /tmp/pkgs.list && sudo apt-get dselect-upgrade

# 卸
$ sudo dpkg -r nginx                   # 留配置
$ sudo dpkg -P nginx                   # 连配置删

# 离线查 .deb
$ dpkg -I package.deb                  # 元信息：包名、版本、依赖
$ dpkg -c package.deb                  # 里面的文件列表
$ dpkg -x package.deb ./extracted      # 解开看内容，不安装

# 检查系统一致性
$ sudo dpkg --audit                    # 有没有半配置的包
$ sudo dpkg --verify                   # 校验已装文件的校验和
$ sudo dpkg --verify nginx             # 只校验某个包

$ dpkg --print-architecture            # amd64
```

⚠️ **`dpkg -i` 不解依赖**。装完通常是「半配置」状态，`dpkg -s` 显示 `unpacked` 或 `half-configured`。**用 `sudo apt -f install` 补齐依赖，或者干脆一开始就用 `sudo apt install ./package.deb`。**

⚠️ **`dpkg --verify` 依赖包文件的校验和信息，不是所有包都能百分百覆盖，结果仅供参考**。做完整性校验优先用 AIDE、Tripwire 等安全工具。

⚠️ **`dpkg --get-selections` + `--set-selections` 还原包列表时，不会自动处理推荐包、新依赖和架构差异。跨大版本（比如 22.04→24.04）盲目还原不推荐**，容易把不兼容的版本拉回来。最稳妥的做法是只备份「手动安装」清单（`apt-mark showmanual`）。

⚠️ **`dpkg -l` 里的状态码要会看**：

| 前两字符 | 含义 |
|---|---|
| `ii` | 正常已装 |
| `rc` | 卸载但**配置还留着**（`removed but configs remain`） |
| `un` | 未安装/未全解包 |
| `iU` | 已解包但未配置（`iW` = 配置文件缺失） |
| `iF` | 半配置 |
| `re` | `r` 替换 `e` 出错 |
| `xx` | 状态码本身非法 |

⚠️ **`dpkg -S 找不到时返回非 0**。找不到通常意味着这个文件**不属于任何包**（手动放的，或从某个包删掉了）。`dpkg -S` 的输出格式是 `包名: 路径`（带冒号）。

⚠️ **`dpkg -S` 在 metapackage 上会失败**。比如 nginx 在 Ubuntu 上是个元包，**二进制文件属于 `nginx-core`，配置文件属于 `nginx-common`**，查 `nginx` 查不到。这不是 bug，是包结构如此。

⚠️ **`dpkg -r` 之后 `dpkg -l | grep` 会看到 `rc` 状态**，配置文件还占着。想彻底清掉用 `-P`，或者 `apt autoremove`。

⚠️ **不要用 `dpkg` 做日常装卸**。它不解依赖、不联网、语义脆弱。**日常用 `apt`，`dpkg` 留给「查文件归属」和「离线处理 deb」这两个场景。**

⚠️ **`dpkg` 被中断会留下锁**，之后所有 apt 操作报 `Could not get lock`。确认没有 apt 在跑之后才能删锁文件，别盲删。

## dpkg-divert — 把文件路径「让」开

当你需要替换一个包自带的文件，又不想让升级覆盖时用。

```bash
dpkg-divert [选项] 操作 文件
```

| 操作 | 作用 |
|---|---|
| `--divert` | **让开**这个路径，把包里的挪到 `.dpkg-divert` 后缀 |
| `--rename` | 让开后重新指定包里的路径 |
| `--remove` / `--local` | 还原 |
| `--list` | 看现有 divert 记录 |

| 选项 | 作用 |
|---|---|
| `--package 包` | 只针对某个包 |
| `--rename` + `路径` | 换名 |
| `--admindir` | 改管理目录（chroot 场景） |
| `--add-local` / `--remove-local` | 本地 divert |

```bash
# 看现有的
$ dpkg-divert --list | grep sshd

# 把 /etc/ssh/sshd_config 让开，自己接管
$ sudo dpkg-divert --divert --rename /etc/ssh/sshd_config
$ sudo nano /etc/ssh/sshd_config          # 现在改这个文件不会被包升级覆盖

# 还原
$ sudo dpkg-divert --local --rename --remove /etc/ssh/sshd_config
```

⚠️ **`dpkg-divert` 会改变文件路径**，弄错会让包管理器以为文件被删了。改之前先 `dpkg-divert --list` 看现状，改完 `dpkg -S` 验证归属。

⚠️ **`--local --rename --remove` 三个选项必须一起给**，只给一部分还原不了。

⚠️ **这是给「包和上游配置打架」的场景用的**。绝大多数情况用配置文件自带的 include 机制（如 `sshd_config.d/`）更干净。

## apt-config — 读改 APT 配置

```bash
apt-config [选项] 命令
```

| 命令 | 作用 |
|---|---|
| `dump` | **打印全部配置** |
| `shell 键` | 读单个值 |
| `set 名=值` | 改配置（写 `/etc/apt/apt.conf.d/`） |

```bash
$ sudo apt-config dump | head -30
$ apt-config shell binary Recommends
$ sudo apt-config set Acquire::Retries "3"
```

常用配置项：

| 键 | 作用 |
|---|---|
| `Acquire::Retries` | 下载重试次数 |
| `Acquire::http::Proxy` | 代理 |
| `APT::Install-Recommends "false"` | **全局不装推荐包** |
| `APT::Get::Assume-Yes "true"` | ⚠️ 全局自动 yes |
| `Dir::Etc::sourcelist` | 源列表路径 |

⚠️ **`apt-config set` 写的是永久配置**，会静默影响以后所有 apt 操作。改之前先 `dump` 记下原值。

## 软件源 — /etc/apt/

**源列表文件**

| 文件 | 格式 | 说明 |
|---|---|---|
| `/etc/apt/sources.list` | 一行一个源 | 老格式，Ubuntu 24.04 默认**基本为空** |
| `/etc/apt/sources.list.d/*.list` | 一行一个源 | 老格式的独立文件 |
| `/etc/apt/sources.list.d/*.sources` | **deb822** | **Ubuntu 24.04 默认格式** |

⚠️ **Ubuntu 24.04 默认用 deb822 格式的 `.sources` 文件**，一个文件里用字段描述源，而不是一行一个：

```
Types: deb
URIs: http://archive.ubuntu.com/ubuntu/
Suites: noble noble-updates noble-backports
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
```

加老格式的 `.list` 也能被识别，但**两个文件混用容易出现重复源**（同一源写两遍，`apt update` 报 `Target Packages ... configured multiple times`）。

⚠️ **`suites` 里写错了会 404**，而且 `apt update` 的报错不直观。改源之后必须 `apt update` 验证。

⚠️ **不要混用 `signed-by` 和 `trusted=yes`**。`trusted=yes` 等于不验证签名，谁都能劫持你的源。**永远用 `Signed-By` 指向 keyring 文件。**

⚠️ **`apt update` 的 `N:` 开头行是警告不是错误**（`N: Skipping acquire of configured file 'main/binary-i386/Packages'`）。行尾有 `E:` 才是真错误。

### add-apt-repository — 加第三方源

```bash
sudo add-apt-repository 源
```

| 选项 | 作用 |
|---|---|
| `-y` | 不询问 |
| `-n` | 只加 `deb` 行，**不加 `deb-src`** |
| `-r` | **移除**该源 |
| `-u` | 加完就 `apt update` |
| `-p` | 加「预发布」源 |
| `-s` | 脚本模式（读 stdin） |

```bash
$ sudo add-apt-repository ppa:git-core/ppa
$ sudo add-apt-repository -y -u ppa:git-core/ppa
$ sudo add-apt-repository -r ppa:git-core/ppa

# 加一行 deb 源
$ echo "deb http://example.com/ubuntu stable main" | sudo tee /etc/apt/sources.list.d/example.list

# 加 deb822 源
$ sudo tee /etc/apt/sources.list.d/example.sources > /dev/null << 'EOF'
Types: deb
URIs: http://example.com/ubuntu/
Suites: stable
Components: main
Signed-By: /usr/share/keyrings/example-keyring.gpg
EOF
```

⚠️ **PPA 是第三方，没有 Canonical 的审查**。加之前想清楚：装的是谁维护的代码、出问题找谁。**公司环境优先用内部源 + `Signed-By`。**

⚠️ **`add-apt-repository` 默认会加 `deb-src`（源码源）**，不需要的话加 `-n`，省一半索引空间。

⚠️ **移除源要同时删 keyring**，否则 `/etc/apt/keyrings` 会越积越多。

## GPG — 验证源的签名

```bash
gpg [选项]
apt-key                      # ⚠️ 已废弃，不要用
```

```bash
# 列出已有的 key
$ gpg --list-keys
$ ls -l /usr/share/keyrings/
$ ls /etc/apt/trusted.gpg.d/

# 生成自己的 key（用来签内网源）
$ gpg --full-generate-key

# 导出公钥给源用
$ gpg --export --armor < KEYID > /etc/apt/keyrings/myrepo.gpg
```

⚠️ **`apt-key` 已经在现代 apt 里废弃**。它把公钥存在一个已签名但内容随时间过期的文件里，key 过期后所有源会突然全挂。新做法是**每个源一个 keyring 文件**，并在源的 `Signed-By` 里指定：

```bash
# 老做法（不要用）
$ sudo apt-key adv --keyserver keyserver.ubuntu.com --recv-keys ABC123

# 新做法
$ curl -fsSL https://example.com/repo/gpg.key \
    | sudo gpg --dearmor -o /etc/apt/keyrings/example.gpg
$ echo "deb [signed-by=/etc/apt/keyrings/example.gpg] http://example.com/ubuntu stable main" \
    | sudo tee /etc/apt/sources.list.d/example.list
```

⚠️ **key 文件权限要是 644**（可读即可），目录 `/etc/apt/keyrings/` 755。权限不对 apt 会拒绝用。

⚠️ **`gpg --dearmor` 处理的是 ASCII armored（`-----BEGIN PGP-----`）公钥**。已经是二进制的 keyring 不要 dearmor。

## snap — 跨发行版包

```bash
snap [选项] 命令
```

| 命令 | 作用 |
|---|---|
| `install` / `remove` | 装 / 卸 |
| `list` | 已装的 |
| `info` | 详细信息（含 channel） |
| `refresh` | 更新 |
| `refresh --list` | 看有什么可更新 |
| `revert` | **回滚到上一个版本** |
| `services` | 看 snapd 的服务 |
| `changes` | 看进行中的操作 |

```bash
$ sudo snap install code
$ snap list
$ snap info code
$ sudo snap refresh
$ snap refresh --list
$ sudo snap revert code          # ⭐ 回滚，出问题时的救命功能
$ snap services                  # 看它起了哪些服务
$ sudo snap install --classic code    # 用 classic 模式（绕过 confinement）
```

⚠️ **snap 是自动更新的，你控制不了**。`snap refresh` 由 `snapd` 定时跑，**不会问你**。想要可控更新：

```bash
# 关闭某包的自动更新
$ sudo snap set system refresh.retain=2
$ sudo snap set <包名> refresh.hold=true    # 暂停该包更新
```

⚠️ **snap 包以 root 权限的 confinement 运行**，和 deb 的权限模型不一样。**服务器上一般不该用 snap**。

⚠️ **`snap revert` 会回退版本但不修复已损坏的状态**。包更新坏了可以回退，但数据/schema 已经迁移就回不去了。

⚠️ **snap 的网络行为受 confinement 限制**，常见问题是「snap 装的程序连不上特定端口/网段」。

⚠️ **snap 安装路径在 `/snap/`**，且在 `/var` 之外，不适合服务器。

## flatpak — 沙箱应用

```bash
flatpak [选项] 命令
```

```bash
$ flatpak remotes                        # 看源
$ flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
$ flatpak search <关键字>
$ flatpak install flathub org.gnome.Calculator
$ flatpak list
$ flatpak update
$ flatpak uninstall <应用 ID>
$ flatpak run <应用 ID>
```

⚠️ **flatpak 不是系统自带的**。`sudo apt install flatpak`。

⚠️ **flatpak 应用的运行环境不是你系统的**。它自带一份库，和 apt 装的同名库**不共享**。所以「在 flatpak 里装的库」和「系统里 apt 装的库」是两份，容易困惑。

⚠️ **同样不适合服务器**，而且比 snap 更重。

## ldd — 看动态库依赖

```bash
ldd [选项]... 文件
```

| 选项 | 作用 |
|---|---|
| （无） | 打印依赖的共享库和解析地址 |
| `-r` | 也显示 `LD_PRELOAD` 类依赖和缺失的库 |

```bash
$ ldd ./myprogram
	linux-vdso.so.1 (0x00007ffd...)
	libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007f...)
	libm.so.6 => /lib/x86_64-linux-gnu/libm.so.6 ...

$ ldd -r ./myprogram
	/lib64/ld-linux-x86-64.so.2 (0x00007f...)
	statically linked      ← 输出这个说明不是动态链接
```

⚠️ **⚠️ 永远不要对不可信的二进制跑 `ldd`**。老版本的 `ldd` 会**实际执行**该程序来解析库，在被入侵的机器上等于执行了攻击者的代码。**新版本（≥ 2.30）改成了安全实现，但老系统上的 ldd 仍会执行。**要检查不可信文件用 `file` 或 `objdump -p`。

⚠️ **`ldd` 的输出出现 `not found`** 说明缺库，或者该库不在搜索路径里。用 `LD_LIBRARY_PATH` 临时指定，或装 `lib` 开发包。

⚠️ **`ldd` 输出 `statically linked` 说明是静态编译**，不依赖系统库，移植性好但体积大。

⚠️ **`ldd` 显示的是「当前这个环境」解析的结果**，换台机器结果可能不同。

## dpkg-reconfigure — 重跑包的配置向导

```bash
sudo dpkg-reconfigure [选项]... 包名...
```

| 选项 | 作用 |
|---|---|
| `-p` / `--priority` | 只处理优先级**低于或等于**该值的包 |
| （无） | 交互式逐个重新配置 |

```bash
$ sudo dpkg-reconfigure openssh-server   # ⭐ 改完 sshd_config 或改密钥后重跑
$ sudo dpkg-reconfigure -plow            # 重跑所有优先级 low 的包
$ sudo dpkg-reconfigure --all            # 全部重跑（会跑很久）
```

⚠️ **`dpkg-reconfigure openssh-server` 会重新生成 host 密钥并重置部分配置**，在生产机上要小心。它是「配置丢了但包还在」时的正规修法，但**不要当重启服务用**（重启服务用 `systemctl restart`）。

⚠️ **`dpkg-reconfigure -plow` 在某些机器上会弹出大量包的交互界面**。批量服务器上用非交互工具（`debconf-set-selections` + `dpkg-reconfigure` 配好预设）。

⚠️ **它不能修复 `dpkg -i` 造成的依赖不满足**。那个用 `apt -f install`。

## gcc — 编译与链接（配合 ldd 排查）

```bash
gcc [选项]... 文件...
```

| 选项 | 作用 |
|---|---|
| `-o 文件` | 输出文件名（**不加就是 a.out**） |
| `-Wall` | **常用警告全开** |
| `-Wextra` | 额外警告 |
| `-g` | 带调试符号（给 gdb 用） |
| `-O0` / `-O2` | 不优化 / 优化（`-O2` 是发布常用） |
| `-c` | **只编译不链接**（出 `.o`） |
| `-l库` | 链接库（`lm` → `libm.so`） |
| `-L目录` | 库搜索路径 |
| `-I目录` | 头文件搜索路径 |
| `-static` | 静态链接 |
| `-D宏` / `-D宏=值` | 定义宏 |
| `-pthread` | **链接线程库（现代 gcc 里常被漏掉）** |

```bash
# 最基本的编译
$ gcc -Wall -O2 -o hello hello.c
$ ./hello

# 多文件：先编译再链接
$ gcc -Wall -c -o main.o main.c
$ gcc -Wall -c -o util.o util.c
$ gcc -o app main.o util.o -lm -pthread

# 调试版
$ gcc -g -O0 -fsanitize=address -o app main.c   # ASan 抓内存错误

# 看依赖（对应 ldd）
$ ldd ./app
$ objdump -p ./app | grep NEEDED     # 不执行目标程序，更安全
```

⚠️ **报错信息在第一行，最后一行才是真正原因**。`undefined reference to 'foo'` 通常是**忘了链接对应的库**（`-lfoo`）或函数声明和定义不一致，不是「foo 不存在」。

⚠️ **不加 `-o` 会生成 `a.out`**，一堆程序会互相覆盖。**养成写 `-o` 的习惯。**

⚠️ **忘记 `-pthread` 的现象是程序静默死锁或段错误**，而不是编译错误，很难查。

⚠️ **`-Wall -Wextra` 开着的警告不要忽略**。大部分警告都是真 bug 的预告。

⚠️ **glibc 版本和目标机器不一致会让程序起不来**（`GLIBC_2.xx not found`）。Debian/Ubuntu 用 `patchelf --set-interpreter` 或静态链接解决，不要手动升级系统 glibc。

## update-alternatives — 管理可选实现的链接

系统里同一个命令常有多个实现（`vi` 可以是 vim.tiny / vim.basic / nano / ed），alternatives 决定 `/usr/bin/vi` 指向谁。

```bash
update-alternatives [选项]...
```

| 操作 | 作用 |
|---|---|
| `--display 名` | 看当前指向和所有候选 |
| `--config 名` | **交互选择**（⚠️ 必须在终端跑） |
| `--set 名 路径` | 直接设为某路径 |
| `--auto 名` | 恢复自动 |
| `--query 名` | 详细查询 |
| `--list 名` | 列出所有候选 |

```bash
$ update-alternatives --display vi
$ update-alternatives --query editor
$ sudo update-alternatives --config editor    # 交互菜单选
$ sudo update-alternatives --set editor /usr/bin/vim.basic
$ sudo update-alternatives --auto editor
$ update-alternatives --list editor
```

⚠️ **`--config` 是交互式的，在脚本或管道里会挂住**。脚本里用 `--set`。

⚠️ **alternatives 的优先级数字越大越优先**。`vim.basic` 通常 30，`vim.tiny` 15，`nano` 40。所以**最小安装时 `vi` 指向 vim.tiny，装了完整 vim 后可能变成 vim.basic** —— 这解释了为什么同一份文档在不同机器上 `vi` 行为不同。

⚠️ **alternatives 只管理 `/usr/bin` 下的符号链接**，man page 会跟着一起切换（作为 slave link）。

## 小结

| 场景 | 命令 |
|---|---|
| 装软件 | `sudo apt update && sudo apt install pkg` |
| 卸干净（连配置） | `sudo apt purge pkg` |
| 清理无用依赖 | `sudo apt autoremove --dry-run` 先看，再真跑 |
| 装本地 deb | `sudo apt install ./file.deb`（**不是** `dpkg -i`） |
| 依赖坏了 | `sudo apt -f install` |
| 查文件属于哪个包 | `dpkg -S /path/to/file` |
| 查包装了哪些文件 | `dpkg -L pkg` |
| 查版本来源 | `apt-cache policy pkg` |
| 搜索 | `apt search kw` |
| 锁定不许升级 | `sudo apt-mark hold pkg` |
| 看哪些是依赖带的 | `apt-mark showauto` |
| 加第三方源 | `sudo add-apt-repository ppa:xxx` |
| 装源密钥（**不用 apt-key**） | `gpg --dearmor` 到 `/etc/apt/keyrings/` |
| 检查系统一致性 | `sudo dpkg --audit` |
| 离线看 deb 内容 | `dpkg -c file.deb` / `dpkg -I file.deb` |
| snap 出问题回滚 | `sudo snap revert 包名` |

**十条铁律**

1. **`apt install` 之前先 `apt update`**，否则装到旧版。
2. **`dpkg -i` 不解依赖**，用 `apt install ./file.deb` 或事后 `apt -f install`。
3. **`apt-mark hold` / `autoremove` / `purge` 之前先 `--dry-run` 或不带 `-y` 看一遍**。
4. **脚本里用 `apt-get` 不用 `apt`**，`apt` 的输出格式不稳定。
5. **`apt upgrade` 不删包，`full-upgrade` 会**。生产上别随手 full-upgrade。
6. **不用 `apt-key`**，改成 per-source keyring + `Signed-By`。
7. **源用 `Signed-By` 不用 `trusted=yes`**，后者等于放弃签名验证。
8. **`autoremove` 会删「手动装的包」**，先 `--dry-run` 确认。
9. **服务器上别用 snap 和 flatpak**，自动更新不可控。
10. **绝不对不可信二进制跑 `ldd`**，老版本会执行它。
