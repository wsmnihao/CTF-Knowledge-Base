# 第 9 章 vi / vim

> **本章目标**：读完后你能——
> 1. 说清为什么服务器上你还是得会 vi，以及 Ubuntu 上 `vi` 和 `vim` 的真实关系

> 6. 用 `q` 录制、`@` 回放宏，把重复十次的编辑压成两次按键
> 7. 说清 `:w`、`:q`、`:wq`、`:q!`、`:x` 五者的语义差别，并知道 `:x` 为什么不改 mtime
> 8. 写出一份服务器上够用、又不惹事的最小 `.vimrc`
>
> **前置知识**：第 3 章《终端与 Shell》
>
> **预计耗时**：90 分钟

你在自己的笔记本上用 nano 改配置文件，一切正常。然后你 SSH 到服务器上，屏幕上只有 24 行、一个光标、没有鼠标。

这时候你有两个选择：装一个 nano，或者学会 vi。

**答案是学会 vi。**理由不是"vi 更优雅"，而是三条非常现实的理由：

1. 服务器上不一定有 nano——最小化安装的镜像和容器常常只有 vi。
2. vi 是 **POSIX 的一部分**。任何一台 Unix-like 机器都保证它能用，包括十年后的那台。
3. 你的 vi 技能是**跨机器的**。在 A 公司服务器练熟的键，在 B 公司笔记本、在 Docker 里、在别人的跳板机上都不会变。

本章不讲"vim 有多神"。本章只讲一件事：**在紧急情况下，你能不能可靠地把一个文件改对并保存下来。**

## 9.1 为什么服务器上还是 vi

### vi 是规范的一部分，不是历史包袱

`vi` 是 POSIX（可移植操作系统环境）规范里明确规定的文本编辑器。规范定义的不只是 `vi` 这个名字，还定义了 `vi` 的按键行为。因此：

- 老的 Solaris/AIX、嵌入式 BusyBox、精简容器里的 `vi`，和 Ubuntu 的 vi 键位一致。
- 你在别处学的 vi 肌肉记忆在这里依然成立。

### Ubuntu 上 `vi` 到底是什么

在 Ubuntu 24.04 上，`vi` 不是一个独立程序，而是 alternatives 机制指向的一个链接：

```bash
$ ls -l /usr/bin/vi
lrwxrwxrwx 1 root root 3 ... /usr/bin/vi -> /etc/alternatives/vi

$ readlink -f "$(command -v vi)"
/usr/bin/vim.tiny
```

**这就是第一个要记住的事实：`vi` 很可能是 `vim.tiny`。**`vim.tiny` 是 vim 裁剪版，语法高亮、很多选项和 `+eval` 特性都没有。所以"某个 vi 命令在文档里能用，我这里却报错"，第一反应应该是：我用的到底是 `vi`、`vim.tiny` 还是完整版 `vim`？

自己确认的办法：

```bash
$ vi --version | head -3
$ vim --version | head -3
$ vim --version | grep -o '[+-]clipboard\|[+-]eval\|[+-]syntax'
```

看一下下面这张表，心里有个定位：

| 编辑器 | 上手成本 | 服务器默认有 | 适合场景 |
|---|---|---|---|
| **nano** | 5 分钟 | 常常有（但精简镜像/容器里常缺） | 改一个文件就走 |
| **vi / vim** | 几天 | 一定有 | 长期工作、需要批量编辑 |
| **ed** | 忘不掉就好 | 一定有 | 脚本里逐行改（见第 8 章 sed） |

### vim 比 vi 多了什么

如果你已经会 vi，下面这些是 vim 独有的、你最该先学的部分：

- **撤销树**：撤销之后还能"撤销这个撤销"，不容易走进死胡同。
- **语法高亮**：读配置文件时错误的地方一眼可见。
- **寄存器**：复制的内容不只有一份，见 9.7。
- **宏**：本章 9.8 的重点。
- **`text object`**：`daw` 一键删一个词，见 9.5。
- **插件**：服务器上**不要**装，见 9.11。

## 9.2 三种模式与模式切换的心智模型

### 模式不是麻烦，是分工

vi 的设计核心是一个分工：不同类型的操作放在不同模式里，避免同一批按键既可能是"插入文字"又可能是"执行命令"。

| 模式 | 怎么进 | 主要按键 | 干什么 |
|---|---|---|---|
| **普通模式**（Normal） | 打开文件就在这里；任何时候按 `Esc` | `h j k l d c y p u i a o :` | 执行命令：移动、删除、复制、进入别的模式 |
| **插入模式**（Insert） | `i` `a` `o` `I` `A` `O` | 就是键盘字母 | 像在记事本里一样打字 |
| **可视模式**（Visual） | `v` `V` `Ctrl+V` | `d` `y` `c` `p` | 选一段文本再操作 |
| **命令行模式** | `:` `/` `?` | 命令 + 回车 | 执行一条命令 |

命令行模式严格说不是独立模式，它只是普通模式下弹出的一行输入框。

### 最关键的一条：普通模式才是"主场"

新手最常见的两个问题，都源于忘了自己在哪个模式：

**问题一：以为自己在普通模式，实际在插入模式。**表现是打完 `jjjj` 之后屏幕上多出四行 `j`：

```bash
# 误操作后
$ cat notes.txt
hello
jjjj
world
```

原因：`i` 之后忘了按 `Esc`，于是 `j` 变成了"回车"。

**问题二：以为自己在插入模式，实际在普通模式。**表现是打出一串 `^H`、`^E`、`0i^H^E^H`。原因是普通模式下这些字母各有含义，`^H` 是退格键的显示（`Backspace`）。

**对策有三个，任选：**

1. 打开 `showmode`，永远知道自己在哪：

```vim
:set showmode
```

屏幕右下角会一直显示 `-- INSERT --` 或 `-- (insert) --`。

2. 养成肌肉记忆：**改完就按 `Esc`，然后停半秒确认光标形状变了再继续。**

3. 万一搞乱了立刻止血：`u` 撤销（普通模式），或者 `Ctrl+C` 也能退出插入模式。

### 心智模型：动词 + 宾语

普通模式下的按键不是"字母"，而是命令。大多数命令的结构是：

```text
数量 + 动词 + 宾语
```

| 部分 | 例子 | 含义 |
|---|---|---|
| 数量 | `3`, `10` | 重复几次 |
| 动词 | `d` delete, `c` change, `y` yank, `p` paste, `v` visual | 要干什么 |
| 宾语 | `w` word, `$` 行尾, `gg` 全文, `iw` inner word | 对谁干 |

所以 `d3w`（删 3 个词）和 `3dw`（同样删 3 个词）是等价写法。理解这个结构，vi 里一半的按键就不用背了。

顺带一提：vi 还有一个从 ed 继承来的 **Ex 模式**。按 `Q` 进入，表现像第 8 章的 `sed` 逐行模式，输入 `:` 后就回到普通模式。你不需要学它，但要知道它存在，这样看到别人按 `Q` 时不会以为他按错了。

## 9.3 打开文件：命令行参数

vi 的"打开"是命令行的一部分，不是在编辑器里敲 `/` 找文件。

```bash
$ vim notes.txt                 # 打开并编辑
$ vim +42 report.md             # 打开并跳到第 42 行
$ vim +/TODO main.c             # 打开并跳到第一个含 TODO 的地方
$ vim -R /etc/ssh/sshd_config   # 只读打开（Read-only）
$ vim -M /etc/passwd            # 只读，且禁止一切修改
$ vim -b disk.img               # 二进制模式，逐字节编辑
$ vim -u NONE notes.txt         # 不读任何配置，排错用
$ vim -n notes.txt              # 不用交换文件
$ vim a.conf b.conf c.conf      # 三个文件一起打开
$ vim -p a.conf b.conf          # 三个文件开成三个标签页
$ sudoedit /etc/hosts           # 用普通用户编辑，保存时才提权
```

### ⚠️ 最容易记混的一条：`vi -r` 和 `vim -r` 不是一回事

```bash
$ vim -r notes.txt     # 崩溃恢复：打开交换文件 notes.txt.swp
$ vim -R notes.txt     # 只读打开
$ vim -h | grep -E '^\s+-(r|R)'   # 自己看帮助里这两个选项的定义
```

在 1970 年代的**经典 vi**（后来的 `vi` / `ex` / `nvi`）里，`-r` 就是 read-only 的缩写。vim 为了成为"兼容 vi 的编辑器"，把这个拼写让给了 recover，于是：

- **`-r` 在经典 vi 里是只读，在 vim 里是恢复。**
- **在 Ubuntu 24.04 上，`vi` 通过 `update-alternatives` 指向 `vim.tiny`，参数完全按 vim 的定义解释**——`vi -r notes.txt` 是**恢复**，不是只读。你可以用 `ls -l $(command -v vi)` 看一眼它到底指向谁。

所以本书所有地方一律用 **`vim -R`** 表示只读。想要"看得见但绝对改不动"，用 `vim -R`，需要更硬的保护再加 `-M`（禁止写文件）。

```bash
$ vim -R /etc/ssh/sshd_config   # 只读，可以搜索、可以翻页
$ vim -M /etc/passwd            # 只读，且修改被直接拒绝
```

### 交换文件：崩溃能救，代价是目录里多一个文件

每次打开 vim，vim 会在同目录创建一个隐藏的交换文件：

```bash
$ ls -a ~/notes/
```

```console
.  ..  notes.txt  .notes.txt.swp
```

正常退出会自动删掉它。**断线、被 kill、机器重启时会残留。**下次打开同一个文件，vim 会拦住你：

```text
E325: ATTENTION
Found a swap file by the name ".notes.txt.swp"
```

这时有两种情况，处理方式完全不同：

| 情况 | 判断方法 | 处理 |
|---|---|---|
| 另一个终端里**真的**有人在编辑 | `ps aux \| grep vim` 找到那个进程 | 换端口 `-b` 或别动它 |
| 残留是上次崩溃留下的 | 没有对应进程 | 删掉 `.swp` 或在 vim 里 `:rm` |

恢复崩溃时未保存的内容用：

```bash
$ vim -r ~/notes/notes.txt
```

恢复完成后把交换文件删掉，否则每次打开都要看到警告。

⚠️ 不要看到 `.swp` 就无脑 `rm -f *swp*`——如果真有人在编辑，你会毁掉他的工作。

### `sudoedit` 比 `sudo vim` 安全

编辑 `/etc` 下的文件有两条路：

```bash
$ sudo vim /etc/ssh/sshd_config   # 整个编辑器以 root 运行
$ sudoedit /etc/ssh/sshd_config  # 编辑你权限下的副本，保存时才提权
```

`sudoedit` 的区别在于：编辑器进程仍是你的普通用户进程，只有"写回目标文件"这一步才用 root。你在编辑器里运行插件、宏、`:!shell` 命令时，不会以 root 身份执行。

不过要注意：**`sudoedit` 是否可用取决于 sudoers 配置**，有些发行版默认禁用或限制它的路径。如果提示 `sudoedit: command not found` 或被拒绝，先问管理员，别自己改 sudoers。

## 9.4 光标移动

vi 的方向键用 `hjkl`，和键盘上的 `jk` 在同一位置。这是历史原因：早期终端没有方向键，vi 必须自己解决。

| 按键 | 动作 | 说明 |
|---|---|---|
| `h` `j` `k` `l` | 左 下 上 右 | 左手 `hjkl` |
| `0` | 行首第一个字符 | 硬行首，空格也算 |
| `^` | 行首第一个**非空白**字符 | 和 `0` 常一起用 |
| `$` | 行尾**最后一个字符** | 在 `$` 上按 `a` 可以追加到行尾 |
| `gg` | 文件第一行 | 两个 `g` |
| `G` | 文件最后一行 | 无参数时 |
| `:{n}` | 第 n 行 | `:42` 也可以 |
| `{n}G` | 第 n 行 | `42G` |
| `w` | 下一个词首 | 空格、标点都算分隔 |
| `W` | 下一个词首（不分标点） | 对路径、URL 有用 |
| `b` `B` | 上一个词首 | |
| `e` | 当前词的最后一个字符 | 便于从词尾开始改 |
| `{` `}` | 上一个 / 下一段（空行分隔） | 读长文本很常用 |
| `(` `)` | 上一个 / 下一句 | |
| `Ctrl+d` `Ctrl+u` | 下 / 上**半屏** | 大文件里翻页的主力 |
| `Ctrl+f` `Ctrl+b` | 下 / 上**一屏** | |
| `Ctrl+e` `Ctrl+y` | 下 / 上滚**一行**（光标不动） | 读日志时很舒服 |
| `H` `M` `L` | 屏幕的顶 / 中 / 底 | |
| `zz` | 把当前行放到屏幕中间 | 配合搜索使用 |
| `Ctrl+o` | 跳回上一个位置 | 搜索跳转后回来 |
| `Ctrl+i` | 再跳过去 | 和 `Tab` 同键 |

### 三个提升体验的组合

**组合一：行号 + 跳转。** 先打开行号：

```vim
:set number
```

然后 `:42` 直接跳。文件里报"第 812 行有问题"时，这一秒值一块钱。

**组合二：搜索 + 居中。** `/error` 找到之后按 `zz`，当前行到屏幕中间，不用眼睛找。

**组合三：计数前缀。** `10j` 下移十行，`3w` 前进三个词，`G` 到文件底再 `gg` 回顶。`5G` 到第五行。

### 终端里方向键失灵怎么办

有些 SSH 终端配置下，方向键会被终端截获（映射成历史记录或别的功能），在 vim 里按了没反应。这不是 vim 的问题。

对策有两个：

1. 用 `hjkl`（本来就该会）。
2. 用 `Ctrl+d` / `Ctrl+u` 翻页，或 `:42` 跳行号。

如果方向键在远程总是干扰，考虑修 `$HOME/.inputrc` 或 SSH 客户端的终端类型设置，而不是改 vim。

## 9.5 编辑：从普通模式走进插入模式

### 六个进入插入模式的键

这是本章最该背熟的一张表：

| 按键 | 进入位置 | 典型场景 |
|---|---|---|
| `i` | 光标**前**一个字符 | 改单词中间 |
| `a` | 光标**后**一个字符 | 想在光标所在字符后面加字 |
| `I` | 行首**第一个非空白字符前** | 加注释、写缩进代码 |
| `A` | 行尾末尾 | 追加一句话 |
| `o` | 在**下方**开一行 | 追加内容（最常用） |
| `O` | 在**上方**开一行 | 往中间插一行 |

**`o` 为什么值得单独强调**：在文件末尾追加三行，传统做法是 `$` 到行尾、`a` 进插入、`Enter` 换行、`Esc`。有了 `o` 只需要一次按键，而且永远不用担心"末尾没有换行符"的边界情况——`o` 会自己补一个换行。

按 `Esc`（或 `Ctrl+[`）回到普通模式。

### 删除与修改

| 按键 | 动作 |
|---|---|
| `x` | 删当前字符 |
| `3x` | 删三个字符 |
| `dw` | 删到下一个词首 |
| `dd` | 删当前整行 |
| `3dd` | 删三行 |
| `D` | 从光标删到行尾 |
| `d$` | 同 `D` |
| `C` | 从光标改到行尾（删完直接进插入模式） |
| `cc` | 改整行（保留缩进） |

### text object：vim 的杀手级功能

`vi` 只能按"字符、词、行"为单位操作，粒度太粗。vim 提供了 **text object**：一个 `a`（around）或 `i`（inner）+ 一个对象名，直接选中"一个完整的词""一对引号里的内容""一段"。

| 按键 | 动作 |
|---|---|
| `diw` | 删除光标所在的词（不含后面的空格） |
| `daw` | 删除光标所在的词（含后面的空格） |
| `ciw` | 改一个词（删完直接进插入模式） |
| `ci"` | 改一对双引号里的内容 |
| `di(` | 删一对圆括号里的内容 |
| `dip` | 删除当前段落 |
| `di(` `di[` `di{` | 各类成对包围 |

配置里只要 `set nocompatible`（默认就是），`iw` / `aw` 这类内置对象就能用。

### 撤销与重做

```text
u        撤销
Ctrl+R   重做
```

**关键点：撤销是"命令级"的。**你一次敲了 `3dd`，它算**一次**操作，`u` 一下就全回来。不是 `u` 三下。

再关键的一点：撤销之后你还能"撤销这个撤销"。`u` 之后按 `Ctrl+R` 是重做；如果连撤销也做错了，可以用撤销树往前翻：

```vim
:earlier 10      " 回到 10 个操作之前的状态
:later           " 往回走
:undo            " 和 u 一样
:redo            " 和 Ctrl+R 一样
```

### 粘贴

```text
p      粘到光标所在行之后（下一行的行首）
P      粘到光标所在行之前
3p     把上次复制的内容贴三份
```

日常最常用的组合是 `dd` + `p` 移动一行：光标在第 20 行，`dd` 剪掉，`p` 粘到第 21 行——一行就下移了。

## 9.6 查找与替换

### 查找

```text
/pattern      往下找
?pattern      往上找
n             下一个匹配
N             上一个匹配
*             搜索光标所在的词（往下）
#             搜索光标所在的词（往上）
```

两个让查找舒服的设置：

```vim
:set hlsearch    " 把所有匹配高亮（默认已开）
:set incsearch   " 边输入边往后面看匹配
:set ignorecase  " 忽略大小写
:set smartcase   " 但你输入里有大写字母时恢复大小写敏感
```

`smartcase` 是 `ignorecase` 的最佳搭档：搜 `error` 能找到 `Error`，搜 `Error` 就只找 `Error`。

搜完之后高亮还留在屏幕上，用下面的命令清掉：

```text
:noh          " 或 Ctrl+L
```

### 三个 vim 特有的正则元素

vim 的正则和 `grep -E` 基本一致，但多三个很实用的东西：

| 写法 | 含义 |
|---|---|
| `\<` `\<word\>` | 单词边界（只匹配完整单词，不会匹配 `error` 里的 `err`） |
| `\c` / `\C` | 强制本次搜索忽略 / 区分大小写 |
| `\v` | "very magic" 模式，反斜杠转义大幅减少 |

`\v` 的例子：

```vim
/\v(pkg|deb)-[0-9]+
```

用 `\v` 时，`(` `|` `+` 都不用转义。这在写复杂模式时省事很多。

如果想匹配完全字面的文本（比如文件路径里那些点号和星号），用 `\V` 表示"从此处开始全部按字面"：

```vim
/\V/usr/local/bin/*.log
```

### 替换：单行、全文、带确认

```vim
:s/old/new/g          " 当前行，每个匹配都替换
:s/old/new             " 当前行，只替换第一个匹配
:s/old/new/gc         " 当前行，逐个确认
:%s/old/new/g          " 全文，每个匹配都替换
:%s/old/new/gc         " 全文，逐个确认
```

⚠️ **第一个高频事故就在这里**：很多人在文件顶行敲 `:s/a/b/g`，发现"整个文件我只改了第一行"。原因是少了 `%`。`%` 的含义是"所有行"，不是"全部匹配"——全部匹配是 `g`。这两个字母分工完全不同。

⚠️ **第二个高频事故是直接在系统文件上执行 `:%s///g`**。没有确认、没有备份，写错了立刻生效。养成习惯：

1. 先 `:g/old/p` 看看会命中多少行；
2. 再 `:%s/old/new/gc` 逐个确认；
3. 需要回退时按 `u`。

`gc` 里的确认键：

| 键 | 作用 |
|---|---|
| `y` | 替换这一处，继续下一处 |
| `n` | 跳过这一处 |
| `a` | 剩下的**全部**替换，结束 |
| `q` | 立刻停止，剩下的都不动 |
| `l` | 替换这一处并跳到下一个匹配处看 |

替换时的三个特殊符号：

| 符号 | 含义 |
|---|---|
| `&` | 整个匹配（用它可以把匹配内容包一层） |
| `\1` | 第一个捕获组（对应 sed 的 `\1`） |
| 分隔符 | 遇到路径里的 `/` 时换分隔符更省事 |

```vim
:s#/usr/local#/opt#g
:s/\(.*\)=\(.*\)/\2=\1/     " 交换等号两边
:s/error/[&]/g              " 给每处匹配加方括号
```

### 按模式批量执行：`:g`

`:g/pattern/命令` 对**所有匹配行**执行一条普通模式命令。它比 `:%s///g` 覆盖面更广，因为能执行的不只是替换。

```vim
:g/todo/s/$/ [未完成]/        " 每行含 todo 的，在行尾加标记
:g/tmp/d                      " 删除所有含 tmp 的行
:g/^#/d                       " 删除所有注释行
:%g/task/normal A [urgent]    " 给所有含 task 的行在行尾追加文字
:v/error/d                    " 删除所有**不**含 error 的行
```

`:g/pattern/p` 是最安全的预演命令：它什么都不改，只把匹配行打印出来。**养成先 `p` 再动手的习惯。**

### 重复上一次替换

```vim
&       " 不带参数执行，再做一次上次的 :s
:~      " 重复上次的 :s（老写法）
:s//new/g " 复用上次的查找模式，只换替换文本
```

`s//new/g` 很实用：上一条命令已经把 `old` 记住了，你只关心新的替换成什么。

## 9.7 复制、剪切与寄存器

### 一切都进寄存器

`yank`（复制）和 `delete`（删除）在内部是**同一个操作**：都是把文本放进寄存器；区别只是 delete 顺便从文件里移除。

所以在 vi 里"复制"和"剪切"是同一个动作，`dd` 和 `yy` 行为对称。

| 按键 | 效果 |
|---|---|
| `yy` | 复制当前行 |
| `3yy` | 复制三行 |
| `y$` | 复制到行尾 |
| `yw` | 复制到下一个词首 |
| `p` / `P` | 粘贴**最近一次删除或复制**的内容 |

### 命名寄存器

寄存器编号 `0` 到 `9`。小写寄存器每次写入就**覆盖**，大写寄存器每次写入就**追加**。

```text
"ayy         " 把当前行存进 a 寄存器（不删除）
"Add         " 追加到 a 寄存器
"ap          " 粘贴 a 寄存器
"aP          " 粘贴 a 寄存器到上一行
```

连着删三行时，vim 会自动把它们轮换存进 `"1` `"2` `"3`：

```text
"1p          " 粘回最近删的那一行
```

另一个有用区别：

```text
"0           " 最近一次 yank 的内容
"-           " 最近一次**小范围**删除的内容
```

系统剪贴板寄存器是 `"+`（粘贴）和 `"*`（拖放），但它们需要 vim 编译时带 `+clipboard`，而且要有 X11 或 Wayland 环境。**结论：纯终端 SSH 里不要指望能用它们**，用文件或 `"a` 更可靠：

```bash
$ vim ~/.clip        # 把内容放进一个文件
$ xclip -selection clipboard < ~/.clip    # 有图形环境时
```

查看和清空：

```vim
:reg             " 列出所有寄存器
:reg a           " 只看 a
:registers       " 同 :reg
```

### ⚠️ 共享家目录时注意 `~/.viminfo`

默认情况下 vim 会把最近复制的**内容和标记**写进 `~/.viminfo`。共享账号、共用家目录的场景下，这意味着：

- 别人可能 `vim` 一下就 `p` 出了你上次复制的密码。
- 你的 `.viminfo` 目录权限是别人可读。

处理方式：

```bash
$ chmod 600 ~/.viminfo
```

```vim
:set viminfo=        " 完全关闭持久化（代价是重启后寄存器没了）
```

**服务器上的默认选择：保留 `viminfo`，但权限设成 600。**

## 9.8 `.` 重复与宏

### `.` 是"重复最后一次改变"

`.` 重复的是**最近一次修改文件的命令**，不包括移动光标、不包括复制。

```text
dw        " 删掉一个词
.         " 再删一个词
.         " 再删一个
3.        " 再删三个
```

这个模式极其实用：把一整行里的重复结构清干净，比一个个按 `x` 快得多。

**注意 `.` 重复的粒度和原命令一致**：你原命令带数量，`.` 就带同样的数量；你用 `cw`，`.` 就重新进插入模式等你打字，所以 `cw` 后面一定要 `Esc`，`.` 才有效。

### 宏：把一串按键存起来

当"一次操作 + `.`"还不够（因为每行要做的事不完全一样），就用宏。

| 按键 | 动作 |
|---|---|
| `qa` | 开始录制到寄存器 `a` |
| （你的按键） | 全部被记录下来 |
| `q` | 停止录制 |
| `@a` | 回放宏 `a` 一次 |
| `@@` | 重复上一次回放的宏 |
| `5@a` | 回放 5 次（比 `5@@` 更快） |

**宏的原理就这么一句：录制期间你按的每个键，都被写进了寄存器 `a`。**所以：

- 宏**就是寄存器**，用 `"ap` 能把宏内容打印出来看，改坏了直接编辑这个寄存器。
- 宏**只在普通模式有效**。`@a` 在插入模式里是另一个含义。

### 录宏的四条纪律

1. **录制期间不要按 `q`**，否则立刻停止录制，后面按键就漏了。
2. **不要在宏里用 `@a` 调自己**，会递归。
3. **先用小数量试跑**（`3@a`），确认正确再上大批量。
4. 宏对**行结构有依赖**。如果每行长度不同、缩进不同，回放结果可能不是你想要的。依赖越强，宏越危险。

### 不用宏也能批量追加：`:g` + `normal`

有些"批量操作"其实不需要宏：

```vim
:%g/task/normal A [urgent]
```

意思是：对每一行含 `task` 的，把普通模式命令 `A [urgent]` 执行一遍。宏和 `:g` 都能用时，**优先用 `:g`**：它更短、更可读、失败时更容易看出问题。

### 在脚本和命令里执行按键

```vim
:normal 3Gdd          " 立刻执行一次按键
:%normal A -- end    " 对每一行执行
```

`:normal` 是把按键从命令行灌进编辑器，在写批处理脚本时很有用。它也能用在你自己的 `.vimrc` 和插件里。

## 9.9 多文件、缓冲区与窗口

这是新手最容易混乱的地方，因为 vi 里有**三个正交的概念**：

| 概念 | 是什么 | 相关命令 |
|---|---|---|
| **缓冲区（buffer）** | 内存里打开的文件内容 | `:e` `:ls` `:b` `:bd` |
| **参数列表（arglist）** | 一串"待处理的文件名" | `:args` `:n` `:N` `:all` |
| **窗口（window）** | 屏幕上的一块显示区域 | `:sp` `:vsp` `:q` `:only` |

### 打开别的文件

```vim
:e /etc/hosts            " 打开新文件替换当前缓冲区
:e! /etc/hosts           " ⚠️ 丢弃当前未保存的修改，强制打开
:e #                     " 回到刚才那个文件
:e! #                    " 强制回到上一个文件
:args *.conf             " 把匹配到的文件设为参数列表
:args **/*.conf          " 递归匹配
```

⚠️ `:e` 到一个新文件时，当前文件如果没保存，vim 会拦住你（报 `E37: No write since last change`）。这时你有三个选择：`:w` 保存、`:e!` 丢弃、`:bd` 关闭这个缓冲区。**这是保护，不要习惯性按 `y` 把所有提示都吞掉。**

### 参数列表：批量处理一批文件

```vim
:n           " 参数列表里的下一个文件（区别于 :bn）
:N           " 上一个文件
:all         " 每个参数都开一个窗口
```

`:n` 是"处理下一个文件"，`:bn` 是"切到下一个缓冲区"。当参数列表只有一个文件时，两个命令感觉一样；一旦你 `:e` 打开了别的文件，它们就分道扬镳了。**理解差异比记住快捷键重要。**

### 缓冲区

```vim
:ls            " 等价 :buffers / :files，列出所有缓冲区
:b 3           " 切到编号 3 的缓冲区
:bn / :bnext   " 下一个缓冲区
:bp / :bprev   " 上一个缓冲区
:bd            " 关闭当前缓冲区（不删磁盘文件）
:bd!           " 关闭并丢弃修改
```

`:ls` 里有两个标记值得认：

- **`+`**：这个缓冲区已被修改。
- **`%`**：当前窗口正在显示的缓冲区。

排查"我到底改了哪些文件"时，`:ls` 一眼就能看清。配合 `set laststatus=2`，编辑器的最底行会一直显示当前文件名——**在服务器上强烈建议打开**，免得在三个文件之间跳晕了把改动存错地方。

### 分屏

```vim
:sp /etc/hosts        " 上下分屏
:vsp /etc/hosts       " 左右分屏
Ctrl+w h/j/k/l        " 在窗口之间移动
:q                   " 关闭当前窗口
:only                " 只留当前窗口
:qall                " 关掉所有窗口
```

一个缓冲区可以在多个窗口里同时显示，改了哪边另一边都会变。窗口只是"看得见的区域"，缓冲区才是"真正的内容"。

### 什么时候该用 vim，什么时候该用 grep

第 8 章讲过 grep 处理的是**流**，vim 处理的是**文件**。

- 问"哪些文件里有 X" → `grep -rl`
- 问"X 在这个文件第几行、上下文是什么" → vim 打开，`/X`、`n`、`zz`
- 问"一共多少个 X" → grep 管道

vim 也有类似功能：`:vimgrep` / `:grep` 在多个文件里搜索，结果进"quickfix" 列表，`:copen` 打开。这在你要在结果之间来回跳转时很顺手：

```vim
:grep -r pattern /etc/
:copen
:cn / :cp          " 下一个 / 上一个结果
```

但判断标准不变：**需要"流式筛选 + 统计"就用 grep，需要"反复进出一个文件"就用 vim。**

## 9.10 保存与退出的语义差别

这一节建议你背下来，因为改系统配置时，"存错了"和"没存上"都是真实事故。

| 命令 | 语义 | 有未保存修改时 |
|---|---|---|
| `:w` | 只保存当前文件，不退出 | 正常保存 |
| `:w file` | 另存为 | 写新文件 |
| `:w!` | 强制写入（覆盖只读标记） | ⚠️ 强行覆盖 |
| `:q` | 退出 | **拒绝退出**（`E37`） |
| `:q!` | 放弃修改，强制退出 | ⚠️ 修改全部丢失 |
| `:wq` | 保存并退出 | 保存后退出 |
| `:x` | 保存（有改动才写）并退出 | 有改动才写盘 |
| `:qa` | 全部保存退出 | 任一文件有修改就整体拒绝 |
| `:qa!` | 全部放弃退出 | ⚠️ 所有修改丢失 |
| `:cq` | 退出，返回非零状态码 | 给 `make` 用，构建失败时中止 |
| `:e!` | 丢弃当前缓冲区的修改 | ⚠️ 修改丢失 |

`ZZ` 是 `:wq` 的快捷键，`ZQ` 是 `:q!` 的快捷键。

### `:q` 报 E37 是保护，不是 bug

```text
E37: No write since last change (add ! to override)
```

它的意思是"你还有改动，我不敢退"。这是 vi 在替你看门。真正该警惕的是 `:q!`：**它不会报错，会安静地丢掉你所有改动。**

⚠️ 在 `/etc/sudoers`、`/etc/fstab` 这类文件上，一个 `:q!` 就可能让你下次 sudo 失败或系统起不来。养成习惯：改配置**先 `:w`**。

### `:x` 和 `:wq` 的差别：只在"有改动"时写盘

```vim
:x     " 缓冲区被修改过 → 写文件；没修改 → 直接退出不写
:wq    " 不管改没改，都写一遍
```

这个差别不是吹毛求疵，它有实际后果：**`:wq` 会更新文件的 mtime**，而大量构建系统和定时任务是靠 mtime 判断"要不要重建"的。

```bash
# 脚本里应该这么写
vim -c ':x' -c ':q' config.ini
# 而不是
vim -c ':wq' -c ':q' config.ini
```

后者每次运行都把 mtime 推到现在，可能触发无意义的重新编译、重新打包，甚至让 `inotify` 之类的监听脚本空转一轮。

⚠️ 反过来，如果你**依赖**"内容没变但时间戳要更新"（比如让某个看时间戳的定时任务重新检查），那就不能用 `:x`。

### 配置备份：留一条退路

编辑系统文件前，把这两行加进 `.vimrc`（见 9.11）：

```vim
set backup
set backupdir=~/.vim-backup,~/.vim-backup//
```

之后每次保存，旧版本会被备份成 `~/.vim-backup/config.ini~`。你改坏了 SSH 配置时，这就是一条明确的退路，不用靠"我记不清刚才删了什么"。

### 需要 sudo 时的保存方式

```vim
:w !sudo tee %          " 把当前缓冲区通过 tee 写回（会提示输密码）
```

不过更推荐 `sudoedit`（见 9.3）：编辑器本身不需要 root 权限。

## 9.11 最小 `.vimrc`（服务器用）

### 原则：保守

服务器上的 `.vimrc` 应该满足三个条件：

1. **不依赖插件**——插件要 git 和网络，装了也可能半残。
2. **不依赖终端的颜色能力**——你不知道对面是 xterm 还是一个只会显示 16 色的 dumb terminal。
3. **不改变按键**——在别人共用或需要临时接管的环境里，改键位是给自己埋雷。

### 推荐配置

```vim
" ~/.vimrc —— 服务器用最小配置
set nocompatible          " 使用 vim 行为而不是 vi 行为（务必保留）
set encoding=utf-8

" 显示
set number                " 行号
set laststatus=2          " 最底行一直显示文件名
set showmode              " 显示当前模式（防卡在插入模式）

" 缩进
set expandtab             " 空格代替 Tab
set tabstop=4
set shiftwidth=4
set softtabstop=4
set autoindent

" 搜索
set hlsearch
set incsearch
set ignorecase
set smartcase

" 撤销与备份
set undofile              " 退出后仍可撤销
set backup
set backupdir=~/.vim-backup,~/.vim-backup//

" 历史
set history=1000
set wildmenu              " 命令行补全显示候选
```

### 每行都在干什么

| 行 | 作用 | 为什么服务器上值得开 |
|---|---|---|
| `set nocompatible` | 启用 vim 特性（`iw`、撤销树等） | vim 默认就是，设一次是保险 |
| `set laststatus=2` | 常驻显示当前文件名 | 三个文件跳来跳去时救命 |
| `set showmode` | 显示 `-- INSERT --` | 防止把命令打进文件 |
| `set expandtab` + `tabstop=4` | 4 空格缩进 | shell 脚本和配置文件的通用约定 |
| `set smartcase` | 大小写搜索的合理默认 | 不用每次搜索都临时设置 |
| `set undofile` | 保存的撤销历史 | 第二天回来还能撤销昨天 |
| `set backup` + `backupdir` | 保存旧版本到 home | 改系统配置的退路 |

### 明确不要装的

| 东西 | 原因 |
|---|---|
| 插件（`:PlugInstall`、fugitive、NERDTree…） | 要 git 和网络；加载耗时；出问题难排查 |
| 主题和 `termguicolors` | 终端不支持真彩色时高亮会花屏或很难读；纯文本 SSH 里颜色往往直接关掉 |
| 自定义按键映射 | 别人的脚本、文档里的说明都是按默认键写的 |
| 大型状态栏插件 | 每次按键都要重绘，SSH 延迟下会明显卡 |
| LSP / AI 补全插件 | 需要常驻进程和大量内存 |

### `.vimrc` 出问题时怎么排查

配置本身出错时，vim 会在启动时给出类似 `E484: Not enough arguments` 或 `E518: Unknown option`，并给出出错行号。

三个救命手段：

```bash
$ mv ~/.vimrc ~/.vimrc.bak          # 先移走，再用 vim 打开文件
$ vim -u NONE notes.txt             # 这次不读任何配置，问题还在就是 vim 本身的问题
$ vim --startuptime vim notes.txt 2>&1 | sort -k2 | tail   # 慢的话，看哪一行加载最耗时
```

⚠️ 顺带说明一个语法点：Vim 脚本和 Ex 命令行里可以用 `"` 开头写注释（前面要有空格），所以你会在网上看到 `:set number " 显示行号` 这种写法。但**那是 Vim 的语法，不是 Bash 的**——Bash 里 `"` 只会开启一个字符串，`mv ~/.vimrc ~/.vimrc.bak " 先移走` 会被解析成"多余的第三个参数"。本章表格里在 vim 块中出现的 `"` 是合法的，在 `bash` 块里请一律用 `#`。

在 vim 里查某个设置到底被谁改的：

```vim
:verbose set number?
```

它会告诉你 `:set number` 是在第几行、哪个文件里被设置的——排查"我的配置为什么没生效"的利器。

### 别忘了 `vimtutor`

服务器上通常已经装好了官方的交互式教程：

```bash
$ vimtutor
```

它不依赖网络、不依赖图形界面，讲的就是普通模式的移动和编辑。**如果你决定只学一件事，就学 `vimtutor` 里的 30 分钟。**它不是完整教程，但足够让你不再害怕 vi。

## 9.12 nano 快速应急

nano 的设计目标恰恰相反：**所有快捷键都显示在屏幕底部**，不用记。

```bash
$ nano notes.txt
$ nano +42 notes.txt    # 打开并跳到第 42 行
$ nano -l notes.txt     # 显示行号
$ nano -w notes.txt     # 不自动换行
```

必会的六个键：

| 按键 | 作用 |
|---|---|
| `Ctrl+O` | 写入（保存）——**按完还要按一次回车确认文件名**，这是最常见的误解 |
| `Ctrl+X` | 退出（有修改会问你要不要保存） |
| `Ctrl+K` | 剪切当前整行 |
| `Ctrl+U` | 粘贴 |
| `Ctrl+W` | 查找（输入后回车） |
| `Alt+W` | 重复上一次的查找 |
| `Ctrl+G` | 帮助（完整快捷键列表） |

**行号和跳转行号的键位在不同 nano 版本里不一样**，不要背网上某篇文章的说法——以 `Ctrl+G` 打开的帮助和你屏幕上那一行提示为准。

### nano 的配置文件

```bash
$ nano ~/.nano.conf
```

```
set tabstospaces
set tabsize 4
set autoindent
set linenumbers
```

注意 nano 的缩进和 Tab 行为与 vi 不同，**不要把 vi 的配置直觉套到 nano 上**。

### nano 什么时候更合适

- 你只想改一个 `PATH` 或一个用户名，五分钟内要走。
- 环境里没装 vim（或只是个容器）。
- 对方给你的操作手册里写的就是 nano。

### vi 什么时候更合适

- 你每周都要在服务器上改配置。
- 要做查找替换、跨文件跳转、批量修改。
- 一次改错可能让服务起不来。

**结论：nano 是应急工具，vi 是主力工具。**两者不冲突——本章的目标是让你在 nano 不存在时也能把文件改对。

## 9.14 动手实验：用宏给 100 行文本批量加前缀和后缀

### 目标

1. 用 `q` 录制、`@` 回放宏，对 100 行文本每行**行首**加前缀、行尾**加后缀**；
2. 理解 `.` 与 `@` 的区别，以及宏为什么能一次处理异构的重复操作；
3. 掌握 `:w` / `:q!` / `:x` 在实际场景中的选择；
4. 体验交换文件和崩溃恢复。

### 步骤

**1. 准备数据**

```bash
$ mkdir -p ~/vim-lab && cd ~/vim-lab
$ seq -f 'task%03g' 1 100 > tasks.txt
$ head -3 tasks.txt
task001
task002
task003
$ wc -l < tasks.txt
100
```

**2. 打开文件，先确认行号**

```bash
$ vim tasks.txt
```

在 vim 里执行：

```vim
:set number
:1
gg
```

你应该看到光标在第 1 行、行号是 1。

**3. 录制宏**

依次按（每行是一次完整的按键序列，按完看到光标回到行首再按回车没有反应就对了）：

```text
qa
I# <Esc>
A -><Esc>
q
```

含义拆开看：

| 按键 | 含义 |
|---|---|
| `qa` | 开始录制到寄存器 `a` |
| `I# ` | 在行首第一个非空白字符前插入 `# ` |
| `Esc` | 回普通模式，这一步属于一次完整修改 |
| `A ->` | 在行尾追加 ` ->` |
| `Esc` | 回普通模式 |
| `q` | 停止录制 |

**4. 试跑 3 次**

```text
3@a
```

你应该看到第 1–3 行都变成了 `# task001 ->` 这样的形式。

**5. 验证撤销粒度**

先按 `3u`，看看到底退回去了什么：

```text
3u
```

结果不是"三行恢复原样"，而是一个**半成品**：第 1 行变成 `# task001 ->`（前缀留着、后缀被撤），第 2 行变成 `task002`（前缀和后缀都被撤，第 3 行重新算进去），第 3 行是 `task003`。

原因在于 `3u` 撤的是**三次修改**，而一次 `@a` 产生**两次修改**（`I# ` 一次、`A ->` 一次）。`3@a` 一共 6 次修改，撤销序列倒着数是：

| 撤销次数 | 撤掉的是 | 第 1 行 | 第 2 行 | 第 3 行 |
|---|---|---|---|---|
| 撤销前 | — | `# task001 ->` | `# task002 ->` | `# task003 ->` |
| `1u` | 第 3 行后缀 | `# task001 ->` | `# task002 ->` | `# task003` |
| `3u` | 第 3 行两次 + 第 2 行后缀 | `# task001 ->` | `task002` | `task003` |
| `6u` | 全部 | `task001` | `task002` | `task003` |

再按 `3u` 回到全撤：

```text
3u
```

**这才是本实验最值钱的一条结论：撤销的粒度是"一次修改"，不是"一次回放"。**回放一次宏 = 两条修改，所以 `3@a` 要 `6u` 才干净。记宏之前先想清楚每条命令算几次修改，否则"撤销"会让你以为 vim 出 bug 了。

以后想撤销整个宏，最省事的办法是在**动手前**先存个档，而不是靠 `u` 数数：

```text
:w! ~/tasks.txt.bak
```

**6. 正式执行**

```text
100@a
```

等它跑完，用 `:set number` 配合 `gg` 确认第 100 行也改了。

**7. 用 `@@` 体验重复回放**

```text
@@
```

它会重复上一条 `@a`，同样改一行。

**8. 检查中间结果**

```vim
:3
```

看到第 3 行是 `# task002 ->`。注意行数没变——宏是**逐行改写**，不是插行。

**9. 保存**

先只用 `:w`：

```vim
:w
```

再 `:q` 退出。

**10. 退出后用命令行验证**

```bash
$ wc -l < ~/vim-lab/tasks.txt
100
$ grep -c '^# task' ~/vim-lab/tasks.txt
100
$ grep -c ' ->$' ~/vim-lab/tasks.txt
100
$ awk 'NF==3' ~/vim-lab/tasks.txt | wc -l
100
$ head -3 ~/vim-lab/tasks.txt
# task001 ->
# task002 ->
# task003 ->
$ tail -1 ~/vim-lab/tasks.txt
# task100 ->
```

四个数字都是 100 才算改对了。其中 `awk 'NF==3'` 是在检查"每行都是三个字段"，这是宏观上的不变式校验——比逐行 `cat` 更可靠。

**11. 体验 `:x` 与 `:wq` 的差别**

```bash
$ vim ~/vim-lab/tasks.txt
```

```vim
:x
```

退出后再看时间戳：

```bash
$ ls -l --time-style=full-iso ~/vim-lab/tasks.txt
```

**再做一次对照**：

```bash
$ vim ~/vim-lab/tasks.txt
```

```vim
:wq
```

再 `ls -l`。你会看到第二次的 mtime 变了，而 `:x` 那次在文件没被修改的情况下**没有改变 mtime**。

**12.（可选）体验崩溃恢复**

在第一个终端里保持 `vim ~/vim-lab/tasks.txt` 打开，在**另一个终端**里：

```bash
$ ls -a ~/vim-lab/
```

```console
.  ..  tasks.txt  .tasks.txt.swp
```

交换文件出现了。现在模拟崩溃（只针对这个 vim 进程，不要乱 kill）：

```bash
$ pgrep -af 'vim .*tasks.txt'
$ kill -9 <上面那个 PID>
```

交换文件会残留。再次打开同一个文件时你会看到 `E325` 警告。先确认没有其他 vim 进程在编辑它，再恢复：

```bash
$ vim -r ~/vim-lab/tasks.txt
```

恢复完成后在 vim 里清掉交换文件：

```vim
:rm
```

### 验证

| 检查项 | 期望结果 |
|---|---|
| `wc -l < tasks.txt` | `100` |
| `grep -c '^# task' tasks.txt` | `100` |
| `grep -c ' ->$' tasks.txt` | `100` |
| `awk 'NF==3' tasks.txt \| wc -l` | `100` |
| `tail -1 tasks.txt` | `# task100 ->` |
| `3u` 之后 | 只撤掉 3 次修改：第 1 行剩 `# task001 ->`，第 2 行变 `task002`，第 3 行变 `task003` |
| `6u` 之后 | 第 1–3 行恢复为 `task001` / `task002` / `task003` |
| 重新 `vim` 后执行 `:wq` | 文件 mtime 改变 |
| 重新 `vim` 后执行 `:x`（文件未改） | 文件 mtime **不**改变 |

### 思考

1. `100@a` 执行到第 47 行时你发现宏录错了。按什么键能立刻停止？已经改掉的 47 行要按几次 `u` 才能全恢复（提示：一次 `@a` 是两次修改）？为什么不能靠"再按一次 `q`"解决？`Ctrl-C` 和 `Ctrl-O` 在这里分别起什么作用？
2. 如果 `tasks.txt` 最后一行**没有换行符**（用 `printf 'task001\ntask002'` 生成的文件），`A ->` 在这一行上还能正常工作吗？为什么 `o` 在这种情况下更可靠？
3. 换一台没配 `~/.vimrc` 的机器，宏还能用吗？宏保存在哪里？
4. `dw` + `.` ×10 和 `qa`/`qdw` + `10@a` 都能实现"删掉十个词"。什么情况下第一个更好，什么情况下第二个更好？
5. 如果你把宏录成 `qaI# <Esc>q`，回放时会发生什么？宏和 `:set paste` 之间有没有关系？
6. 为什么 `:x` 适合写进脚本，而 `:wq` 可能造成意料之外的构建行为？

### 清理

```bash
$ cd ~
$ rm -rf ~/vim-lab
```

如果你在第 12 步留下过备份目录，可以一并清掉：

```bash
$ rm -rf ~/.vim-backup
```

⚠️ 清理前先 `ls` 一眼确认要删的目录里**只有**你这次实验产生的东西。`rm -rf` 没有回收站。
