## 🎯 核心心法
- **端口即服务**：扫描端口就是找目标开着的“门”，每扇门后都可能藏着一个服务或漏洞。
- **Nmap 6 种端口状态**：
  - `open`：门开着（重点攻击目标）。
  - `closed`：门关着，但主机活着（能收到 RST）。
  - `filtered`：被防火墙挡住，Nmap 不知道开没开。
  - `unfiltered`：能访问，但无法确认开关（常见于 ACK 扫描）。
  - `open|filtered`：分不清是开着还是被挡了（UDP 扫描专属）。
  - `closed|filtered`：分不清是关闭还是被过滤（高级扫描专属）。

## 🚪 三大核心扫描技术 (TCP 与 UDP)

### 1. TCP Connect 扫描 (`-sT` 全开扫描)
*   **权限**：**普通用户也可用**（不需要 sudo）。
*   **原理**：调用系统底层的 `connect()` 函数，走完整的“三次握手”。连接建立后，再发 RST 断开。
*   **抓包特征**：`SYN -> SYN/ACK -> ACK -> RST`（有完整的 ACK）。
*   **缺点**：速度慢；因为建立了真实连接，会在目标的 Web 日志、系统日志中留下你的 IP 记录（极不隐蔽）。

### 2. TCP SYN 扫描 (`-sS` 半开扫描)
*   **权限**：**必须 root/sudo**（需要构造原始数据包）。
*   **原理**：Nmap 的**默认扫描方式**。发 SYN 包，如果目标回 SYN/ACK，Nmap 直接发 RST 掐断，**绝不完成第三次握手**。
*   **抓包特征**：`SYN -> SYN/ACK -> RST`（没有 ACK）。
*   **优点**：速度极快；因为没有完成连接，目标的应用层根本不知道你来过，**隐蔽性极高**。

### 3. UDP 扫描 (`-sU`)
*   **权限**：必须 root/sudo。
*   **原理**：UDP 没有三次握手。发空包过去：
  - 如果端口**关闭**，目标会回一个 **ICMP Type 3, Code 3 (端口不可达)**。
  - 如果端口**开放**，目标通常会装死（不理你）。
*   **状态表现**：开放的端口通常显示为 `open|filtered`，关闭的显示 `closed`。
*   **致命缺点**：**极其慢**！千万不要用 `-sU -p-` 扫全端口，会跑到天荒地老。实战中建议 `--top-ports 50` 或 `-p 53,161,123` 扫特定目标。

## ⚡ 性能微调与范围控制 (微操)

### 1. 端口范围与数量
| 参数 | 含义 | 实战场景 |
| :--- | :--- | :--- |
| `-p 80,443` | 扫指定端口列表 | 精准打击 |
| `-p 1-1023` | 扫指定端口范围 | 扫常见系统端口 |
| **`-p-`** | **全端口扫描 (1-65535)** | **红队实战必用**，防止漏掉高位端口 (如 8080/8888) |
| `-F` | 快速模式 (扫最常用的 **100** 个) | 赶时间时的快速摸底 |
| `--top-ports 10` | 扫最常见的 10 个端口 | UDP 扫描时的保命神技 |

### 2. 扫描速度与隐蔽 (Timing Templates)
*   `-T0` / `-T1`：**龟速/隐蔽模式**。真实红队项目专用，防止触发 WAF/IDS 报警。
*   `-T3`：默认的正常速度。
*   `-T4`：**激进模式**。打 CTF/靶机专用，速度飞快。
*   `-T5`：疯狂模式。极易丢包导致结果不准，不推荐。

### 3. 进阶发包控制
*   `--min-rate 1000`：每秒至少发 1000 个包（强行突破限速）。
*   `--min-parallelism 64`：至少保持 64 个探针同时并发（治疗 Nmap 假死/卡顿）。
*   `-r`：按端口顺序扫描（默认是随机乱序扫描）。
