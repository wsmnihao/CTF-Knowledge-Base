## 🎯 核心心法
- **为什么要做主机发现？** 直接扫端口会产生大量噪音，且极其浪费时间。先找出“活人”，再针对性地去“搜身”。
- **Nmap 默认逻辑**：如果不提供任何发现选项，Nmap 会先 Ping 一下，只有收到响应的主机才会被继续端口扫描。
- **核心痛点**：如果防火墙拦截了你的探测包，Nmap 会误判该主机“离线”，从而直接跳过不扫了。**换一种探测协议，往往能绝处逢生。**

## 🔍 目标指定语法 (Target Specification)
在扫描前，你需要告诉 Nmap 扫哪里。
*   **列表**：`scanme.nmap.org example.com` (扫这两个域名)
*   **范围**：`10.11.12.15-20` (扫 .15 到 .20 共 6 个 IP)
*   **组合范围**：`10.10.0-255.101-125` (第三段和第四段组合，扫 256 × 25 = **6400** 个 IP)
*   **网段**：`10.10.12.13/29` (根据掩码算网段，块大小为 8，可用范围 .9 到 .14)
*   **从文件读取**：`nmap -iL targets.txt`

> **💡 实战技巧**：`nmap -sL -n 10.10.12.0/24` 可以帮你列出要扫描的 IP 清单，但**不发送任何探测包**。加上 `-n` 是不做 DNS 解析，防止卡顿。

## 🕵️‍♂️ 四大主机发现技术 (按网络层级从下到上)

### 一、 数据链路层：ARP 扫描 (局域网无敌)
*   **原理**：在你的局域网（同一个子网）里大喊：“谁是 192.168.1.1？把你的 MAC 地址报上来！”
*   **优点**：**防火墙几乎拦不住**（ARP 工作在二层），速度极快，结果最准。如果目标在同一个网段，Nmap 会**优先且自动**使用 ARP。
*   **参数**：`-PR` （如果你只想扫局域网存活主机且不扫端口）
*   **命令**：`sudo nmap -PR -sn 192.168.1.0/24`
*   **判断标准**：收到 **ARP Response** 就是活的。

> **🚨 跨网段限制**：ARP 包无法穿过路由器。如果你扫外网或不同网段，只能用下面的 ICMP 或 TCP/UDP。

### 二、 网络层：ICMP 扫描 (探测路由器外的世界)
如果目标在另一个网段，Nmap 默认会用 ICMP。但由于防火墙经常拦截 Ping（Type 8），我们需要用“变种”ICMP包：

| 扫描方式 | Nmap参数 | 发送的包类型 (Type) | 期望的回应 (Type) | 实战含义 |
| :--- | :--- | :--- | :--- | :--- |
| **Echo 扫描** | `-PE` | Type 8 (Ping 请求) | Type 0 (Ping 应答) | 最基础的探测，容易被防火墙拦截。 |
| **时间戳扫描** | `-PP` | Type 13 (现在几点？) | Type 14 (时间应答) | **绕过禁 Ping 防火墙的利器**，顺便还能获取目标系统时间。 |
| **地址掩码扫描** | `-PM` | Type 17 (你的子网掩码是多少？) | Type 18 (掩码应答) | 现代系统基本不理睬，但有时能查出老旧网络设备。 |

> **命令格式**：`sudo nmap -PE -sn 10.200.6.0/24`

### 三、 传输层：TCP 扫描 (最隐蔽的探测)
如果 ICMP 全部被拦截，我们利用 TCP 三次握手的机制来探测。

| 扫描方式 | Nmap参数 | 发送的包 | 目标回应 | 适用场景与权限 |
| :--- | :--- | :--- | :--- | :--- |
| **TCP SYN 扫描** | `-PS` | SYN (请求建连) | SYN/ACK 或 RST | **极其隐蔽**。只要收到任何回应，就说明主机存活。<br>**普通用户**发 `-PS` 会触发完整的 3 次握手。 |
| **TCP ACK 扫描** | `-PA` | ACK (确认) | RST (重置) | 目标收到莫名其妙的 ACK 包，会回一个 RST。**必须使用 root/sudo 权限**。 |

> **命令格式**：`sudo nmap -PS -sn 10.200.6.0/24` （默认探测 80 端口，可自定义如 `-PS22` 探测 SSH 端口）

### 四、 传输层：UDP 扫描 (反向思维)
*   **原理**：UDP 没有三次握手。如果你向目标**开放的** UDP 端口发包，通常没回应；但如果你向目标**关闭的** UDP 端口发包，目标会回一个 **ICMP port-unreachable（端口不可达）** 错误包。
*   **Nmap 参数**：`-PU`（默认向高端口发垃圾包）。
*   **命令**：`sudo nmap -PU -sn 10.200.6.0/24`
*   **判断标准**：只要收到了 ICMP 端口不可达包，就说明主机是活的。

## 🧠 DNS 反查 (Reverse-DNS Lookup)
在实战中，IP 地址是冰冷的，域名往往能暴露这台机器的作用（比如 `mail.xxx.com`、`dc01.xxx.com`）。
*   默认情况下，Nmap 会尝试对**存活**的主机进行 DNS 反查。
*   `-R`：**强制**对所有扫描的 IP（包括没探测到存活的）进行 DNS 反查。
*   `-n`：**彻底关闭** DNS 反查（扫描速度最快）。
*   `--dns-servers`：指定 DNS 服务器。

## ⚡ 速查总结表 (实战必备)

| 目标网络环境             | 首选探测参数        | 完整推荐命令                              |
| :----------------- | :------------ | :---------------------------------- |
| **同局域网 (子网内)**     | `-PR`         | `sudo nmap -PR -sn <目标IP/24>`       |
| **跨网段，目标没防护**      | `-PE`         | `sudo nmap -PE -sn <目标IP/24>`       |
| **跨网段，目标禁 Ping**   | `-PP` 或 `-PS` | `sudo nmap -PP -sn <目标IP>`          |
| **内网极度严格，封死 ICMP** | `-PS` 或 `-PA` | `sudo nmap -PS22,80,443 -sn <目标IP>` |

> **再次牢记**：加上 `-sn` 才代表“只找活人，不扫端口”。不加的话，找到活人后 Nmap 会默认开始扫端口。
