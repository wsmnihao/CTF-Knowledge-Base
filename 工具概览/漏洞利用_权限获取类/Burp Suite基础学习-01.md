### 认识Burp Suite

Burp Suite 是一个基于 Java 的框架，专门用于**Web 应用渗透测试**。它是行业标准的手动安全测试工具，也适用于移动应用和 API 的评估。

**核心原理**：Burp Suite 能拦截浏览器和 Web 服务器之间的所有 HTTP/HTTPS 流量。拦截后，你可以：
- 查看请求和响应
- 修改请求再发给服务器
- 修改响应再发给浏览器

这个“拦截 + 修改”的能力，是 Burp Suite 整个框架的支柱。也正因为如此，它成为了手动 Web 应用测试中不可或缺的工具。

#### Burp Suite的三个版本

| 版本                    | 定位           | 核心功能                                              | 授权       |
| --------------------- | ------------ | ------------------------------------------------- | -------- |
| **Community（社区版）**    | 免费，适合学习和基础测试 | 手动拦截、修改、重放请求                                      | 免费，非商业用途 |
| **Professional（专业版）** | 专业渗透测试人员首选   | 自动漏洞扫描、无限制 Intruder、保存项目、API 集成、Burp Collaborator | 需要许可证    |
| **Enterprise（企业版）**   | 服务器端持续扫描     | 自动扫描器，定期扫描 Web 应用漏洞（类似 Nessus 做基础设施扫描）            | 需要许可证    |

### 社区版Burp Suite核心功能

|功能|干什么用的|大白话解释|
|---|---|---|
|**Proxy（代理）**|拦截并修改请求和响应|Burp 最有名的功能，能“卡住”浏览器和服务器之间的流量，让你随便改|
|**Repeater（中继器）**|多次捕获、修改、重发同一个请求|手动改参数反复试，比如测 SQL 注入、试不同的 payload|
|**Intruder（入侵者）**|自动向端点发大量请求|用来暴力破解或模糊测试，社区版有速度限制|
|**Decoder（解码器）**|编码和解码数据|发 payload 前先把编码解出来，或者把 payload 编好再发|
|**Comparer（比较器）**|比较两块数据（字或字节级别）|用快捷键就能把两段数据丢进去对比，看哪里不一样|
|**Sequencer（音序器）**|评估 token 的随机性|检查会话 Cookie 之类的值是不是真的随机，如果不够随机就可能被预测|
#### 扩展功能

Burp Suite 基于 Java，所以支持用 **Java、Python、Ruby** 写扩展来增强功能。

- **BApp Store（应用商店）**：Burp 的扩展市场，可以直接下载第三方模块。
- **Logger++**：一个常用的扩展，增强了 Burp 内置的日志功能。
- 部分扩展需要专业版才能用，但社区版也能用不少。

### Burp Suite的安装

|平台|安装方式|
|---|---|
|**AttackBox**|已预装，直接跳过|
|**Kali Linux**|已预装。如果缺了，用 `apt` 从 Kali 仓库装|
|**Windows / macOS / Linux**|从 PortSwigger 官网下载安装程序，选 Community 版|
#### kali安装命令

如果 Kali 里没有 Burp Suite，执行：
```bash
sudo apt install burpsuite
```

#### Linux 手动安装注意

如果你在 Linux 上手动装，且**没用 `sudo`**：

- Burp Suite 会装在**你的家目录**下：`~/BurpSuiteCommunity/BurpSuiteCommunity`
- 不会被加到 `PATH`，所以不能直接敲 `burpsuite` 启动，得进目录跑

### Burp Suite 代理（Proxy）介绍

#### Proxy 是干什么的

Proxy 是 Burp Suite 最基础、最核心的工具之一。它能**捕获浏览器和目标服务器之间的请求和响应**，让你可以查看、修改、丢弃或转发这些流量。

#### 核心功能

|功能|说明|
|---|---|
|**拦截请求**|开启拦截后，请求会被卡在 Burp 里，不会直接到服务器。你可以选择转发、丢弃、编辑，或发到其他模块|
|**掌控一切**|能完全控制 Web 流量，这是手动测试 Web 应用的关键能力|
|**捕捉与记录**|默认情况下，即使拦截关闭，所有经过代理的请求也会被记录，方便后续分析|
|**WebSocket 支持**|除了 HTTP，Burp 还能捕获和记录 WebSocket 通信|
|**日志与历史**|捕获的请求会出现在 **HTTP history** 和 **WebSocket history** 子标签里，可以随时回看或发到其他模块|
**操作：**
**开启/关闭拦截**：点击 **“Intercept is on”** 按钮切换。开启时请求被卡住，关闭时请求直接通过。

#### 代理设置（Proxy settings）

点击 **Proxy settings** 按钮，可以进入代理专属设置。几个值得注意的功能：

| 功能                           | 说明                                                                         |
| ---------------------------- | -------------------------------------------------------------------------- |
| **响应拦截**                     | 默认不拦截服务器响应，但可以勾选“Intercept responses based on the following rules”来自定义拦截规则 |
| **匹配与替换（Match and Replace）** | 用正则表达式动态修改请求和响应，比如改 User-Agent、改 Cookie                                    |

### FoxyProxy连接代理

#### 为什么

要让 Burp Suite 抓到浏览器的流量，需要把浏览器的代理指向 Burp 的监听地址。FoxyProxy 是一个 Firefox 扩展，可以让你一键切换代理配置。

#### 配置步骤

注意：不一定非要这个foxy代理，只要是能快速切换/挂起代理的插件就行

**1. 安装 FoxyProxy**

- 下载安装 **FoxyProxy Basic** 扩展
- AttackBox 里已经装好了，不用再装

**2. 打开 FoxyProxy 选项**

安装后，Firefox 右上角会出现 FoxyProxy 按钮，点击它，再点 **Options**。

**3. 新建代理配置**

点 **Add**，填写：

| 字段              | 值           |
| --------------- | ----------- |
| Title（标题）       | `Burp`      |
| Proxy IP（代理 IP） | `127.0.0.1` |
| Port（端口）        | `8080`      |

**4. 保存并激活**

- 点 **Save** 保存
- 点 Firefox 右上角的 FoxyProxy 图标，选择刚创建的 `Burp` 配置

**5. 在 Burp 中开启拦截**

切回 Burp Suite，确保 **Proxy** 标签页里的 **Intercept is on** 是开启状态。

**6. 测试**

打开 Firefox，访问 `http://目标IP/`。浏览器会卡住，Burp 的 Proxy 里会弹出这个 HTTP 请求，说明拦截成功。

#### 注意点

- **代理激活 + 拦截开启时，浏览器会卡住**，这是正常的，因为请求被 Burp 卡住了。
- **别忘了关拦截**：测试完记得把 Intercept 关掉，否则浏览器一直发不出请求。
- **右键菜单**：在 Burp 里右键点击请求，可以转发、丢弃、发到其他模块。
- **关掉其他标签页**：开启拦截前，先把 AttackBox 浏览器里其他标签页关掉，否则会收到一堆 WebSocket 请求，干扰你看目标请求。

### 范围界定与目标定位（scope）

#### 为什么需要 Scope

代理会捕获所有经过的流量，如果不限制范围，Burp 里会堆满无关的请求，根本没法看。**Scope（范围）** 就是用来告诉 Burp：“我只关心这个目标，其他流量别记。”

#### 如何设置 Scope

**方法一：快速添加**

1. 打开 **Target** 标签页
2. 在左侧列表里找到你的目标
3. 右键 → 选择 **Add To Scope**
4. Burp 会问你是否要停止记录范围外的内容，选 **Yes**

**方法二：手动配置**

打开 **Target → Scope settings**，可以手动包含或排除特定域名/IP，精确控制测试范围。

#### 让代理只拦截范围内的流量

光设置 Scope 还不够，代理默认还是会拦截所有请求。要去：

**Proxy → Proxy settings → Intercept Client Requests**

勾选 **And URL Is in target scope**

这样代理就会**完全忽略范围外的流量**，Burp 里的流量视图会干净很多。

#### 两步缺一不可

| 步骤                                       | 作用            |
| ---------------------------------------- | ------------- |
| **Add To Scope**                         | 告诉 Burp 哪些是目标 |
| **Proxy 设置里勾选 “URL Is in target scope”** | 让代理只拦截目标流量    |

只做第一步，代理还是会抓一堆无关请求；两步都做，视图才真正干净。

### HTTPS代理（TLS流量拦截）

#### 为什么需要配置 HTTPS

Burp 默认能拦截 HTTP 流量，但遇到 HTTPS 网站（比如 `https://google.com`）就会报证书错误，因为浏览器不信任 Burp 提供的证书。

#### 解决方法：导入 PortSwigger CA 证书

**1. 下载 CA 证书**

确保 Burp 代理已激活，浏览器访问
```text
http://burp/cert
```

**2. 打开 Firefox 证书设置**

地址栏输入：
```text
about:preferences
```

**4. 信任 CA 证书**

- 在弹出的窗口里勾选 **信任此 CA 识别网站**
- 点 **确定**

完成后，浏览器就信任 PortSwigger CA 了，再通过 Burp 代理访问 HTTPS 网站就不会报证书错误。

#### 为什么要这样做

Burp 拦截 HTTPS 流量时，会用自己的证书跟浏览器建立连接。浏览器默认不信任这个证书，所以要手动把 PortSwigger CA 加进信任列表，Burp 才能正常解密和查看 HTTPS 流量。
